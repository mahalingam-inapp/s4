1. Week map and exam focus

Week 4 moves from CNNs for spatial/image data to models for ordered or sequential data. The central chain is:

  1. A vanilla Recurrent Neural Network (RNN) retains a hidden state so that previous inputs can influence the current output.
  2. Repeated backpropagation through time creates vanishing/exploding-gradient problems, especially for long-term dependencies.
  3. LSTM and GRU add gates that regulate memory and make long-range learning more practical.
  4. Natural Language Processing (NLP) turns human language into representations that a model can process.
  5. Word embeddings encode words as dense semantic vectors.
  6. Transfer learning adapts large pretrained models instead of training everything from scratch.
  7. Attention dynamically assigns importance to relevant input elements; multi-head attention learns several relationship types in parallel.
  8. A practical PyTorch example combines an RNN with attention for binary sequence classification and visualizes attention weights.

Instructor emphasis: Read the papers/books listed with the course sessions. The lectures provide the basic framework; references deepen the concepts.

2. Sequential data and why RNNs are needed

2.1 Sequential data

Sequential data is data in which order matters and an element may depend on earlier elements.

Sequential example Why order matters
Sentence/text Reordering words may change or destroy meaning: “My name is Yadu” is not equivalent to an arbitrary permutation.
Time series A stock price, weather value, or demand observation is associated with a time order.
Speech/audio Sound evolves through an ordered waveform over time.
Sensor/IoT readings Each observation is linked to a timestamp and prior state.
Video A video is an ordered sequence of frames; shuffling frames changes the action.
Exam rankings Rank 1, rank 2, etc. cannot be arbitrarily rearranged.

Non-sequential data is data for which order is not essential to the intended task, such as an unordered collection of independent photographs or a tabular record whose columns are treated as simultaneous features.

Exam trap: An individual image contains important spatial relationships, but the lecture’s RNN-versus-CNN distinction is that RNNs explicitly model an ordered progression over time/position, whereas CNNs learn local spatial features.

2.2 CNN versus RNN

Feature CNN RNN
Primary strength Spatial/local feature extraction Ordered/sequential dependency modeling
Typical input Images/pixels Text, time series, speech, sensor streams, video-frame sequences
Core operation Convolution and shared filters Recurrent hidden-state update with shared weights across time
Memory of previous step Not an explicit recurrent memory loop Yes, via the hidden state
Examples emphasized Facial recognition, phone unlocking, image recognition Document/sentence processing, summarization, forecasting, speech recognition

Transfer-learning recap: A pretrained model can be reused and modified for a related problem rather than trained and validated from scratch. This applies beyond CNNs, including NLP.

3. Recurrent Neural Networks (RNNs)

3.1 Definition

A Recurrent Neural Network is a neural network designed for sequential or temporal data. It contains recurrent connections that carry a hidden state across time steps, allowing information from earlier inputs to affect later predictions.

RNNs have input, hidden, and output layers. The required hidden size/number of layers is a design choice determined by the problem; it is not a universal constant.

3.2 Memory loop and hidden state

At time step \(t\), the RNN uses both the current input \(x_t\) and previous hidden state \(h_{t-1}\):

\[ h_t = \phi(W_{xh}x_t + W_{hh}h_{t-1} + b_h) \]

\[ y_t = \psi(W_{hy}h_t + b_y) \]

where:

  • \(W_{xh}\): input-to-hidden weights;
  • \(W_{hh}\): recurrent/hidden-to-hidden weights;
  • \(W_{hy}\): hidden-to-output weights;
  • \(\phi\): usually \(\tanh\) or another hidden activation;
  • \(\psi\): task-dependent output activation.

The same weights are shared across time, which lets the model process variable positions consistently. The hidden state is a compressed memory, not a literal storage of the entire sequence.

Human-reading analogy from the live lecture: A reader remembers preceding words while reading the next one; otherwise the reader cannot understand the complete sentence. Similarly, the RNN’s memory loop preserves useful prior context until the sequence can be interpreted.

3.3 Common input–output arrangements

Arrangement Example
One-to-many Image caption generation
Many-to-one Sentiment classification of a sentence
Many-to-many, aligned Tagging every word in a sentence
Many-to-many, different lengths Machine translation/sequence-to-sequence generation

3.4 Applications stated in the source

  • Time-series forecasting: predict future values from historical trends.
  • Language modeling: predict/generate text using preceding context.
  • Speech recognition: process an audio sequence and recognize spoken words.
  • Signal processing.
  • Anomaly detection in sequential/time-series data (the transcript says “enamel detection,” evidently transcription noise).
  • NLP, summarization, and ordered-document processing.

4. Training RNNs: Backpropagation Through Time

4.1 BPTT

An RNN is unrolled through time. A forward pass computes hidden states and outputs for all time steps; the loss is then propagated backward through those repeated computations. This is Backpropagation Through Time (BPTT).

Because of the chain rule, gradients include products of many Jacobians/activation derivatives:

\[ \frac{\partial L}{\partial h_t} = \frac{\partial L}{\partial h_T} \prod_{k=t+1}^{T} \frac{\partial h_k}{\partial h_{k-1}} \]

Repeated multiplication causes the two major RNN training problems.

4.2 Vanishing gradient

If typical derivative magnitudes are below 1, their product shrinks exponentially. The live lecture illustrates this with \(0.5^{50}\), which is extremely close to zero.

Effects:

  • earlier time steps receive almost no parameter update;
  • training slows or stalls;
  • the model struggles to connect distant inputs and outputs;
  • long-term dependencies are not learned effectively.

Sigmoid and \(\tanh\) derivatives can be small, particularly in saturated regions, so repeated multiplication makes this problem acute in long sequences.

4.3 Exploding gradient

If relevant factors have magnitude above 1, repeated multiplication makes gradients grow rapidly.

Effects:

  • unstable weight updates;
  • highly erratic/diverging loss;
  • possible numerical overflow/NaNs;
  • unreliable training and increased computational difficulty.

4.4 Remedies mentioned

  • gated architectures: LSTM and GRU;
  • attention mechanisms;
  • gradient clipping (particularly useful for exploding gradients);
  • careful weight initialization;
  • suitable activations such as ReLU where appropriate;
  • layer normalization;
  • skip/residual connections.

Exam trap: ReLU does not by itself guarantee that a recurrent model learns long dependencies, and gradient clipping primarily bounds exploding gradients; it does not fundamentally solve vanishing gradients.

5. LSTM: Long Short-Term Memory

5.1 Definition and motivation

An LSTM is a gated RNN designed to retain useful information across long sequences and mitigate the vanishing-gradient/long-term-dependency problem. Unlike a vanilla RNN’s single hidden-state pathway, it explicitly maintains:

  • hidden state \(h_t\) (exposed/output representation);
  • cell state \(c_t\) (long-term memory pathway);
  • forget, input, and output gates.

5.2 Equations

\[ f_t=\sigma(W_f[x_t,h_{t-1}]+b_f) \]

\[ i_t=\sigma(W_i[x_t,h_{t-1}]+b_i) \]

\[ \tilde c_t=\tanh(W_c[x_t,h_{t-1}]+b_c) \]

\[ c_t=f_t\odot c_{t-1}+i_t\odot\tilde c_t \]

\[ o_t=\sigma(W_o[x_t,h_{t-1}]+b_o) \]

\[ h_t=o_t\odot\tanh(c_t) \]

5.3 Gate functions

Component Question answered Function
Forget gate \(f_t\) What old information is no longer relevant? Scales/discards parts of \(c_{t-1}\).
Input gate \(i_t\) What new information should be stored? Controls candidate-memory insertion.
Candidate \(\tilde c_t\) What new content could be remembered? Proposes new memory values.
Cell state \(c_t\) What long-term information should flow onward? Carries controlled memory through time.
Output gate \(o_t\) What memory should be exposed now? Controls the hidden state/output representation.

5.4 Strengths, limitations, and use

Strengths: better at very long dependencies, document summarization, large language sequences, and translation; selective forgetting prevents all old information from accumulating indiscriminately.

Costs: three gates plus candidate/cell computation mean more weight matrices, parameters, stored activations, memory, computation, and training time. The live lecture emphasizes that LSTM is heavier, slower, more resource-demanding, and harder to train than GRU, while often being more capable on long sequences.

6. GRU: Gated Recurrent Unit

6.1 Definition

A GRU is a simplified gated RNN that addresses standard-RNN limitations with two gates:

  • update gate;
  • reset gate.

It merges long-term cell memory and exposed hidden memory into a single hidden state; it has no separate cell state.

6.2 Equations

One common convention is:

\[ z_t=\sigma(W_zx_t+U_zh_{t-1}+b_z) \]

\[ r_t=\sigma(W_rx_t+U_rh_{t-1}+b_r) \]

\[ \tilde h_t=\tanh(W_hx_t+U_h(r_t\odot h_{t-1})+b_h) \]

\[ h_t=z_t\odot h_{t-1}+(1-z_t)\odot\tilde h_t \]

Some texts reverse the two coefficients in the final interpolation; always state the convention being used.

6.3 Component functions

Component Function
Update gate \(z_t\) Determines the balance between retaining prior hidden state and accepting candidate information.
Reset gate \(r_t\) Determines how much past state participates in constructing the candidate.
Candidate state \(\tilde h_t\) Potential new hidden content derived from current input and reset-filtered history.
Final hidden state \(h_t\) Gated mixture of prior state and candidate state; also serves as output memory.

6.4 Strengths and limitations

  • fewer gates and parameters than LSTM;
  • lower memory use and computational cost;
  • generally faster/easier to train;
  • often comparable performance for many tasks and useful for short-to-medium sequences, speech-to-text, and translation.

The live instructor frames GRU as less trustworthy than LSTM for very long documents because its compact/updating memory may overwrite useful history. This is a rule of thumb, not an absolute law: empirical performance depends on data, tuning, and task.

Correction to a noisy transcript statement: A GRU does not use “input and output gates.” Its defining gates are update and reset. A reset gate is applied at each time step to candidate formation; it is not merely a manual whole-document reset.

7. RNN versus GRU versus LSTM

Dimension Vanilla RNN GRU LSTM
Memory Hidden state Hidden state Hidden + separate cell state
Gates None Update, reset Forget, input, output
Parameters Lowest Medium Highest
Speed Fast per step, but difficult long-range training Usually fastest gated option Usually slower
Long dependencies Weak Good Often strongest
Vanishing-gradient resistance Low Improved Improved
Typical choice Simple/short sequence baseline Efficiency and moderate sequences Very long/complex dependencies

Absolute exam facts:

  • GRU has two gates and no separate cell state.
  • LSTM has three gates plus a cell state.
  • The GRU candidate state is not a gate.
  • Neither architecture “eliminates” all gradient problems; they mitigate them.

8. Natural Language Processing (NLP)

8.1 Definition and scope

NLP is the AI field that enables computers to understand, interpret, analyze, and generate human language. It combines:

  • linguistics: grammar, syntax, semantics, pragmatics;
  • machine learning trained on language corpora;
  • deep neural models such as RNN, LSTM, GRU, and Transformers.

Objectives:

  • language understanding: extract meaning from text/speech, e.g., sentiment in a review;
  • language generation: produce human-like language, e.g., a chatbot response;
  • enable human–machine interaction and reduce linguistic barriers.

NLP versus NLU: Natural Language Understanding is a subset within the broader NLP field. NLU includes semantic parsing, relation extraction, paraphrase understanding, sentiment analysis, and dialogue understanding; broader NLP also includes translation, categorization, and generation.

8.2 Six-stage pipeline emphasized in lectures/case study

\[ \text{Raw input}\to\text{Tokenization}\to\text{Stop-word processing} \to\text{Feature extraction/embeddings}\to\text{Model training}\to\text{Prediction} \]

Example:

  1. Input: “I love programming in Python.”
  2. Tokens: [I, love, programming, in, Python].
  3. After illustrative stop-word removal: [love, programming, Python].
  4. Convert tokens into numeric embeddings.
  5. Train a sentiment/topic classifier.
  6. Output: Positive.

8.3 Tokenization

Tokenization splits text into meaningful units such as words/subwords. It does not remove stop words, generate embeddings, classify text, or identify named entities.

8.4 Stop words and caveat

Stop words are common words often carrying limited standalone information: “the,” “in,” “on,” “is,” “at,” “of,” “and.” Removal can reduce noise, vocabulary, and computation in traditional systems.

However, it is task-dependent:

  • “I am not happy” changes meaning if “not” is deleted.
  • modal words such as “should,” “could,” or “would” may distinguish a suggestion from a negative statement.

Therefore contextual tasks may benefit from retaining stop words.

8.5 Normalization

  • Stemming: mechanically reduces words to a stem (possibly not a valid word).
  • Lemmatization: maps an inflected word to its dictionary lemma using linguistic knowledge.

Example: improve, improved, improving, improves → a common base. These reduce vocabulary but do not by themselves understand intent.

8.6 NLP applications

  • sentiment analysis and text classification;
  • spam detection;
  • machine translation;
  • question answering;
  • chatbots/dialogue agents;
  • speech recognition;
  • summarization;
  • named entity recognition;
  • recommendations and text similarity.

9. Text features and word embeddings

9.1 Why numeric features are necessary

Neural/ML models operate on numbers, not raw strings. Feature extraction converts language into numeric representations.

9.2 Bag of Words and TF–IDF

Bag of Words (BoW) represents a document using vocabulary counts and ignores word order/context.

TF–IDF increases the weight of terms that are frequent in a document but uncommon across the corpus:

\[ \operatorname{tfidf}(t,d)=\operatorname{tf}(t,d)\log\left(\frac{N}{\operatorname{df}(t)}\right) \]

They are fast and useful baselines, but sparse, high-dimensional, and weak at semantics/context.

9.3 Word embeddings

A word embedding is a dense, low-dimensional vector representation in which semantic/syntactic relationships are encoded geometrically. Typical classic dimensions are about 50–300.

Compared with one-hot encoding:

One-hot Embedding
Sparse and vocabulary-sized Dense and lower-dimensional
Equal distance between distinct words Similar words can be nearby
No learned semantics Encodes usage/semantic relationships

Examples:

  • dog and puppy should be closer than dog and table.
  • The classic analogy is approximately \(v(king)-v(man)+v(woman)\approx v(queen)\).
  • “king and queen are close” and “apple and banana are close” share a relation structure but contain different entity types; embeddings help preserve those distinctions.

9.4 Embedding methods

Method Central idea
Word2Vec CBOW Predict a target word from surrounding context.
Word2Vec Skip-gram Predict surrounding context from a target word.
GloVe Uses global word co-occurrence statistics.
FastText Incorporates subword/character n-gram information; helps with morphology and rare words.
ELMo Contextual embeddings from a language model.
BERT/GPT-family representations Transformer-based contextual representations; the same word may have different vectors in different contexts.

Example of context: “river bank” and “bank account” should give different contextual representations for “bank.”

9.5 Benefits and uses

  • dimensionality reduction and lower computation than one-hot vectors;
  • semantic and syntactic similarity;
  • reusable pretrained input features;
  • improved accuracy and reduced training time;
  • text similarity, sentiment, translation, QA, and recommendation.

10. Transfer learning and pretrained NLP models

10.1 Definition

Transfer learning reuses knowledge from a model pretrained on a large/general dataset for a different but related downstream task. Usually, the model is then fine-tuned on a smaller task-specific dataset.

10.2 Process

  1. Pretraining: train on a massive corpus such as Wikipedia/Common Crawl using a general objective.
  2. Adaptation/fine-tuning: continue training on a labeled domain/task dataset, often with a task-specific output head.

Common pretraining objectives stated:

  • causal/next-token language modeling (associated with GPT);
  • masked-language modeling (associated with BERT);
  • next-sentence prediction (used in original BERT pretraining).

10.3 Why transfer learning?

  • overcomes limited labeled task data;
  • reduces training time and compute;
  • reuses rich linguistic/contextual knowledge;
  • generalizes better;
  • often produces state-of-the-art downstream performance.

Training a large NLP model from scratch demands vast corpora, memory, and high-performance compute; this is why the instructor strongly recommends pretrained models.

10.4 Models named in the source

  • BERT (Bidirectional Encoder Representations from Transformers);
  • GPT;
  • T5;
  • RoBERTa;
  • DistilBERT;
  • XLNet;
  • Word2Vec and GloVe as pretrained embedding resources.

Downstream uses include sentiment analysis, classification, translation, summarization, and question answering.

11. Attention mechanisms

11.1 Core idea

Attention lets a model give different relevance weights to different input elements instead of treating every element equally. It mimics selective human focus and is especially useful for long sequences or complex inputs.

Benefits emphasized:

  • focuses computation on relevant information;
  • captures long-range dependencies;
  • improves accuracy and efficiency;
  • handles variable-length inputs;
  • produces attention weights that can provide some interpretive insight;
  • works across text, speech, images, video, and graphs.

Caveat: Attention weights can be inspected, but they are not automatically a complete or causal explanation of every prediction.

11.2 Query, key, value formulation

For query matrix \(Q\), key matrix \(K\), and value matrix \(V\):

\[ \operatorname{Attention}(Q,K,V) = \operatorname{softmax}\left(\frac{QK^\top}{\sqrt{d_k}}\right)V \]

Steps:

  1. identify/project queries, keys, and values;
  2. compute similarity/alignment scores (dot product, scaled dot product, or additive scoring);
  3. apply softmax to normalize scores into attention weights;
  4. compute the weighted sum of values.

Scaling by \(\sqrt{d_k}\) prevents large dot products from driving softmax into saturation.

11.3 Types

  • Additive attention: a small feed-forward network scores query–key compatibility.
  • Dot-product attention: uses query–key dot products.
  • Scaled dot-product attention: scales by \(\sqrt{d_k}\); central to Transformers.
  • Self-attention: queries, keys, and values come from the same sequence.
  • Multi-head attention: performs multiple attention operations in parallel subspaces:

\[ \operatorname{MHA}(Q,K,V)=\operatorname{Concat}(head_1,\dots,head_H)W^O \]

This captures diverse relationships simultaneously.

11.4 Sparse attention

Dense self-attention normally has \(O(n^2)\) pairwise score complexity. Sparse attention retains only selected connections.

Exam-safe pipeline:

  1. compute/select relevance structure;
  2. retain top-\(k\) or allowed tokens/connections;
  3. normalize over the retained set;
  4. compute the weighted combination.

Trap: Normalize over all tokens, prune, and fail to renormalize—the weights no longer sum to one over retained tokens and output scale depends on pruning.

11.5 Domain applications

Machine translation: while generating each target word, focus on relevant source words.

Text: emphasize sentiment-bearing/contextual words.

Computer vision: visual attention supports image recognition and object detection; Vision Transformers and CNN–attention hybrids improve spatial understanding.

Graph neural networks: assign different importance to nodes or edges.

Speech recognition: focus on critical audio regions, handle variable duration, and improve transcription in background noise or multi-speaker settings. Attention prioritizes relevant signals; it does not literally perform noise removal by itself.

Action recognition: temporal attention selects critical frames/motion patterns; spatial attention selects important regions. Challenges include high-dimensional video, motion variation, lighting, and background. Uses include surveillance, sports, and interactive systems.

Future directions: Vision Transformers, CNN–attention hybrids, multimodal alignment across images/text/audio, autonomous driving, diagnostics, and personalized AI.

13. Explainability for sequence models

Interpretability means obtaining insight into why a model produced a prediction.

Gradient-based explanation Attention-based architectural signal
Computed after/around a prediction using derivatives Generated within the forward pass
Post hoc saliency/sensitivity Explicit learned importance weights per time step
PyTorch autograd can produce it Requires an attention component
Does not make the base architecture inherently interpretable Offers built-in inspectable signals, though not guaranteed causal explanation

Changing the optimizer, initialization, or use of synthetic data does not make a model architecturally interpretable.

14.3 Synthetic sequence generation

The function takes sequence length and batch size, creates random input sequences with torch.rand, creates random binary target labels with torch.randint, and returns inputs and targets.

14.4 Model architecture

An ExplainableRNN(nn.Module) class contains:

  1. an RNN layer parameterized by input and hidden sizes;
  2. a linear attention-scoring layer from hidden size to 1;
  3. a fully connected output layer;
  4. a sigmoid for binary probability in the lecture implementation.

If the RNN returns

\[ H=[h_1,\ldots,h_T]\in\mathbb{R}^{B\times T\times H}, \]

the attention calculation is conceptually:

\[ e_t=w_a^\top\tanh(h_t)+b_a, \qquad \alpha_t=\frac{e^{e_t}}{\sum_j e^{e_j}}, \]

\[ c=\sum_{t=1}^{T}\alpha_t h_t, \qquad \hat y=\sigma(W_cc+b_c). \]

The model returns both prediction \(\hat y\) and attention weights \(\alpha\).

14.5 Training configuration stated

Hyperparameter Value
Sequence length 10
Batch size 32
Input size 1
Hidden size 16
Output size 1
Epochs 5
Learning rate 0.01
Loss Binary cross-entropy (BCELoss)
Optimizer Adam

Training loop:

  1. generate inputs and targets;
  2. forward pass to predictions and attention weights;
  3. compute BCE loss;
  4. clear old gradients (optimizer.zero_grad());
  5. backpropagate (loss.backward());
  6. update parameters (optimizer.step());
  7. print epoch and loss.

Observed losses were roughly 0.68–0.70. The lecture says rerunning should lower loss; exam-safe caveat: random batches and stochastic optimization mean loss is not guaranteed to decrease on every run/epoch. A value near \(\ln 2\approx0.693\) is chance-level BCE for balanced random binary labels, and if labels are independent of inputs the model cannot learn a real predictive pattern.

14.6 Binary classification: logit, sigmoid, BCE

A logit is an unrestricted score in \(( -\infty,+\infty )\). Sigmoid converts it to probability:

\[ \sigma(a)=\frac{1}{1+e^{-a}}. \]

Binary cross-entropy:

\[ L=-\left[y\log(p)+(1-y)\log(1-p)\right]. \]

  • BCELoss: input must already be a probability, so use logit → sigmoid → BCELoss.
  • BCEWithLogitsLoss: combines sigmoid and BCE more stably, so do not apply sigmoid before it.

14.7 Visualization

A visualization function takes inputs, attention weights, targets, and predictions and uses a loop to plot attention weights over sequence positions. Titles include sequence/sample, true label, and prediction; axes and legend make the important time steps visible. One example showed true label 1 and prediction about 0.53.

Exam trap: A probability of 0.53 is only slightly above the usual 0.5 threshold; it does not establish “good accuracy.” Accuracy must be calculated across an evaluation set.

15. EduLingua case study

15.1 Scenario

EduLingua wants an automated student-feedback analyzer. Stakeholders:

Person Role Priority

Rahul Lead engineer Robustness and maintainability
Maria Data analyst Accuracy, semantic features, richer insights

Required categories: Positive, Negative, Suggestion. Optional extensions include NER for courses/instructors and later machine translation.

15.2 Sentiment/text classification

Text classification assigns predefined labels. Sentiment analysis specifically identifies opinion/emotional polarity.

  • “The instructor explained concepts clearly.” → Positive
  • “The assignments were confusing.” → Negative
  • “Please include more practical exercises.” → Suggestion

Sentiment analysis is not translation, summarization, embedding generation, or entity extraction.

15.3 Named Entity Recognition

NER locates and classifies entities such as people, organizations, locations, dates, course names, and instructor names.

Example: “Professor Smith taught Python Programming.”

  • Professor Smith → Person/Instructor
  • Python Programming → Course

NER enables aspect-based feedback, linking opinion to a specific target:

“Professor John explains concepts well, but assignments are too difficult.”

  • Instructor/Professor John → Positive
  • Assignments → Negative

This is richer than one overall sentiment label but increases development time, computation, testing, and maintenance.

15.4 Options and trade-off

Option Advantage Cost/risk
Baseline sentiment-only MVP Fast, cheaper, easy to test, meets immediate need Less analytical depth
Add NER now Course/instructor-level and aspect-based insights More complexity and time
Add machine translation later Multilingual scalability Extra engineering/testing; not needed for immediate launch

15.5 TF–IDF versus contextual embeddings

TF–IDF Contextual embeddings
Fast and simple MVP baseline More semantic/context-aware
Ignores order and context Same word changes representation by context
Low initial cost More model/compute complexity
May require later replacement for advanced NER/aspect tasks Reusable foundation for sentiment, NER, aspects, translation

15.6 Technical debt and recommendation

If the first system tightly couples TF–IDF to the classifier, later moving to NER/Transformers may require replacing features, retraining, redeployment, and retesting. That accumulated future cost is technical debt.

Best strategic compromise presented by the source: ship a focused sentiment/suggestion MVP quickly, but use a modular, future-proof architecture—preferably reusable contextual embeddings/pretrained representations—so NER, aspect analysis, and multilingual support can be added without redesigning the entire pipeline.

16. Instructor Q&A and emphasis preserved

Q1. On what kinds of problems is a CNN used?

Primarily image/picture problems where features are extracted from pixels. Facial recognition, phone unlocking, and image recognition are applications.

Q2. What is the key difference between CNN and RNN?

The RNN has a recurrent memory/hidden-state loop for ordered context; a CNN primarily extracts spatial features.

Q3. Why does an RNN need memory?

To retain earlier words/time steps so the sequence can be understood as a whole. Without recurrence, each item would be processed independently.

Q4. What is sequential data?

Data where order matters and each step may depend on the previous step: sentences, time series, audio, sensors, and video frames.

Q5. What causes vanishing gradient?

Repeated chain-rule multiplication of small derivatives during BPTT makes the gradient approach zero; early steps stop receiving useful updates.

Q6. What causes exploding gradient?

Repeated multiplication of large factors makes gradients grow excessively, causing unstable or failed training.

Q7. Why LSTM and GRU?

They are gated upgrades to vanilla RNNs that regulate information flow and mitigate memory/gradient difficulties. LSTM favors long/complex sequences; GRU favors a lighter/faster architecture.

Q8. Why is NLP used with RNN/LSTM/GRU?

It processes language so the system can represent and understand words, grammar, sentence structure, and meaning. Converting words into numerical vectors is one step in that broader process—not the whole purpose of NLP.

Q9. Why use transfer learning in NLP?

Training a large language model from scratch requires enormous data, compute, memory, and time. Pretrained models such as BERT/GPT or embeddings such as GloVe can be adapted to the target task.

17. Exam traps and precision corrections

  1. GRU gates: update and reset—not input/output/forget.
  2. LSTM gates: forget, input, output, plus a distinct cell state.
  3. Hidden state: compressed temporal representation, not verbatim storage of every prior token.
  4. BPTT: recurrence is unfolded through time; ordinary feed-forward backpropagation language alone is incomplete.
  5. Vanishing vs exploding: tiny products cause vanishing; large products cause exploding.
  6. BCELoss vs BCEWithLogitsLoss: the first needs probabilities; the second takes logits.
  7. Attention: prioritizes relevant portions; it does not automatically remove noise and is not always a faithful causal explanation.
  8. Sparse attention: prune/select before normalizing over retained entries, or renormalize after pruning.
  9. Tokenization: only segmentation; it is not stop-word removal, embedding, NER, or classification.
  10. NER vs sentiment: NER identifies entities; sentiment classifies opinion. They complement one another.
  11. Stop-word removal: not always desirable—negations and modals can carry crucial meaning.
  12. Static vs contextual embedding: Word2Vec/GloVe usually give one vector per word type; BERT-like models vary by context.
  13. Transfer learning: reuse and adapt pretrained knowledge; it is not merely copying a final model without task adaptation.
  14. Loss near 0.693: for balanced random binary targets this is chance behavior, not evidence of successful learning.
  15. Framework: despite a closing slip mentioning TensorFlow/Keras, the implementation described uses PyTorch.
  16. Performance claims: GRU is often faster and LSTM often stronger for long dependencies, but neither is universally superior.

Review Week augmentation: clinical sequence-classification synthesis

High-yield recurrent-model distinctions

  • Vanilla RNN update concept: \(x_t+h_{t-1}\rightarrow h_t\); BPTT unrolls recurrence and propagates gradients through time. In a long clinical report, early history or negation can alter a much later finding; a vanilla RNN may receive too little learning signal at early positions because of vanishing gradients.
  • GRU update gate balances retained hidden-state information against new information; reset gate controls how much old information enters candidate construction. A GRU has no separate LSTM-style cell state and is often simpler/more efficient. A GRU retention question points to the update gate, not a forget gate.
  • LSTM uses a dedicated cell state for long-term information. Forget gate removes old cell content, input gate stores new content, and output gate exposes cell information through the hidden state. Hidden state and cell state are not interchangeable.
  • Memory shortcut: RNN—hidden state; GRU—update/reset; LSTM—forget/input/output plus cell state.

Preprocessing and representation corrections

  • Tokenization may operate at word, subword, character, or sentence level and must not be confused with embedding.
  • Stop-word removal must be domain-aware: removing “no” from “no evidence of malignancy” reverses the clinical meaning.
  • With a 10,000-word vocabulary, a one-hot vector contains one 1 and 9,999 zeros: it is sparse, high-dimensional, and does not encode similarity such as malignant ≈ cancerous. Dense embeddings are compact and can encode semantic proximity.
  • Word2Vec: CBOW predicts a target from context; skip-gram predicts context from a target. GloVe uses global word–word co-occurrence. FastText uses character/subword n-grams and helps with morphology, rare words, and OOV-like cases. ELMo produces contextual vectors using a deep bidirectional language model. Word2Vec/GloVe are normally static; ELMo and Transformer encoders are contextual. The word “bank” illustrates context dependence.

Attention corrections and implementation pipeline

  • Q is what is sought, K describes matching/relevance, and V is the information aggregated: \[ \operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right)V. \] \(QK^T\) gives compatibility, scaling prevents extreme dot products, softmax yields non-negative weights summing to one, and those weights aggregate values. Q is not a prediction, and attention softmax is not the final binary classifier.
  • Multi-head attention runs learned heads in parallel, concatenates their outputs, and applies a linear transform. Different heads can capture syntactic, semantic, positional, and long-distance relations; its purpose is not sequence-length reduction or removal of positional information.
  • An LSTM with self-attention remains an attention-augmented recurrent model, not a pure Transformer. The LSTM supplies recurrent memory; attention supplies dynamic relevance. Transformers are attention-centered and do not require traditional recurrence.
  • Clinical triage pipeline: report → domain-aware tokenization/preprocessing → contextual embeddings → LSTM hidden states → Q/K/V attention → scaled scores → softmax → weighted representation → classifier → probability → chosen threshold → high/low-risk class.
  • PyTorch training: tensor input (commonly batch × sequence length × embedding dimension, subject to configuration) → forward pass/logit or probability → BCE loss → backward/autograd → Adam update. BCELoss expects probabilities; BCEWithLogitsLoss accepts raw logits and combines sigmoid with BCE more stably. The operational threshold need not be 0.5.
  • Attention-highlighted phrases are model-generated relevance indicators, not proof of causal reasoning; use them alongside validation and other explanation methods.
