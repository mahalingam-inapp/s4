1. Week overview and learning objectives

Week 6 moves from basic deep learning to goal-oriented decision making. The central idea is that an autonomous agent learns which actions to take in an environment so that its long-run reward is maximized. Depending on problem complexity, decision making can use simple conditionals, decision trees or mathematical optimization; nonlinear, sequential and uncertain problems motivate heuristics, genetic algorithms and especially RL.

By the end of the week, one should be able to:

  • define RL and explain its interaction loop;
  • identify agent, environment, state, action, reward, policy, Q-value and episode;
  • explain how a policy network maps states to actions;
  • compare deterministic and stochastic policies;
  • explain exploration–exploitation and policy-gradient learning;
  • state why TD/Q-learning can be unstable and how target networks help;
  • describe DQN architecture, replay memory, target synchronization and training;
  • compare DQN, REINFORCE and actor–critic approaches;
  • interpret a practical DQN implementation and diagnose inconsistent rewards.

2. Goal-oriented decision making and reinforcement learning

2.1 Meaning

Goal-oriented decision making selects actions whose outcomes align with a specified objective. In RL, the objective is expressed through rewards, and an agent improves its behavior through repeated interaction rather than receiving a labelled “correct action” for every state.

Reinforcement learning is a machine-learning paradigm in which an agent learns by trial and error, receiving rewards or penalties from an environment and developing a strategy that maximizes expected cumulative reward.

The goal is not merely the largest immediate reward. The agent seeks the largest expected return:

$$ G_t = \sum_{k=0}^{\infty}\gamma^k r_{t+k+1}, \qquad 0 \le \gamma < 1 $$

where $\gamma$ discounts distant rewards. A short-term sacrifice can be rational if it creates a larger future return.

2.2 RL interaction loop

At time $t$:

  1. The agent observes state $s_t$.
  2. It chooses action $a_t$ according to policy $\pi$.
  3. The environment changes to $s_{t+1}$.
  4. The environment supplies reward $r_{t+1}$.
  5. The agent updates its policy/value estimates and repeats.
Agent --action a_t--> Environment
Agent <--state s_(t+1), reward r_(t+1)-- Environment

An episode is the complete trajectory from an initial state to a terminal/final state. The agent learns over many episodes until behavior converges toward an optimal strategy.

2.3 Core terms

Term Exam-ready definition Examples
Agent Learner/decision maker capable of selecting actions. It may contain a neural network and a policy. Robot, game AI, autonomous vehicle, AI vacuum cleaner
Environment The external setting in which the agent operates; it changes state and returns feedback after actions. Warehouse, classroom floor, game world, market
State, $s$ Representation of the current situation of the environment. Grid position, chessboard, sensor vector, image/frame
Action, $a$ Choice available to the agent. Up/down/left/right, clean, accelerate, brake, pick object
Reward, $r$ Scalar feedback indicating the desirability of an action/outcome. Goal $+1$; collision/hole $-1$; step cost

Instructor Q&A — who gives the reward? The user does not manually reward every action. The environment returns feedback according to the reward logic designed for the task. For a vacuum-cleaner agent, cleaning actual dirt can receive positive feedback; attempting to clean where there is no dirt can receive negative feedback. The “environment” is the work area (for example, the classroom or office floor) and its task dynamics/reward mechanism.

The defining RL feature is learning from experience in a sequential environment.

3. Policy networks

3.1 Definition and role

A policy network is a neural network parameterized by $\theta$ that directly represents a policy:

$$ \pi_\theta(a\mid s)=P(A_t=a\mid S_t=s) $$

It accepts the current state and produces either an action or a distribution over actions. Direct state-to-action mapping enables fast, context-aware, data-driven decisions. By learning good action sequences, an agent can navigate complex environments, adapt to new situations and improve toward a predefined goal.

State -> Policy network -> action scores/probabilities -> selected action

The instructor’s study-policy analogy: to “crack an exam,” a student chooses a study policy (for example, six, eight or twelve study hours). In RL, the policy similarly guides action selection toward a goal.

3.2 Deterministic versus stochastic policy

Feature Deterministic policy Stochastic policy
Mapping $a=\mu(s)$ $a\sim\pi(a\mid s)$
Output One fixed action Probability distribution over actions
Same state revisited Same action Possibly different sampled action
Strength Predictable and efficient Natural exploration; handles uncertainty
Limitation Can become rigid or miss alternatives Variable behavior; probability estimation required
Example Vacuum: if dirt, always clean Navigation: left .2, right .4, up .3, down .1

In the vacuum example, “dirt → clean; no dirt → do not clean” is deterministic. A stochastic robot selects among actions according to probabilities.

If $P(\text{up})=.5$, $P(\text{right})=.3$, and $P(\text{down})=.2$, ten visits might yield five up, three right and two down actions. It does not always choose “up” merely because up has the largest probability.

Important distinction: deterministic environment dynamics mean that the same state–action pair produces the same next state. This does not force the policy to be deterministic. A stochastic policy can create different trajectories in a deterministic environment.

The lecture also names finer architectural/use categories: discrete-action, continuous-action, actor–critic, hierarchical, multi-agent and recurrent policy networks. These are not alternatives to the basic deterministic/stochastic distinction; most ultimately implement one of those two policy forms. Deterministic continuous-control methods include Deep Deterministic Policy Gradient (DDPG), with examples such as robotic-arm control and autonomous driving. Stochastic policy optimization includes Monte Carlo policy gradient/REINFORCE, Proximal Policy Optimization (PPO) and Trust Region Policy Optimization (TRPO), and can support discrete or continuous actions.

Model-selection caveat (repeated instructor emphasis): no algorithm is universally “best.” Performance depends on the problem, dataset/experience, training procedure and hyperparameters. A decision tree, SVM, unsupervised method or RL method can be preferable on different tasks. The algorithm/reward timing can also be adapted to the problem—for example, delivering feedback after a sequence of 50 actions rather than after every action—rather than using an existing method unchanged.

3.3 Exploration versus exploitation

  • Exploration: try unfamiliar actions to obtain information and discover potentially better routes.
  • Exploitation: choose the action currently believed to yield the greatest reward.

Too much exploration wastes effort and prevents reliable use of known good actions. Too much exploitation makes the agent repeatedly use its current best action, potentially locking into a suboptimal solution and limiting continuous improvement. Effective learning requires a balance.

An $\varepsilon$-greedy policy chooses:

$$ a_t=\begin{cases} \text{random action}, & \text{with probability }\varepsilon,\\ \arg\max_a Q(s_t,a), & \text{with probability }1-\varepsilon. \end{cases} $$

Usually $\varepsilon$ starts high and decays, moving from exploration toward exploitation.

Exam trap: $\varepsilon=0$ removes only the additional $\varepsilon$-greedy randomness. A softmax/stochastic policy can still sample different actions.

3.4 Policy-gradient methods

Policy gradients optimize the policy parameters directly rather than first learning Q-values and then deriving a policy. Their objective is:

$$ J(\theta)=\mathbb{E}_{\tau\sim\pi_\theta}[G(\tau)] $$

The policy-gradient idea is:

$$ \nabla_\theta J(\theta)\approx \mathbb{E}\left[\nabla_\theta\log\pi_\theta(a_t\mid s_t)G_t\right] $$

Thus, actions associated with high return become more probable; actions associated with poor return become less probable.

REINFORCE

REINFORCE is a Monte Carlo policy-gradient algorithm:

  1. Run a complete episode using $\pi_\theta$.
  2. Calculate the return $G_t$ for each time step.
  3. Update the policy in the direction $\nabla_\theta\log\pi_\theta(a_t\mid s_t)G_t$.

With a baseline $b(s_t)$, usually $V(s_t)$:

$$ A_t=G_t-b(s_t) $$

$$ \nabla_\theta J(\theta)\approx \mathbb{E}\left[\nabla_\theta\log\pi_\theta(a_t\mid s_t)A_t\right] $$

  • $A_t>0$: sampled action performed better than expected; increase its probability.
  • $A_t<0$: it performed worse than expected; decrease its probability.

If an action makes a Frozen Lake agent fall into a hole, the return is below the baseline, giving negative advantage. Its probability decreases; because softmax probabilities sum to one, alternatives become relatively more likely.

The baseline reduces gradient variance. It does not remove learning, cancel all bad-episode updates or change the optimal policy.

3.5 Uses and trends of policy networks

Applications emphasized in the sessions:

  • robotics: navigation, manipulation and adaptive control;
  • gaming: strategy and complex sequential play;
  • autonomous vehicles: adaptive navigation in dynamic environments;
  • finance: trading and portfolio decisions under uncertainty;
  • healthcare: treatment/decision optimization;
  • recommendation and other real-time decision systems.

Emerging directions include multi-agent learning, hierarchical policies, transfer/generalization, safer and more explainable policies, and use in increasingly complex real-world environments.

4. Value-based RL, Q-learning and temporal-difference learning

4.1 Q-values and Bellman target

$Q(s,a)$ estimates long-term return, not only immediate reward. The optimal Bellman relationship is:

$$ Q^*(s,a)=\mathbb{E}\left[r+\gamma\max_{a'}Q^*(s',a')\mid s,a\right] $$

Tabular Q-learning updates:

$$ Q(s,a)\leftarrow Q(s,a)+\alpha\left[r+\gamma\max_{a'}Q(s',a')-Q(s,a)\right] $$

The bracketed quantity is the TD error:

$$ \delta=r+\gamma\max_{a'}Q(s',a')-Q(s,a) $$

4.2 Temporal-difference learning

TD learning combines ideas from:

  • Monte Carlo methods: learning from experience/returns;
  • dynamic programming: bootstrapping, i.e., updating an estimate using another estimate.

It learns from incomplete episodes by comparing successive predictions with observed reward plus an estimated future value. This is more incremental than waiting for the entire episode.

4.3 Sources of instability

Problem Explanation
Bootstrapping error Targets use imperfect estimates; errors can propagate and amplify.
Moving/non-stationary target Updating a network changes both prediction and the target it is trying to match.
Oscillation/divergence Poor learning rate or rapidly changing targets can make updates fluctuate or explode.
Overestimation bias The max operator can favor noisy overestimates, especially in stochastic environments.
Correlated observations Consecutive episode transitions violate the ideal of independent, identically distributed samples.
Function-approximation effects One neural-network update affects many states; exploding/vanishing gradients and generalization errors can destabilize unrelated regions.

The combination of function approximation, bootstrapping and off-policy learning is especially challenging. DQN addresses two major issues using experience replay and a target network.

5. Target networks

5.1 Definition and primary purpose

A target network is an auxiliary, delayed copy of the primary/online value network. It provides a temporarily fixed reference for computing TD targets. Its primary purpose is to stabilize training by decoupling target computation from online-network updates.

Without separation, the same continually changing network supplies both predicted Q-values and targets; the learner chases a moving target. A slower target network reduces rapid fluctuations, oscillation, feedback instability and divergence, producing smoother convergence and more accurate Q estimates—even in complex, high-dimensional environments.

5.2 Online and target network

Online/local Q-network, $Q(s,a;\theta)$ Target Q-network, $Q(s,a;\theta^-)$
Updated by gradient descent each training step Frozen between synchronizations
Produces current predicted Q-values Produces stable next-state target values
Learns continuously Copies or slowly tracks online parameters

For a transition $(s,a,r,s',d)$, where $d=1$ if terminal:

$$ y=r+\gamma(1-d)\max_{a'}Q(s',a';\theta^-) $$

The online-network loss is commonly mean squared TD error:

$$ L(\theta)=\mathbb{E}\left[(y-Q(s,a;\theta))^2\right] $$

Only $\theta$ receives the gradient update; $y$ is treated as fixed for that step.

5.3 Hard and soft updates

Hard update: after every $K$ learning updates, copy:

$$ \theta^-\leftarrow\theta $$

Soft/Polyak update: at every step or regularly:

$$ \theta^-\leftarrow\tau\theta+(1-\tau)\theta^-, \qquad \tau\ll1 $$

Hard updating gives piecewise-constant targets; soft updating changes them smoothly. Both preserve slower target movement than the online learner.

5.4 Correct DQN update order

  1. Sample a minibatch from replay memory.
  2. Compute targets with the frozen target network.
  3. Compute online predictions and TD loss.
  4. Backpropagate and update only the online network.
  5. At the prescribed interval, hard-copy online weights, or apply a soft update.

Instructor emphasis: the target network is a “stabilizing anchor” and the stable learning signal is the key. Its immediate effect is slower-changing target values.

5.5 What a target network does not do

It does not create exploration, replace gradient descent, remove the replay buffer, or learn as an independent model. It is updated from the online network. Its job differs from experience replay.

6. Experience replay

6.1 Replay memory

Instead of training only on the newest consecutive transition, DQN stores:

$$ e_t=(s_t,a_t,r_{t+1},s_{t+1},d_t) $$

in a replay buffer and later draws random minibatches.

Benefits:

  • breaks temporal correlation between neighboring frames/transitions;
  • reuses old experiences, improving data/sample efficiency;
  • mixes experiences from different parts of the state space;
  • produces more stable gradient updates.

A common Python structure is collections.deque(maxlen=N): it has fixed capacity and automatically discards the oldest item when full. Appending and random minibatch sampling are separate operations.

6.2 Experience replay versus target network

Experience replay Target network
Stabilizes the data distribution Stabilizes the TD target
Randomizes minibatches and breaks temporal correlation Reduces the moving-target feedback loop
Reuses transitions Holds delayed/frozen parameters
Improves sample efficiency Improves convergence and reduces oscillation

Both mechanisms are complementary: replay alone does not guarantee stable targets, and a target network alone does not remove correlated training data.

7. Deep Q-Network (DQN)

7.1 Motivation

Tabular Q-learning requires one value per state–action pair and is practical only when states can be enumerated. Images, raw game frames, camera data, large maps and high-dimensional sensor vectors make the table prohibitively large. DQN replaces the Q-table with a deep neural network:

$$ s\longrightarrow \text{neural network}\longrightarrow [Q(s,a_1),\ldots,Q(s,a_m)] $$

The selected exploitative action is $\arg\max_a Q(s,a)$. Deep feature learning reduces the burden of manually enumerating high-dimensional states and lets classic Q-learning operate on learned representations.

7.2 Architecture

  • Input: state representation. For vector states, a feature vector; for visual tasks, commonly a stack of raw frames (the session example mentions $84\times84\times4$).
  • Feature layers: CNN layers for image inputs learn edges, shapes and objects. Fully connected layers can be used directly for vector inputs. ReLU is a typical activation. RNNs may be used where temporal sequence/state history matters.
  • Output: one Q-value for every discrete action.
  • Loss: difference (often MSE) between predicted and target Q-values.
  • Optimizer: gradient-based optimizer such as Adam.
  • Stabilizers: replay memory and target network.
  • Behavior policy: often decaying $\varepsilon$-greedy.

7.3 End-to-end DQN training pipeline

  1. Initialize online and target networks; copy online weights to target.
  2. Initialize fixed-capacity replay buffer.
  3. Observe the environment state.
  4. Choose an action using $\varepsilon$-greedy behavior.
  5. Execute the action; observe reward, next state and terminal flag.
  6. Store the transition in replay memory.
  7. Once sufficient samples exist, draw a random minibatch.
  8. Compute target $y$ using the target network.
  9. Gather the online Q-value for each sampled action.
  10. Compute TD/MSE loss, clear gradients, backpropagate and use the optimizer.
  11. Hard- or soft-update the target network.
  12. Decay $\varepsilon$, continue until episode termination, and repeat episodes.

7.4 Advantages, limitations and applications

Advantages

  • handles large/high-dimensional input spaces;
  • learns representations from raw sensory/image data;
  • scales Q-learning to complex environments;
  • replay and target networks make learning substantially more stable;
  • successful in dynamic decision tasks such as Atari games.

Limitations

  • computationally expensive;
  • sensitive to learning rate, discount, replay size, batch size, target-update rate and exploration schedule;
  • may converge slowly;
  • standard DQN assumes a manageable set of discrete actions;
  • can struggle with sparse rewards and tasks requiring long-term planning;
  • may overestimate action values.

Applications: Atari/game-playing AI, robot navigation and object manipulation, autonomous vehicles, and continuously optimized finance/trading strategies.

Backpropagation is used during learning, even though only the forward method is explicitly defined in a PyTorch module.

8.3 Replay-buffer class

The buffer:

  • stores past experiences in a deque;
  • appends state, action, reward, next state and done;
  • randomly samples a batch;
  • separates the tuple fields into state/action/reward/next-state/done tensors;
  • exposes its current length so learning starts only after enough examples exist.

8.4 DQN-agent class

The agent initializes state/action sizes and hyperparameters including learning rate, $\gamma$, $\varepsilon$, epsilon decay and minimum epsilon. It creates:

  • local/online Q-network;
  • target Q-network;
  • Adam optimizer;
  • replay memory of size 1,000 with batch size 64 in the demonstration.

Key methods:

  • act(state): choose a greedy online-network action or random action based on epsilon;
  • step(...): store the transition and, when memory exceeds the batch size, sample and call learning;
  • learn(experiences): compute target and expected Q-values, calculate loss, optimize online parameters and soft-update the target;
  • update_epsilon(): decay epsilon while respecting its minimum.

9. Actor–critic methods and architecture choice

9.1 Actor–critic

Actor–critic combines policy-based and value-based learning:

  • Actor: learns $\pi_\theta(a\mid s)$ and selects actions.
  • Critic: estimates $V_w(s)$ or $Q_w(s,a)$ and evaluates the actor.

A typical TD advantage is:

$$ \delta_t=r_{t+1}+\gamma V_w(s_{t+1})-V_w(s_t) $$

The critic learns from $\delta_t$; the actor changes action probability in proportion to the same feedback. Compared with plain REINFORCE, the critic supplies lower-variance, stepwise learning signals rather than waiting only for a full episodic return.

9.2 Comparison

Criterion DQN REINFORCE Actor–critic
Family Value-based Policy-based Hybrid
Learns $Q(s,a)$ Policy directly Policy plus value estimate
Action choice Derived, often $\varepsilon$-greedy Sample from policy Actor samples/chooses
Typical strength Stable/interpretable value estimates with replay + target Simple direct policy optimization Better balance of policy flexibility and lower-variance feedback
Typical weakness Discrete actions; hyperparameter/computation burden High variance; often slower/noisier learning More complex; two learners can introduce tuning issues
Prefer when Stability and clear Q-value interpretation matter Direct/fast policy optimization is the priority Overall balance and noisy/inconsistent rewards matter

“Fast convergence” is context-dependent; the case notes associate direct policy optimization with speed, DQN with stability/clear reward interpretation, and actor–critic with the strongest overall compromise.

10. DataForge Robotics case study

10.1 Scenario and formulation

DataForge Robotics develops autonomous warehouse navigation. Maya prototypes a Python grid world similar to OpenAI Gym’s Frozen Lake: each cell represents an aisle, safe region or obstacle/hole. The robot must move from start to goal without entering hazards.

  • State: robot location and relevant surroundings.
  • Actions: up, down, left, right (or warehouse movement commands).
  • Rewards: positive for reaching the goal; negative for holes, collisions or inefficient actions; possibly small step cost.
  • Policy: navigation strategy.
  • Episode: start-to-goal/hole/terminal run.

Maya builds a PyTorch policy network. Raj investigates DQN/Q-values. Logs show inconsistent rewards between exploratory new paths and exploitation of known routes, and some reward summaries conflict with transition logs.

10.2 Correct diagnosis

Reward variability can be a natural consequence of exploration: random or low-probability actions can temporarily lower returns while producing useful data. A learning-rate change addresses the size of parameter updates, not the diversity of experiences. Therefore, do not reduce learning rate merely because exploration makes rewards vary.

Before changing architecture or hyperparameters:

  1. validate that reward summaries and transition logs use the same episode boundaries and preprocessing;
  2. inspect sampled actions, policy probabilities and $\varepsilon$ values;
  3. inspect predicted Q-values/TD errors;
  4. separate exploratory from exploitative episodes;
  5. run comparable seeds/evaluation episodes with exploration disabled;
  6. then tune learning rate or exploration schedule based on evidence.

10.3 Recommendation logic

  • Choose DQN if stability, discrete actions and interpretable Q-values are primary.
  • Choose REINFORCE if direct policy optimization and conceptual simplicity matter and high variance is acceptable.
  • Choose actor–critic when both policy flexibility and value-based feedback are needed, especially under noisy/inconsistent rewards.

For this case, the source recommends actor–critic as the strongest overall compromise, while recognizing all three as viable depending on stakeholder priorities.

12. Common misconceptions and exam traps

  1. “RL maximizes immediate reward.” False; it maximizes expected cumulative return.
  2. “The end user manually gives each reward.” False; the environment/reward function supplies it after interaction.
  3. “A policy and Q-function are the same.” False; a policy selects actions, while a Q-function evaluates state–action pairs.
  4. “Stochastic means choose the most probable action.” False; it means sample from the entire distribution.
  5. “Deterministic dynamics imply deterministic behavior.” False; a stochastic policy can vary actions.
  6. “$\varepsilon=0$ makes every policy deterministic.” False; only epsilon randomness disappears.
  7. “DQN is just a larger Q-table.” False; it approximates Q-values with a neural network.
  8. “CNN replaces replay or target networks.” False; CNN extracts image features; the other two stabilize training.
  9. “Replay and target networks solve the same problem.” False; replay breaks data correlation, target networks slow target movement.
  10. “Replay buffer randomly decides what to retain.” Usually false; a fixed-capacity deque drops oldest items, while minibatches are sampled randomly.
  11. “The target network trains independently.” False; it copies/tracks online parameters.
  12. “Target networks increase exploration.” False; exploration comes from $\varepsilon$-greedy or a stochastic policy.
  13. “A target network removes all instability.” False; function approximation, reward noise and tuning can still cause problems.
  14. “REINFORCE baseline removes negative learning.” False; negative advantage intentionally reduces a bad sampled action’s probability.
  15. “More episodes guarantee perfection.” False; more data helps only with sound environment design, reward signal, algorithm and hyperparameters.
  16. “Inconsistent rewards automatically mean lower learning rate.” False; first distinguish exploration variability, logging errors and unstable parameter updates.
  17. “DQN works naturally for any continuous action.” Standard DQN produces one value per discrete action; continuous control usually motivates actor-based methods.

13. Likely exam questions with answer points

Q1. Define RL and explain its loop.

Define agent–environment trial-and-error learning; state the cumulative-reward objective; explain state → policy/action → environment → next state/reward → update; define episode.

Q2. Explain policy networks and compare deterministic and stochastic policies.

Define direct state-to-action mapping; show $a=\mu(s)$ versus $a\sim\pi(a\mid s)$; compare predictability, exploration and uncertainty; use vacuum/navigation examples.

Q3. Explain exploration versus exploitation.

Define both, state risks of excess, present $\varepsilon$-greedy equation and epsilon decay; distinguish stochastic-policy sampling from epsilon randomness.

Q4. What is TD learning and why can it be unstable?

Explain Monte Carlo plus bootstrapping, incomplete-episode updates and TD error; discuss moving targets, error propagation, overestimation, correlated data and neural approximation.

Q5. Why is a target network used in DQN?

Describe online/target separation; write $y=r+\gamma(1-d)\max Q(s',a';\theta^-)$; explain fixed reference, reduced oscillation/divergence, hard and soft synchronization.

Q6. Differentiate target network and experience replay.

Use the two-column comparison: target stability versus data decorrelation/sample reuse; emphasize complementarity.

Q7. Explain DQN architecture and training.

Motivate high-dimensional approximation; input/features/output Q-vector; epsilon action; transition storage; random minibatch; target computation; MSE/Adam update; target synchronization; epsilon decay.

Q8. Explain REINFORCE with baseline.

Direct policy optimization; full-episode return; log-policy gradient; $A=G-V(s)$; positive/negative advantage; baseline reduces variance without changing optimum.

Q9. Compare DQN, REINFORCE and actor–critic.

Contrast what each learns, action selection, stability/variance, complexity and suitable conditions. For noisy warehouse rewards, justify actor–critic as an overall compromise.

Q10. Diagnose inconsistent reward signals in DataForge Robotics.

Explain exploration-induced variability; validate logs; compare policy probabilities, Q-values and epsilon; evaluate without exploration; distinguish learning-rate tuning from exploration tuning; then choose architecture based on goals.

  • Policy network: neural policy mapping state to action probabilities/actions.
  • Q-value: expected long-term return of a state–action pair.
  • TD learning: bootstrap from reward plus a successor estimate before an episode ends.
  • DQN: neural approximation of Q-values for high-dimensional states.
  • Replay buffer: memory of transitions sampled in random minibatches.
  • Target network: delayed/frozen Q-network used to construct stable TD targets.
  • REINFORCE: Monte Carlo algorithm that directly optimizes a stochastic policy.
  • Actor–critic: actor chooses; critic evaluates and supplies lower-variance feedback.

Must-remember formulas

$$G_t=\sum_{k=0}^{\infty}\gamma^k r_{t+k+1}$$

$$Q(s,a)\leftarrow Q(s,a)+\alpha[r+\gamma\max_{a'}Q(s',a')-Q(s,a)]$$

$$y=r+\gamma(1-d)\max_{a'}Q(s',a';\theta^-)$$

$$L(\theta)=\mathbb{E}[(y-Q(s,a;\theta))^2]$$

$$\theta^-\leftarrow\theta \quad\text{(hard)},\qquad \theta^-\leftarrow\tau\theta+(1-\tau)\theta^- \quad\text{(soft)}$$

$$A_t=G_t-V(s_t)$$

$$\nabla_\theta J\approx\mathbb{E}[\nabla_\theta\log\pi_\theta(a_t\mid s_t)A_t]$$

Last-minute comparisons

If asked about… Recall…
Policy vs Q-value Choose versus evaluate
Deterministic vs stochastic Fixed action versus sampled distribution
Exploration vs exploitation Learn alternatives versus use known best
Replay vs target network Decorrelate samples versus stabilize targets
Online vs target network Gradient-updated versus delayed/frozen
Q-learning vs DQN Table versus neural function approximator
REINFORCE vs actor–critic Episodic high-variance return versus value-guided lower-variance update
Learning rate vs epsilon Update magnitude versus experience diversity

20-second DQN story

Observe state → choose an epsilon-greedy action → receive reward/next state → store transition → sample a random minibatch → compute frozen-target Bellman values → minimize online-network TD loss → periodically/softly update target → decay epsilon → repeat.

Instructor-emphasized takeaways

  • RL is goal-oriented and feedback driven.
  • The agent is the decision maker; the environment supplies the resulting state and reward.
  • A policy maps states to actions; a Q-value measures expected cumulative reward.
  • Balance exploration and exploitation—neither extreme is desirable.
  • Target networks provide the stable learning signal; replay memory provides diverse past experience.
  • DQN is the explicit bridge between deep neural networks and classical Q-learning.
  • Applications repeatedly emphasized: gaming, robotics/navigation, autonomous systems and finance/trading.
