Scope and learning outcomes

Week 3 progresses from single-/multilayer neural networks, perceptrons, activation functions, forward/backpropagation, model training and fine-tuning to Convolutional Neural Networks (CNNs). The week covers CNN structure and evolution, transfer learning, face recognition, neural style transfer, object detection/localization, and a TensorFlow/Keras implementation.

After studying these notes, you should be able to:

  • define a CNN and explain why it is preferred to a plain multilayer perceptron (MLP) for images;
  • describe convolution, activation, pooling, flattening, dense layers and the resulting feature hierarchy;
  • compare LeNet, AlexNet, VGGNet, GoogLeNet/Inception, ResNet, DenseNet, MobileNet, EfficientNet and Vision Transformers;
  • explain transfer learning, feature extraction and fine-tuning;
  • distinguish face detection, face recognition and embedding comparison;
  • derive content/style losses in neural style transfer;
  • distinguish classification, localization and detection and apply IoU and NMS;
  • evaluate two-stage versus single-shot detectors and edge versus cloud deployment; and
  • interpret and reproduce the demonstrated TensorFlow/Keras CNN.

Instructor emphasis: Questions may ask either “explain CNN with its architecture” or “explain the CNN diagram in detail.” Match the depth and diagram to the wording. Theory must also be practised in code.

1. Why CNNs?

1.1 Definition

A Convolutional Neural Network (CNN) is a class of deep-learning model designed to process grid-like data, especially images. An image is naturally represented as a rectangular grid of pixels; a colour image also has channels (for example, an RGB image of size \(224\times224\times3\)). CNNs learn spatial hierarchies of visual features and are central to image recognition, classification, object detection and segmentation.

CNNs use small learned filters rather than connecting every pixel independently to every neuron. This gives three major advantages:

  1. Local connectivity: a filter examines a small neighbourhood at a time.
  2. Weight sharing: the same filter weights are applied at every spatial location.
  3. Hierarchical feature learning: early layers detect simple features; deeper layers combine them into meaningful parts and objects.

These properties reduce the number of parameters and computation compared with a fully connected image model, improve training efficiency, and preserve spatial relationships.

1.2 CNN versus a plain MLP

Aspect Plain MLP CNN
Input treatment Image is usually flattened; spatial layout is largely lost Retains grid/spatial structure
Connections Typically dense; every input connects to many neurons Local receptive fields
Weights Separate weights across locations Shared filter weights across the image
Parameters Very large for realistic images Far fewer for equivalent feature extraction
Robustness to position Poorer; object movement changes many inputs Better translation tolerance through convolution/pooling
Best suited to General vector/tabular representations Images and other grid-like data

Illustration from the live class: if a cat and dog occupy different parts of an image, a plain MLP may identify patterns but does not naturally encode their spatial arrangement. CNN filters preserve local spatial relationships. This is also why face-ID systems can tolerate some shift or tilt of the face.

Clarifying caveat: CNN weights are still learned and updated during training by backpropagation. “The same weights everywhere” means that one filter’s learned weights are shared across spatial positions, not that CNN weights never update.

2. End-to-end CNN architecture

Input image
   ↓
Convolution → feature maps
   ↓
Non-linear activation (usually ReLU)
   ↓
Pooling / subsampling
   ↓
[Repeat convolution–activation–pooling as required]
   ↓
Flatten
   ↓
Fully connected (dense) layer(s)
   ↓
Output: class probabilities or regression value(s)

The number and arrangement of convolutional, pooling and dense layers depend on the problem. There is no rule that each type occurs only once.

2.1 Input layer

  • Receives raw image pixels.
  • Shape is normally \(H\times W\times C\), where \(C=3\) for RGB.
  • Example: \(224\times224\times3\).

2.2 Convolutional layer

The convolutional layer is the core feature extractor. A small matrix called a filter or kernel (commonly \(3\times3\), sometimes \(5\times5\)) slides across the input. At each position, element-wise multiplication and summation produce one output value.

For input \(X\), kernel \(K\), and bias \(b\), a 2-D cross-correlation-style operation used in CNN libraries is:

\[ Z_{i,j}=\sum_m\sum_n X_{i+m,j+n}K_{m,n}+b \]

The result produced by one filter is a feature map. Multiple filters produce multiple stacked feature maps. During training, each filter specializes in a pattern such as an edge, colour transition, texture or curve.

For input size \(N\), kernel size \(F\), padding \(P\), and stride \(S\), the spatial output size is:

\[ N_{out}=\left\lfloor\frac{N+2P-F}{S}\right\rfloor+1 \]

Practical example: a vertical-edge filter produces large activations where light/dark pixel values change vertically. A different filter may respond to curves or texture.

2.3 Feature maps and feature hierarchy

A feature map indicates where and how strongly a learned pattern occurs. It is localized evidence, not a complete class prediction for each patch.

  • Early layers: edges, lines, colour changes and simple textures.
  • Middle layers: corners, curves, repeated motifs and object parts (eyes, wheels).
  • Deep layers: faces, expressions, vehicles or other semantically meaningful patterns.
  • Dense/output layers: combine evidence from many maps to decide the final class.

Exam trap: A feature-map activation does not normally mean “this patch is class X.” Classification comes after features are aggregated.

2.4 Activation layer

An activation function introduces non-linearity so that the network can learn complex patterns.

The most commonly emphasized function is ReLU:

\[ \operatorname{ReLU}(x)=\max(0,x) \]

It maps negative values to zero and retains positive values. Sigmoid and \(\tanh\) exist, but ReLU is widely used in CNN hidden layers.

2.5 Pooling layer

Pooling reduces spatial dimensions, computation and sensitivity to small spatial variations while retaining dominant information.

Max pooling

For each local window, retain the maximum value. With a \(2\times2\) window and stride 2, a \(4\times4\) map becomes \(2\times2\).

Live-session example:

\[ X=\begin{bmatrix} 1&3&2&4\\ 0&6&1&2\\ 3&1&5&7\\ 2&4&0&1 \end{bmatrix} \]

The four \(2\times2\) blocks have maxima \(6,4,4,7\), so:

\[ \operatorname{MaxPool}(X)= \begin{bmatrix}6&4\\4&7\end{bmatrix} \]

Average pooling

Replace each local block by its mean. For the first block above:

\[ \frac{1+3+0+6}{4}=2.5 \]

Pooling type Operation Tendency
Max pooling Maximum in each window Preserves strongest/dominant response
Average pooling Mean of each window Produces smoother summary

2.6 Flatten layer

Flatten converts multidimensional feature maps into a one-dimensional vector. It bridges spatial feature extraction and dense classification. It has no learned parameters.

2.7 Fully connected (dense) layer

Every neuron receives the flattened representation. Dense layers learn weights and biases to aggregate all extracted evidence and perform:

  • classification (often a Softmax output), or
  • regression (one or more continuous values).

For \(C\) classes, Softmax converts logits \(z_i\) to probabilities:

\[ p_i=\frac{e^{z_i}}{\sum_{j=1}^{C}e^{z_j}} \]

3. Evolution of major architectures

The evolution moves from relatively simple designs to deeper, more accurate and computationally efficient networks.

Architecture Approx. year Main contribution / emphasis
LeNet 1998 (live class also mentioned an early 1988 origin) Early convolution + pooling system for handwritten-digit recognition; associated with MNIST
AlexNet 2012 ImageNet breakthrough; popularized deep CNNs, ReLU, GPU training and dropout; sharply reduced image-recognition error
ZFNet 2013 Refinement/visualization of AlexNet-style design
VGGNet 2014 Simple, uniform stack of small \(3\times3\) convolutions; greater depth improves feature extraction, but parameter-heavy
GoogLeNet / Inception 2014 Inception modules process multiple spatial scales efficiently; strong performance with fewer parameters than VGG
ResNet 2015 Residual/shortcut connections improve gradient flow and enable very deep networks
DenseNet 2016/2017 Each layer receives features from all preceding layers; feature reuse, stronger gradient flow and fewer parameters
MobileNet 2017 Designed for mobile/embedded devices; depthwise-separable convolution reduces compute
EfficientNet 2019 Compound scaling jointly balances depth, width and input resolution for accuracy/efficiency
Vision Transformer (ViT) Later development Splits an image into patches treated as tokens and uses self-attention for global context; supports CNN–Transformer hybrids

3.1 LeNet and MNIST

MNIST is a standard dataset of many handwritten digit images (roughly tens of thousands; the lecture referred to around 60,000). Its varied handwriting styles make it useful for training digit-recognition systems. LeNet combined convolution and pooling for this problem and helped establish the CNN idea.

3.2 AlexNet

  • Won the 2012 ImageNet competition and pioneered modern deep learning in computer vision.
  • Used ReLU instead of slower saturating activations, dropout for regularization and GPU computation.
  • The live class emphasized its dramatic error-rate reduction and benchmark status.

3.3 VGGNet versus GoogLeNet

  • VGGNet: conceptually simple and deep; repeated \(3\times3\) filters; excellent feature extraction but computationally/parameter intensive.
  • GoogLeNet: inception modules observe multiple receptive-field scales; more computationally efficient and uses fewer parameters.

3.4 ResNet

A residual block learns a residual function \(F(x)\), then adds the original input:

\[ y=F(x)+x \]

The identity shortcut lets gradients travel more directly through the network, helping alleviate degradation and vanishing-gradient problems in very deep models.

Exam trap: A residual/shortcut connection adds an earlier representation to a later one. It is not the same as an ordinary dense layer, where every neuron is connected through independently learned weights.

3.5 DenseNet

DenseNet concatenates feature maps from all previous layers:

\[ x_l=H_l([x_0,x_1,\ldots,x_{l-1}]) \]

This encourages feature reuse, improves gradient flow and can achieve high accuracy with fewer parameters. The lecture connected its strong feature extraction to demanding face-ID and medical-image uses.

3.6 MobileNet, EfficientNet and ViT

  • MobileNet: uses depthwise-separable convolution so CNNs can run on devices with limited compute.
  • EfficientNet: compound scaling balances network depth, width and resolution instead of scaling one dimension alone.
  • ViT: converts fixed-size image patches into tokens, analogous to word tokens in NLP, and uses self-attention rather than conventional convolution for feature extraction. It captures global context; CNNs remain relevant in hybrid approaches.

4. Transfer learning

4.1 Definition and rationale

Transfer learning is a machine-learning technique in which a model pretrained on one task (usually a large source dataset) is reused and adapted for a different but related target task. It is a technique within machine learning, not a replacement for machine learning.

Instead of learning everything from scratch, it transfers useful learned representations. CNN early layers commonly learn general features—edges, shapes and textures—while later layers are more task-specific. Therefore, a model trained on a large dataset such as ImageNet can be an effective starting point for a smaller target dataset.

Benefits:

  • much less labelled target data;
  • shorter training time;
  • lower computational cost;
  • faster development/deployment;
  • often better accuracy than scratch training on a small dataset.

4.2 Traditional learning versus transfer learning

Traditional training from scratch Transfer learning
Randomly initialized parameters Starts from pretrained parameters
Needs a large task-specific dataset Effective with limited labelled data
High time and compute Faster and cheaper
Learns basic and task-specific features anew Reuses basic features and learns/adapts task-specific features

4.3 Standard workflow

  1. Select a suitable pretrained model whose source task/data are reasonably related.
  2. Remove/replace the original classification head with a new output head for the target classes.
  3. Freeze the convolutional base initially so its useful weights are not changed.
  4. Train the new classifier on the target dataset, usually with a small learning rate.
  5. Optionally fine-tune: unfreeze some upper layers and retrain gently.
  6. Validate on held-out target data and deploy.
ImageNet-pretrained CNN
        ↓
Replace final classifier
        ↓
Freeze most layers
        ↓
Train new head
        ↓
Optionally unfreeze upper layers
        ↓
Fine-tune with small learning rate

4.4 Feature extraction versus fine-tuning

Feature extraction Fine-tuning
Pretrained backbone frozen Some pretrained layers unfrozen
Only new head is trained Head and selected upper layers adapt
Fast; lower overfitting risk Potentially better task fit
Good for very small datasets Useful when more target data are available

Caveat: Fine-tuning too many layers with too little data or too large a learning rate can destroy useful pretrained knowledge (catastrophic forgetting) or overfit.

4.5 Medical-image example

To build a tumour classifier from a small set of medical images:

  • begin with a CNN pretrained on a large image dataset;
  • reuse its edge/shape/texture detectors;
  • replace the final head with tumour categories;
  • train the head and perhaps fine-tune upper layers.

The live lecture extended the idea: if an MRI-detection system already exists and only a modification is needed, adapting/integrating pretrained models is much faster than rebuilding preprocessing, feature extraction and training from scratch.

4.6 Common pretrained families and domains

Computer vision commonly uses AlexNet, VGG, Inception, ResNet, DenseNet, MobileNet or EfficientNet-style pretrained models. Transfer learning is also effective in NLP, where pretrained language representations are adapted to downstream tasks.

The recorded lecture additionally mentioned:

  • source datasets: ImageNet and COCO;
  • frameworks: TensorFlow and PyTorch;
  • adaptation aids: data augmentation and learning-rate adjustment;
  • healthcare: fine-tune a pretrained model to classify an X-ray as normal or pneumonia-affected and analyze MRI images;
  • NLP: adapt BERT/GPT-style models for sentiment analysis and translation;
  • speech/audio: convert speaker audio to a spectrogram, segment/stack it, reuse an image-style CNN such as AlexNet, and classify emotion (anger, joy, sadness, neutral or boredom); and
  • speech recognition and object detection as further target domains.

4.7 Transfer-learning categories and challenges

The lecture’s decision diagram distinguishes transfer settings by asking whether source and target have the same data distribution/domain and the same task:

  • ordinary learning: source/target setting and task are essentially the same;
  • inductive transfer learning: target task differs, so labelled target information guides the new task;
  • transductive transfer learning / domain adaptation: task is the same but source and target domains/distributions differ;
  • unsupervised transfer learning: the target differs and labelled target data are unavailable, so transfer supports an unsupervised target problem.

The source and target must be sufficiently related for transferred features to help. Key challenges are domain mismatch, inappropriate pretrained-model selection, output-head mismatch and negative transfer. Select a source model whose learned representation fits the target modality; for example, an image source is a more natural starting point for another visual problem, while audio may first be transformed into a spectrogram before using an image CNN.

Exam trap: Transfer learning does not mean blindly copying a complete model. The final task-specific head is normally replaced, and freezing/fine-tuning choices must match dataset size and task similarity.

5. CNN applications

5.1 Broad uses

  • Image classification and recognition
  • Object detection and localization
  • Image segmentation
  • Face identification/security
  • Medical imaging (e.g., locating suspicious regions in MRI scans)
  • Autonomous driving/pedestrian recognition
  • Industrial inspection and robotic vision
  • Neural style transfer

5.2 Face detection versus face recognition

These are separate stages:

Stage Question answered Typical output
Face detection “Where are the faces?” Bounding boxes/cropped face regions
Face recognition “Whose face is this?” Identity or similarity score

Correct pipeline:

Group/input photo
   ↓
Face detector
   ↓
Crop/align each face
   ↓
CNN embedding network
   ↓
Face embedding vector
   ↓
Euclidean/cosine comparison with enrolled vectors
   ↓
Identity match

A face embedding is a compact numerical vector that represents identity-relevant facial features. Images of the same person should produce nearby vectors; different identities should be farther apart.

Methods/models named in the lecture include Haar cascades, MTCNN and SSD for detection; Local Binary Pattern Histograms (LBPH) as a traditional local-pattern recognizer; FaceNet, DeepFace and OpenFace-style deep embedding models; and OpenCV for lightweight deployment. FaceNet embeddings support one-shot matching, while DeepFace was highlighted for robust verification/identification from large-scale training.

Cosine similarity is:

\[ \cos(\theta)=\frac{u\cdot v}{\lVert u\rVert\lVert v\rVert} \]

Euclidean distance is:

\[ d(u,v)=\sqrt{\sum_i(u_i-v_i)^2} \]

Exam traps:

  • Similarity metrics compare embeddings; they do not locate faces.
  • Computing an embedding from the entire uncropped scene introduces background and other-person information. Detect/crop first.
  • Triplet loss shapes the embedding space; it does not replace a face detector.

5.3 Triplet loss

Triplet training uses:

  • anchor \(A\): a reference face;
  • positive \(P\): the same identity;
  • negative \(N\): a different identity.

The objective makes \(A\) closer to \(P\) than to \(N\) by margin \(\alpha\):

\[ L=\max\left(\lVert f(A)-f(P)\rVert^2-\lVert f(A)-f(N)\rVert^2+\alpha,0\right) \]

5.4 Neural Style Transfer (NST)

NST synthesizes a generated image \(G\) that preserves the structure/content of a content image \(C\) while adopting the artistic texture/style of a style image \(S\).

Procedure:

  1. Load a pretrained CNN and keep its weights fixed.
  2. Pass content, style and generated images through it.
  3. Use deeper feature activations to compare content.
  4. Use feature correlations (Gram matrices) across selected layers to compare style.
  5. Optimize the pixels of \(G\), not the network weights.

Content loss at layer \(l\):

\[ L_{content}=\frac{1}{2}\sum_{i,j}\left(F^{l}_{ij}(G)-F^{l}_{ij}(C)\right)^2 \]

For feature matrix \(F^l\), the Gram matrix is:

\[ G^l_{ij}=\sum_k F^l_{ik}F^l_{jk} \]

Style loss compares the generated and style-image Gram matrices across selected layers:

\[ L_{style}=\sum_l w_l\left\|G^l(G)-G^l(S)\right\|_F^2 \]

Total loss:

\[ L_{total}=\alpha L_{content}+\beta L_{style} \]

\(\alpha\) and \(\beta\) control the content–style balance.

The lecture used VGG19 as an example feature extractor and linked NST to filters/stylized photos (such as Snapchat/Prisma), art and design, photo enhancement, and marketing/branding graphics. It also warned that image manipulation and deepfakes can be misused; creative techniques should be applied responsibly.

Exam trap: In classical NST, the pretrained CNN is a fixed feature extractor. Gradient descent updates the generated image pixels.

5.5 Named application examples, challenges and future trends

  • YOLO (You Only Look Once): simultaneously predicts boxes and class probabilities for real-time detection.
  • SSD (Single Shot MultiBox Detector): detects at multiple scales using feature maps of different resolutions.
  • R-CNN: generates region proposals, then applies a CNN to classify/refine them.
  • Fast R-CNN: shares convolutional computation across proposals.
  • Faster R-CNN: adds an RPN for end-to-end proposal generation.
  • Tesla Autopilot example: real-time recognition of pedestrians and obstacles for navigation/safety.
  • Facebook example: face recognition and automatic tagging to improve interaction.
  • Prisma example: transforms user photographs into stylized artwork.

Challenges include real-time latency in safety-critical autonomous systems and privacy/ethical risks in face recognition, unauthorized surveillance and deepfakes. Developers and policy makers must balance innovation with individual privacy and responsible use. Anticipated trends include 3-D imaging, improved algorithms, edge computing, better accuracy/speed, and expanded creative tools for personalized content.

6. Object detection and localization case study

6.1 OptiVision Labs scenario

OptiVision Labs is designing a robotic scanner for packages and pallets on a moving conveyor belt.

  • Anna Ramirez: Lead Engineer
  • Mark Chen: Algorithm Specialist
  • Lisa Ortiz: Product Manager

The system must detect and localize every object, classify it as small box, large box or pallet, exceed 30 FPS, and balance accuracy, latency, memory, compute, complexity and future extensibility.

6.2 Classification, localization and detection

Task Question Output
Classification What is in the image? One or more class labels
Localization Where is the object? Bounding-box coordinates
Object detection What objects are present, and where? Class + confidence + box for each object

A box may be represented as \((x,y,w,h)\) or \((x_{min},y_{min},x_{max},y_{max})\).

6.3 Bounding-box regression

Bounding-box regression refines an approximate box by predicting coordinate offsets—move left/right/up/down, widen, shrink, and so on.

It does not:

  • classify the object;
  • generate proposals; or
  • remove duplicates.

Memory aid: proposal says “look here”; regression says “adjust the box”; classification says “what it is”; NMS says “remove duplicates.”

6.4 Sliding windows and region proposals

Traditional sliding-window detection exhaustively evaluates many overlapping image windows. It provides good coverage but is slow and redundant. That is Mark’s concern: too many candidate regions can prevent the conveyor system from meeting its real-time target.

A Region Proposal Network (RPN) learns to suggest likely object regions more intelligently. In a two-stage detector, proposals are then classified and refined.

6.5 Two-stage versus single-shot detection

Dimension Two-stage detector Single-shot detector
Pipeline Proposals first; classify/refine second Direct class + box prediction in one pass
Examples Faster R-CNN YOLO, SSD
Localization Usually stronger, especially for small objects Traditionally somewhat lower, though modern systems narrow the gap
Speed/FPS Lower Higher; real-time friendly
Compute/memory Higher Lower
Complexity Greater Simpler deployment

Single-shot detectors often divide the image into a grid and predict boxes, objectness/confidence and class probabilities directly.

6.6 Intersection over Union (IoU)

IoU measures overlap between predicted box \(B_p\) and ground-truth box \(B_g\):

\[ \operatorname{IoU}(B_p,B_g)=\frac{|B_p\cap B_g|}{|B_p\cup B_g|} \]

  • Range: \(0\) (no overlap) to \(1\) (perfect overlap).
  • The case study uses \(\operatorname{IoU}\ge0.5\) to count a localization as valid.

Practical example: if intersection area is 40 and union area is 80, \(IoU=40/80=0.5\), so it just meets the case-study threshold.

Exam trap: IoU evaluates spatial overlap. It does not classify objects, choose an architecture or control conveyor speed.

6.7 Non-Maximum Suppression (NMS)

Detectors may predict several overlapping boxes around one object. NMS removes redundant detections:

  1. Sort boxes by confidence.
  2. Keep the highest-confidence box.
  3. Compute its IoU with nearby boxes of the relevant class.
  4. Suppress boxes whose overlap exceeds the NMS threshold.
  5. Repeat with the remaining boxes.

IoU is a measurement; NMS is a decision procedure using that measurement.

Exam trap: Evaluation IoU usually compares prediction with ground truth. NMS IoU usually compares predictions with one another.

6.8 Confidence, precision and recall

Precision measures how many predicted detections are correct:

\[ \text{Precision}=\frac{TP}{TP+FP} \]

Recall measures how many real objects were detected:

\[ \text{Recall}=\frac{TP}{TP+FN} \]

High recall means few missed packages; high precision means few false alarms. Industrial conveyor systems may prioritize recall because a missed item can be expensive, while still controlling false positives.

Confidence and NMS thresholds alter the precision–recall balance. Lowering a confidence threshold generally increases recall but may reduce precision.

6.9 FPS, latency and throughput

  • FPS: frames processed per second.
  • Latency: time from capture to usable detection result.
  • Throughput: total work completed per unit time.

High FPS does not automatically guarantee low per-frame latency in every batched system, so both should be measured. In the case study, above 30 FPS is required because the belt moves continuously; slow processing could allow objects to leave the field of view.

6.10 Edge versus cloud deployment

Edge inference (on scanner) Cloud inference
Low and predictable communication latency Powerful/scalable compute
Works without reliable network Easier central updates
Better data locality Can support larger models
Strict compute/memory/power limits Network latency, bandwidth and outages
More device optimization required Possible latency spikes

The quiz’s primary reason for edge computing is reduced communication latency, not automatic accuracy improvement, cost reduction or scalability.

6.11 Optional 3-D depth

Depth supplies distance/spatial information and can:

  • separate touching or overlapping objects;
  • improve localization/counting;
  • help with occlusion; and
  • improve recall.

Costs include extra sensors, calibration, computation and system complexity. Depth does not replace classification, box regression or NMS.

6.12 Case alternatives

Option A — region proposals on an edge device

  • Pros: stronger localization/refinement, low network latency, robust local operation.
  • Cons: lower FPS, higher memory and compute demand on constrained hardware.

Option B — single-shot detector in the cloud, optional depth

  • Pros: high raw throughput, scalable compute, potential recall benefit from depth.
  • Cons: variable network latency, bandwidth dependence and more sensor/cloud complexity.

Reasoned recommendation: Because a moving production line requires predictable low latency and over 30 FPS, first benchmark an optimized single-shot detector on the edge if hardware permits. The stated options need not be accepted as inseparable bundles. If forced to choose only A or B, compare measured end-to-end FPS/latency and miss cost: choose A when localization reliability and deterministic operation dominate and it can be optimized past 30 FPS; choose B only when network service-level guarantees make cloud latency acceptable and throughput/recall dominate.

If a two-stage model reaches only 20 FPS against a 30-FPS target, do not replace it blindly. First:

  1. profile the RPN, backbone, classification and regression heads;
  2. reduce input resolution or proposal count where acceptable;
  3. apply pruning, quantization or hardware acceleration;
  4. retune confidence/NMS thresholds; and
  5. revalidate both FPS/latency and IoU/precision/recall.

7. TensorFlow/Keras CNN implementation

7.1 TensorFlow and Keras

TensorFlow is Google Brain’s open-source framework for building, training and deploying machine-learning/deep-learning models. It supports CPU, GPU, TPU, cloud, mobile and edge execution.

Key ideas:

  • Tensor: multidimensional array; scalar = 0-D, vector = 1-D, matrix = 2-D, and higher-dimensional data are higher-rank tensors.
  • Computational graph: operations are nodes and flowing data are edges, enabling efficient execution.
  • Keras: high-level TensorFlow API for building/training neural networks (tensorflow.keras).
  • Ecosystem: TensorFlow Lite for mobile/embedded deployment, TensorFlow.js for web ML and TensorFlow Extended for production pipelines.

The lecture also mentioned support/use cases spanning CNNs, RNNs, Transformers, supervised/unsupervised/reinforcement learning, NLP chatbots/sentiment/translation, time series, anomaly detection, robotics/games, healthcare and drug discovery.

7.2 Demonstrated sequential model

The demonstration imports TensorFlow and Keras layers/models, constructs a Sequential CNN, and stacks three convolution–pooling blocks:

from tensorflow.keras import layers, models

model = models.Sequential([
    layers.Input(shape=(64, 64, 3)),
    layers.Conv2D(32, (3, 3), activation="relu"),
    layers.MaxPooling2D((2, 2)),
    layers.Conv2D(64, (3, 3), activation="relu"),
    layers.MaxPooling2D((2, 2)),
    layers.Conv2D(64, (3, 3), activation="relu"),
    layers.MaxPooling2D((2, 2)),
    layers.Flatten(),
    layers.Dense(64, activation="relu"),
    layers.Dense(10, activation="softmax"),
])

model.compile(
    optimizer="adam",
    loss="sparse_categorical_crossentropy",
    metrics=["accuracy"],
)

The exact layer widths shown in the transcript were first convolution 32 filters, later convolutions 64 filters, \(3\times3\) kernels, \(2\times2\) max pooling, ReLU hidden activations and a 10-class Softmax output.

With a \(64\times64\times3\) input and valid \(3\times3\) convolution, the first convolution produces \(62\times62\times32\). The first \(2\times2\) pooling then produces \(31\times31\times32\).

For that first convolution, parameters are:

\[ (3\times3\times3+1)\times32=896 \]

Pooling and flattening layers have zero trainable parameters. Dense-layer parameters are \((n_{in}+1)n_{out}\).

7.3 Compilation and model summary

  • Adam is the optimizer.
  • Sparse categorical cross-entropy is appropriate when labels are integer class IDs; categorical cross-entropy is used with one-hot targets.
  • Accuracy is the requested metric.
  • model.summary() reports output shapes and parameter counts.
  • The demonstration reported about 684,490 total/trainable parameters (about 2.61 MB) and zero non-trainable parameters.

Important correction/exam trap: Zero non-trainable parameters does not mean “nothing is left to train” or that training is complete. It means every parameter is currently marked trainable. A frozen transfer-learning backbone would create non-trainable parameters.

7.4 Input-shape warning and modern Keras form

The transcript showed a warning about passing input_shape directly into a layer. In a Sequential model, the input dimensions need to be specified only once; later layers infer their shapes. The clean modern form is an explicit layers.Input(...) as shown above.

7.5 Zero padding

Padding adds border pixels, usually zeros. For stride 1 and an odd \(F\times F\) kernel, choosing

\[ P=\frac{F-1}{2} \]

preserves spatial size. Thus a \(3\times3\) kernel uses \(P=1\). In Keras, padding="same" performs same-size padding for stride 1.

7.6 Training/evaluation

After model construction and compilation:

history = model.fit(x_train, y_train, epochs=..., validation_data=(x_val, y_val))
test_loss, test_accuracy = model.evaluate(x_test, y_test)

The lecture’s code primarily demonstrated architecture and summary; it noted that a real dataset and subsequent epochs/evaluation are needed to measure accuracy.

Instructor emphasis: Change the number of layers, filters and classes to suit the problem statement; do not copy one architecture mechanically. Run and practise the notebook so the theoretical layers become concrete.

9. Likely exam questions with answer points

Q1. Define a CNN and explain its architecture.

Define grid-like image processing; draw input → convolution → ReLU → pooling → repeated blocks → flatten → dense → output; explain filter sliding, feature maps, spatial reduction, hierarchy and classification.

Q2. Why are CNNs preferred to MLPs for images?

Mention local receptive fields, shared weights, fewer parameters, preserved spatial relationships, hierarchical features, compute efficiency and improved tolerance to location changes.

Q3. Perform max/average pooling on a matrix.

Partition according to pool size and stride; select maximum or compute mean in every block. For the lecture matrix, max pooling yields \(\begin{bmatrix}6&4\\4&7\end{bmatrix}\).

Q4. Trace CNN evolution.

LeNet/MNIST → AlexNet/ReLU-GPU-dropout → VGG/small filters and depth → Inception/multiscale efficiency → ResNet/shortcuts → DenseNet/feature reuse → MobileNet/mobile efficiency → EfficientNet/compound scaling → ViT/patch attention.

Q5. Explain transfer learning and fine-tuning.

Define pretrained source model adapted to related target task; explain reusable early features, replacing head, freezing base, training head, optional partial unfreezing at low learning rate; state benefits and overfitting/catastrophic-forgetting caveats.

Q6. Explain a face-recognition pipeline.

Detection → crop/align → embedding CNN → vector comparison → identity. Distinguish detection from recognition and metrics from localization; optionally explain triplet loss.

Q7. Explain neural style transfer mathematically.

Fixed pretrained CNN; generated image is optimized; deep feature content loss + Gram-matrix style loss; total weighted loss \(\alpha L_c+\beta L_s\).

Q8. Distinguish classification, localization and detection.

Classification = what; localization = where; detection = class and box for every object.

Q9. Define IoU and NMS.

Give intersection/union formula, range and 0.5 threshold; describe confidence sorting and overlap suppression; distinguish ground-truth evaluation from prediction-to-prediction suppression.

Q10. Compare two-stage and single-shot detectors.

Two-stage = proposals then classification/regression, usually more precise but slower/heavier. Single-shot = direct one-pass prediction, faster and suitable for real time, traditionally some localization trade-off.

Q11. Recommend a detector/deployment for OptiVision Labs.

Use evidence: >30 FPS, low predictable latency, miss cost, IoU, recall, memory and network conditions. Prefer measured optimization and edge deployment where feasible; justify any choice rather than claiming a universally best model.

Q12. Explain the demonstrated Keras model and parameter counts.

Three Conv2D–MaxPool blocks, flatten, ReLU dense layer, 10-way Softmax; Adam + sparse cross-entropy + accuracy. Use \((k_hk_wc_{in}+1)c_{out}\) for convolution parameters and explain zero-parameter pooling/flatten layers.

10. Exam traps and corrections

  1. “CNNs are only classifiers.” False: they are also backbones for detection, localization, segmentation, embeddings and style transfer.
  2. “Feature maps are patch-level class decisions.” False: they show learned-pattern responses.
  3. “Pooling learns parameters.” Standard max/average pooling does not.
  4. “Flatten preserves spatial arrangement explicitly.” It converts maps to a vector; spatial features must already have been encoded.
  5. “Shared weights never train.” False: shared kernel values train, but the same values are reused spatially.
  6. “ResNet shortcut equals a fully connected layer.” False: it adds an earlier activation through an identity/projection route.
  7. “Transfer learning means no training.” False: at minimum the new head is trained; fine-tuning may adapt upper layers.
  8. “Similarity detects faces.” False: a detector locates; similarity compares embeddings.
  9. “Triplet loss replaces detection.” False: it trains discriminative embeddings.
  10. “NST trains the CNN.” Classical NST freezes the CNN and updates the image.
  11. “Bounding-box regression proposes boxes or removes duplicates.” False: it refines coordinates.
  12. “IoU performs classification.” False: it measures overlap.
  13. “NMS compares predictions with ground truth.” Usually false: it suppresses overlapping predictions.
  14. “Higher FPS always means lower latency.” Not necessarily in batched/pipelined systems; measure both.
  15. “Edge automatically increases model accuracy.” Its main case-study advantage is latency/reliability; hardware is constrained.
  16. “Cloud is always faster.” Compute may be faster, but end-to-end time includes network delay.
  17. “Depth replaces the 2-D detector.” False: it adds spatial information and complexity.
  18. “Zero non-trainable parameters means training is finished.” False: all current parameters are trainable.
  19. “Only the first Conv2D must receive input_shape.” More precisely, input shape is declared once, preferably via an explicit Input layer; subsequent layers infer shapes.

11. Rapid revision sheet

One-line definitions

  • CNN: deep network using local shared filters to learn spatial feature hierarchies.
  • Kernel/filter: small learned matrix slid across an input.
  • Feature map: spatial pattern-response map produced by one filter.
  • ReLU: \(\max(0,x)\).
  • Pooling: parameter-free spatial summarization/downsampling.
  • Flatten: converts feature maps to one vector.
  • Dense layer: aggregates features for classification/regression.
  • Transfer learning: adapts a pretrained model to a related target task.
  • Fine-tuning: gently retrains selected pretrained layers.
  • Embedding: compact vector representation used for similarity matching.
  • IoU: intersection area divided by union area.
  • NMS: removes overlapping duplicate predictions.
  • RPN: learned region-proposal generator.
  • FPS: frames processed per second.
  • Latency: time from input to result.

Must-know formulas

\[ N_{out}=\left\lfloor\frac{N+2P-F}{S}\right\rfloor+1 \]

\[ \operatorname{ReLU}(x)=\max(0,x) \]

\[ p_i=\frac{e^{z_i}}{\sum_j e^{z_j}} \]

\[ \operatorname{IoU}=\frac{\text{intersection}}{\text{union}} \]

\[ \text{Precision}=\frac{TP}{TP+FP},\qquad \text{Recall}=\frac{TP}{TP+FN} \]

\[ y=F(x)+x \]

\[ L_{triplet}=\max(d(A,P)-d(A,N)+\alpha,0) \]

\[ L_{NST}=\alpha L_{content}+\beta L_{style} \]

Review Week augmentation: CNN architecture distinctions

  • At each convolution location, take local input–kernel element-wise products, sum them, optionally add bias, and apply an activation. Sliding this operation produces a feature map. Early filters commonly detect edges/corners/textures; deeper layers combine these into shapes and object parts. Depth increases the effective receptive field.
  • ResNet residual block: \(y=F(x)+x\). The shortcut improves information and gradient flow, reduces degradation/optimization difficulty, and makes very deep (100+ layer) models practical. ResNet is defined by skip connections, not depthwise-separable convolution.
  • MobileNet decomposes ordinary convolution into depthwise spatial filtering of each input channel followed by pointwise \(1\times1\) channel mixing. This reduces parameters and computation for mobile, IoT, edge, and embedded deployment.
  • High-yield distinction: ResNet—skip connections; MobileNet—depthwise-separable convolution; DenseNet—dense connectivity; EfficientNet—compound scaling of depth, width, and resolution.
  • Transfer-learning workflow: load a pretrained model, replace/adapt output layers, then fine-tune selected or all layers. A low learning rate helps preserve useful learned features, especially when the target dataset is small and related.
