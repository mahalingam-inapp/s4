Scope and learning outcomes

Week 10 moves from the earlier deep-learning implementations (which already used Python libraries) to the language foundations needed to understand and write those implementations. By the end of the week, a learner should be able to:

  • explain Python’s origin, design goals, features, applications, and popularity;
  • distinguish interpreted execution from the explicit compile-then-run model;
  • choose between cloud and local development environments;
  • write syntactically correct Python using identifiers, keywords, indentation, quotations, comments, logical lines, variables, assignments, and standard data types;
  • distinguish interactive mode from script mode;
  • define and call functions and explain modularity/reusability;
  • select lists, tuples, and dictionaries based on mutability, lookup, memory, readability, and business requirements; and
  • assemble a small, readable Python program using input, calculations, conditions, loops, collections, and functions.

1. Introduction to Python

1.1 Definition and history

Python is a high-level, general-purpose, interpreted programming language known for simple, readable syntax. It was created by Guido van Rossum and publicly released in 1991. Work began in the late 1980s and drew ideas from earlier languages such as ABC, Modula-3, C, ALGOL, Smalltalk, and Unix shell scripting. The stated design lesson is that Python combined useful ideas while trying to refine disadvantages of earlier languages.

Python is:

  • open source: it can be used without paying a licence fee;
  • supported by a large, continually growing community;
  • suitable for beginners because code resembles natural language;
  • powerful enough for professional, research, and large-project use; and
  • continually developed through Python 2 and Python 3 version families.

Instructor emphasis: Python became a major language because simplicity, flexibility, control, a rich ecosystem, and cross-domain applicability occur together—not because of only one feature.

Examples mentioned include web development, data science, artificial intelligence, machine learning, deep learning, graph neural networks, neural-network model building, data/database analysis, scripting, GUI applications, research, and projects. If a graph neural network or deep-learning task is required, Python’s ecosystem often already provides a suitable library.

1.3 Python compared with C/Java-style development

In C, a beginner must learn constructs such as headers, main, printf, scanf, braces, and an explicit compile/run workflow. In Python, corresponding intent is expressed more directly using functions such as print() and input(), and indentation replaces braces for blocks.

print("Hello Python")
name = input("Enter your name: ")

This does not mean Python has no syntax. It means that its syntax is comparatively compact and readable.

1.4 Portability and supported environments

The lecture describes Python as portable across Unix variants (including Linux, Solaris, and FreeBSD), Windows families, macOS, and historically several other platforms/devices. It has also been ported to Java and .NET virtual-machine environments. The central exam point is cross-platform compatibility, not memorization of obsolete platform names.

Criterion Cloud-based IDE (e.g., Google Colab) Local environment (e.g., Jupyter, VS Code, PyCharm)

Hardware Provider supplies compute; GPU options such as a T4 may be available CPU, RAM, and GPU must exist locally

Instructor Q&A: “Give an example of a cloud-based Python ecosystem/IDE.” Answer: Google Colab. Jupyter Notebook, VS Code, and PyCharm were discussed as local options.

2.2 Local installation workflow

  1. Download Python from python.org.
  2. Run the installer.
  3. Configure/add Python to the system path.
  4. Install or configure an IDE such as PyCharm or VS Code if desired.
  5. Install the libraries required by the project.

An IDE provides editing, execution, debugging, and project-management support; it is not the Python language itself. The Python interpreter executes Python code, while an IDE is a development interface around it.

2.3 Version compatibility caveat

The newest Python version is not automatically the best version for every project. The instructor described a local generative-AI/GPU project in which a newer Python version did not support the required CUDA-related extension, while Python 3.10 (or another earlier compatible version) did. Exact version numbers were recalled uncertainly; the durable lesson is:

  • check the compatibility matrix of Python, CUDA, frameworks, drivers, and packages;
  • do not upgrade merely because a version is newest; and
  • select a version supported by the complete dependency stack.

Exam trap: “Latest version = maximum compatibility” is false.

3. How Python code executes

3.1 Interpreter and compiler

Compiler-oriented workflow Interpreted workflow
The whole source program is translated before execution in a distinct programmer-visible step Statements are executed through an interpreter without a separate user-managed compile step
Produces a machine-code or intermediate artifact before running Supports immediate/interactive execution
Examples discussed: C, C++, Java (Java source becomes bytecode such as .class) Example: Python

Lecture illustration:

  • Java: Hello.java → compile → Hello.class bytecode → execute → output.
  • Python: hello.py → invoke interpreter → output, with no separate compilation command required in the basic workflow.

Technically, common Python implementations may compile source to bytecode internally. Therefore the accurate statement is: Python is commonly described as interpreted because the user normally runs source through an interpreter and does not manage a distinct compile stage.

3.2 Interactive mode (REPL)

The Read–Eval–Print Loop accepts a statement, evaluates it, prints the result, and waits for the next statement.

>>> print("Hello Python")
Hello Python
>>> 3 + 4 * 5
23

Multiplication has higher precedence than addition, so:

\[ 3 + 4 \times 5 = 3 + 20 = 23 \]

Interactive mode is ideal for short tests, learning, and debugging snippets. A multi-line compound statement in the interactive interpreter is terminated by entering an empty physical line.

3.3 Script mode

A complete program is saved, normally with a .py extension, and passed to the interpreter. Execution continues until the script ends or an error/explicit termination occurs. Script mode is suited to reusable, maintainable programs.

Interactive mode Script mode
Immediate one-statement/snippet feedback Executes saved program file
Good for experiments and debugging Good for complete/reusable applications
Work may not be preserved unless copied Code is persistently stored
Blank line can terminate a compound input block Blank lines normally improve readability and do not terminate the file

4. Python lexical and syntax essentials

4.1 Statements and order

A statement is an instruction executed by Python. In ordinary sequential execution, order matters because later statements may depend on earlier state.

x = 10
y = x + 5
print(y)       # 15

Moving y = x + 5 before the assignment to x would fail if x had not already been defined.

4.2 Identifiers

An identifier names a variable, function, class, module, or other object.

Rules:

  • begins with A–Z, a–z, or _;
  • remaining characters may contain letters, digits 0–9, or underscores;
  • cannot contain punctuation such as @, $, or %;
  • cannot be a reserved keyword; and
  • is case-sensitive: Manpower and manpower are different identifiers.

Examples:

sales_total = 100       # valid
_helper = 5             # valid
product2 = "Book"       # valid
# 2product = "Book"     # invalid: begins with digit
# sales-total = 100     # invalid: hyphen

4.3 Naming conventions

Conventions improve consistency even when the interpreter would accept another valid identifier.

  • Class names normally begin with an uppercase letter and use CapWords, e.g., SalesReport.
  • Functions and ordinary variables normally use lowercase snake_case, e.g., calculate_total.
  • A single leading underscore, _name, conventionally marks an internal/non-public name; it does not enforce true privacy.
  • Two leading underscores, __name, inside a class trigger name mangling and are often described pedagogically as “strongly private.” They still do not create absolute security.
  • Names with both leading and trailing double underscores, such as __init__, are language-defined/special (“dunder”) names; do not invent such names casually.

Exam trap: A leading underscore is a convention, not an access-control guarantee.

4.4 Keywords/reserved words

Keywords already have language-defined meanings and cannot be used as identifiers. Examples include and, else, if, for, while, def, return, class, True, False, and None. The transcript describes keywords as lowercase; remember that modern Python also contains case-sensitive literals/keywords such as True, False, and None.

4.5 Indentation and suites

Python does not use braces to delimit blocks for functions, classes, conditions, or loops. A suite is a group/block of statements controlled by a header and represented by indentation.

if score >= 50:
    print("Pass")
    result = True
else:
    print("Fail")
    result = False
  • Statements in the same block must use consistent indentation.
  • The number of spaces is syntactically flexible, but standard style uses four.
  • Incorrect or inconsistent indentation changes block membership or raises an error.
  • if and else align with each other; their controlled statements align within their respective suites.

Instructor emphasis: Indentation is “very important” and is rigidly enforced because it performs the role braces perform in many other languages.

4.6 Logical lines, physical lines, and continuation

A statement normally occupies one logical line. Explicit continuation uses a backslash:

total = item1 + \
        item2 + \
        item3

Inside parentheses, square brackets, or braces, continuation is implicit and the backslash is unnecessary:

days = [
    "Monday",
    "Tuesday",
    "Wednesday",
]

Prefer implicit continuation because a trailing backslash is fragile.

4.7 Multiple statements on one line

Python permits multiple simple statements separated by semicolons:

x = 1; y = 2; print(x + y)

However, one statement per line is clearer and more maintainable. A semicolon is normally unnecessary at the end of a Python statement.

4.8 Quotations and strings

Python accepts matching single or double quotes for ordinary string literals and triple quotes for multi-line strings.

word = 'Python'
sentence = "Python is readable."
paragraph = """This text
occupies multiple lines."""

The opening and closing quote type must match. Triple-quoted strings are string literals; when used as the first statement in a module, class, or function they serve as documentation strings.

4.9 Comments and blank lines

Single-line comments start with # and continue to the line end:

# Calculate net revenue after returns
net_revenue = sales - returns

The lecture refers to triple-quoted text as a way to write multi-line comments. More precisely, Python has no special multi-line comment token: consecutive # lines are comments, while an unassigned triple-quoted literal is merely an unevaluated/unused string expression (and may be a docstring in special positions).

Good comments explain why, assumptions, or non-obvious logic; they should not repeat self-evident code. Blank lines improve visual organization. In a .py file they do not end the program; in an interactive multi-line entry, an empty line signals completion.

5. Variables, assignment, typing, and memory

5.1 Variables and dynamic typing

A variable is a name bound to an object/value. Python does not require a separate type declaration before assignment.

x = 10          # x refers to an int object
x = "ten"       # x now refers to a str object

The object has a type; the name can later be rebound to an object of another type. Python infers the type at assignment time.

age = 25
height = 5.8
name = "Asha"
active = True

print(type(age))       # <class 'int'>

5.2 Assignment and multiple assignment

a = b = c = 0               # same initial value bound to three names
name, age, score = "Ravi", 30, 82.5

The number of targets and unpacked values must match. With mutable values, chained assignment can make multiple names refer to the same object:

a = b = []
a.append(1)
print(b)                     # [1]

5.3 Memory model

Assignment binds a name to an object in memory; it does not necessarily copy a value. Reassignment changes the binding. If no references to an object remain, Python’s memory management can reclaim it. Mutability determines whether an existing object can change in place.

6. Standard data types

6.1 Scalar/basic types

Type Meaning Example Mutable?
int Whole integer; Python supports very large integers subject to memory 42, -7 No
float Floating-point/decimal approximation 3.14, -0.5 No
complex Real and imaginary parts 2 + 3j No
str Ordered Unicode text sequence "Python" No
bool Logical truth value True, False No

Floating-point values are binary approximations, so exact decimal equality can be unreliable in some calculations. Use an appropriate tolerance or decimal representation for precision-sensitive financial work.

6.2 String operations

Strings support concatenation, repetition, indexing/slicing, and many methods.

name = "Python"
greeting = name.upper() + " is fun"
print(greeting)                     # PYTHON is fun
print(name[0:3])                    # Pyt
print("ha" * 3)                    # hahaha

Strings are immutable: methods such as .upper() return a new string rather than altering the original object.

6.3 Collections overview

Structure Syntax Ordered? Mutable? Main access model Best suited to
List [1, 2, 3] Yes Yes Position/index Changeable ordered sequence
Tuple (1, 2, 3) Yes No Position/index Fixed record/configuration
Dictionary {"a": 1} Insertion-ordered in modern Python Yes Key Meaningful key-to-value lookup

The lecture calls dictionaries “unordered,” reflecting an older/general conceptual description. For exams based strictly on the slide, state that dictionaries are key–value mappings and not accessed by numeric position; for modern Python, also know that insertion order is preserved.

7. Lists

A list is a mutable, ordered sequence that can store multiple items, including heterogeneous types.

sales = [120, 135, 128]
sales.append(142)
sales[0] = 125
print(sales)               # [125, 135, 128, 142]

Common operations/methods include append, extend, insert, remove, pop, indexing, slicing, iteration, len, and sorting.

Advantages

  • preserves sequence/order;
  • easy iteration and positional access;
  • grows/shrinks dynamically;
  • supports in-place updates;
  • readable for daily metrics, time series, product records, and other ordered collections.

Limitations

  • searching for an arbitrary value generally requires a linear scan, approximately \(O(n)\);
  • positional entries can become unclear when each field has a business meaning;
  • mutability permits accidental modification; and
  • typically uses more overhead than a comparable tuple.

Use case: daily sales measurements collected chronologically are naturally represented as a list.

8. Tuples

A tuple is an ordered, immutable sequence.

database_config = ("localhost", 5432, "analytics")
coordinates = (10.5, 76.2)

Immutability means the tuple’s element references cannot be added, removed, or reassigned after creation. It signals that the record should remain fixed and helps prevent accidental structural change.

Advantages

  • protects fixed data from direct structural modification;
  • communicates intent clearly;
  • often has slightly less memory overhead than a list; and
  • can be used as a dictionary key when all contained elements are hashable.

Limitations/caveats

  • cannot append, remove, or replace elements;
  • updates require constructing a new tuple;
  • position-only meaning may reduce readability; and
  • a tuple can contain a mutable object, so “tuple is immutable” does not guarantee that every nested object is immutable.

Typical uses: coordinates, fixed configuration values, and stable settings.

9. Dictionaries

A dictionary is a mutable mapping of unique, hashable keys to values.

feature_flags = {
    "dark_mode": True,
    "beta_checkout": False,
}

feature_flags["dark_mode"] = False
print(feature_flags["beta_checkout"])

Common methods include keys(), values(), items(), get(), update(), and pop().

Why lookup is fast

Dictionaries use hashing. A hash function maps a key to a likely storage location, so average insertion, update, and lookup are approximately:

\[ T(n) = O(1) \quad \text{on average} \]

Worst-case behavior can degrade (conceptually toward \(O(n)\)) because of collisions or adversarial conditions, so “constant time” is an average-case claim, not an absolute guarantee.

Advantages

  • fast key-based retrieval;
  • descriptive keys improve readability;
  • convenient updates and membership tests;
  • well suited to feature flags, user information, product catalogs, and ID-based records.

Limitations

  • more memory overhead than simple sequences;
  • keys must be hashable and unique;
  • inconsistent key formats cause failed/duplicated lookups; and
  • dictionary access is by key, not by semantic numeric position.

10. Choosing a data structure: ByteWave Analytics case study

10.1 Business context

ByteWave Analytics must store and retrieve product sales/metrics, configuration settings, and feature flags. The developer perspective prioritizes technical performance, while the project-manager perspective also values maintainability, clarity, team skill, delivery time, and business risk.

10.2 Recommended choices

Requirement Choice Reason
Chronological product sales/daily metrics List Ordered, appendable, easily iterated
Fixed configuration that should not change Tuple Immutability communicates/protects stable structure
Feature flags or values retrieved by name/ID Dictionary Clear key–value semantics and average \(O(1)\) lookup
Complex records Dictionary or list of dictionaries Field names are clearer than unexplained positions

10.3 List versus dictionary for metrics

Use a list when order and sequential processing dominate and lookup by a meaningful ID is unimportant. Use a dictionary when direct lookup/update by product, feature, or user ID dominates.

Example:

# Sequence-oriented
daily_sales = [1200, 1350, 1280]

# Lookup-oriented
sales_by_product = {
    "P100": 1200,
    "P200": 1350,
}

10.4 Normalizing keys before dictionary use

Raw IDs may arrive as integers, strings, differently cased text, or strings with extra spaces. Since 101 and "101" are distinct keys, normalize at the system boundary.

def normalize_product_id(raw_id):
    return str(raw_id).strip().upper()

sales_by_product[normalize_product_id(" p100 ")] = 1200

Normalization creates one canonical representation, simplifies downstream logic, prevents duplicate logical IDs, and reduces special cases. Supporting several raw key types everywhere increases complexity and error risk.

10.5 Decision framework

Ask four questions:

  1. Mutability: must the structure change after creation?
  2. Lookup: is access mainly by position/sequence or by meaningful key?
  3. Memory/performance: are size and lookup frequency large enough to matter?
  4. Readability/maintenance: will another developer understand what each value means?

Avoid both premature optimization (choosing complexity without evidence) and ignoring performance (using linear searches for a genuinely lookup-heavy workload). Benchmark when scale matters, and balance technical efficiency with organizational needs.

11. Input, output, and built-in functions

11.1 input()

input(prompt) displays an optional prompt and returns entered data as a string.

age_text = input("Enter age: ")
age = int(age_text)

Exam trap: input() does not automatically return an integer even if the user types digits.

11.2 print()

print() sends values to standard output.

name = "Asha"
score = 92
print(name, score)
print(f"{name} scored {score}")

11.3 Built-in versus user-defined functions

Built-in function User-defined function
Already supplied by Python Written by the programmer for a specific need
Ready to call Must be defined before it is called during sequential execution
Examples: print, input, len, range, type Examples: add, multiply, divide, greet

Built-ins reduce repeated implementation and improve productivity. User-defined functions provide customization and modularity.

12. Functions and modular programming

A function is a reusable block of code designed to perform a specific task. It is defined using def.

def greet(name):
    return "Hello " + name

message = greet("Shazia")
print(message)                 # Hello Shazia
  • greet is the function name.
  • name is a parameter.
  • "Shazia" is the argument supplied at the call.
  • return sends a result back to the caller.
def add(a, b):
    return a + b

result = add(3, 4)             # 7

Functions turn a long program into manageable modules. Instead of debugging 100 undifferentiated lines, one might isolate ten-line addition, multiplication, and division functions. This improves:

  • reusability;
  • readability;
  • testing and debugging;
  • maintenance;
  • collaboration; and
  • scalability.

Exam trap: Printing and returning are not identical. print(value) displays a value; return value passes it to the caller for further use.

13. Conditions, loops, and a consolidated program

Although the week focuses on language essentials, the implementation session demonstrates variables, functions, loop logic, comments, structure, and indentation together.

def calculate_average(values):
    """Return the arithmetic mean of a non-empty sequence."""
    total = 0
    for value in values:
        total = total + value
    return total / len(values)


student_name = input("Enter student name: ")
scores = [78, 84, 91]
average = calculate_average(scores)

if average >= 50:
    status = "Pass"
else:
    status = "Fail"

print(f"{student_name}: average={average:.2f}, status={status}")

This program shows:

  • a user-defined function and parameter;
  • a list;
  • initialization and reassignment of variables;
  • a for loop and indented suite;
  • len() and input() built-ins;
  • arithmetic;
  • an if/else decision; and
  • formatted output.

14. Important comparisons

14.1 Readability, portability, object orientation, interpretation

These are distinct ideas:

  • Readability: humans can understand the source easily.
  • Portability: the program can run across platforms with little/no change.
  • Object orientation: code can organize state and behavior using classes/objects.
  • Interpreted execution: code is run through an interpreter without a separate user-managed compile step.

One does not imply the others.

14.2 List versus tuple versus dictionary

Question List Tuple Dictionary
Can structure change? Yes No Yes
Access style Index Index Key
Duplicates Allowed Allowed Keys unique; values may repeat
Typical lookup Position \(O(1)\); value search \(O(n)\) Position \(O(1)\); value search \(O(n)\) Key lookup average \(O(1)\)
Meaning Changeable sequence Fixed sequence/record Named mapping

14.3 Dynamic versus static typing

In statically typed languages, a variable is commonly declared with a type that constrains later assignments. In Python, names are dynamically bound and can be rebound to objects of different types. Dynamic typing increases flexibility but can move certain errors from compile time to run time, so clear naming, validation, tests, and optional type hints are useful.

15. Common misconceptions and exam traps

  1. “Python has no compilation whatsoever.” Common implementations may compile internally to bytecode; the key is no separate user-managed compile step in normal use.
  2. “Interpreted means Python ignores syntax.” False; syntax and indentation are enforced.
  3. “Semicolons are required.” False; they are usually unnecessary.
  4. “Indentation is only cosmetic.” False; it defines suites/blocks.
  5. “Any spaces are fine within one block.” False; indentation must be consistent.
  6. “Triple quotes are a true multi-line-comment operator.” Strictly false; they create string literals, although unused ones are sometimes employed comment-like.
  7. “Variables have permanent types.” False; objects have types and names can be rebound.
  8. “Assignment copies an object.” Not necessarily; it normally binds another reference.
  9. “Tuples make everything inside immutable.” False if they contain mutable nested objects.
  10. “Dictionaries are always \(O(1)\).” Average key operations are \(O(1)\); worst cases can be worse.
  11. “Dictionaries are lists with labels.” Incomplete; they are hash mappings with unique hashable keys.
  12. “A leading underscore makes data secure/private.” It is mainly a convention.
  13. “input() returns the type the user intended.” It returns a string unless explicitly converted.
  14. “An IDE and interpreter are the same.” The IDE assists development; the interpreter executes Python.
  15. “Cloud is always preferable.” Local execution may be required for privacy, security, offline work, or controlled dependencies.
  16. “Local is always faster/more capable.” Cloud systems can supply GPUs and eliminate local hardware constraints.
  17. “Newest Python is always safest.” Framework/CUDA/package compatibility may require an earlier version.
  18. “Readable code matters only to beginners.” Readability directly improves professional collaboration, debugging, maintenance, and scalability.

16. Likely examination questions with answer points

Q1. Define Python and explain its major features.

Python is a high-level, general-purpose, interpreted, open-source language created by Guido van Rossum and released in 1991. Explain simplicity, readability, versatility, dynamic typing, rich libraries, portability, interactivity, extensibility, database/GUI support, and scalability, with applications in web, data science, AI/ML/DL, scripting, and research.

Q2. Why is Python considered beginner-friendly yet powerful?

Natural-language-like syntax, few keywords, no brace-heavy boilerplate, immediate execution, and rich built-ins reduce entry difficulty. Libraries, extensibility, cross-platform support, database/GUI connectivity, and AI/data ecosystems support professional-scale work.

Q3. Compare compiled and interpreted languages.

Discuss whole-program translation as a distinct step versus interpreter-led execution; use C/C++/Java and Python examples; mention Java bytecode; qualify that Python may create bytecode internally.

Q4. Compare interactive and script modes.

Define REPL and .py script execution; compare immediacy, persistence, use cases, and blank-line behavior for multi-line REPL statements.

Q5. Explain Python identifier rules and conventions.

State valid first/subsequent characters, case sensitivity, prohibition on punctuation/keywords, class/function naming style, and meanings/caveats of _name, __name, and __name__.

Q6. Why is indentation significant in Python?

It defines suites for functions, classes, conditions, and loops; replaces braces; must be consistent; incorrect indentation changes logic or raises an error. Include a short if/else example.

Q7. Explain dynamic typing and Python’s memory model.

Names bind to typed objects; no type declaration is required; rebinding can change the referenced type; assignment may share references; mutable objects can be changed in place.

Q8. Distinguish built-in and user-defined functions.

Built-ins are predefined (print, input, len, range); user-defined functions use def for specific requirements. Discuss parameters, arguments, return values, modularity, reusability, readability, and debugging.

Q9. Compare lists, tuples, and dictionaries.

Use the structure comparison table: order, mutability, access model, complexity, memory/readability implications, and appropriate use cases.

Q10. Recommend structures for ByteWave Analytics.

List for chronological/changeable sales; tuple for fixed configuration; dictionary for feature flags or ID lookup. Explain normalization of product IDs and balance developer performance concerns with manager maintainability/delivery concerns.

Q11. Compare cloud and local Python environments.

Google Colab versus local Jupyter/VS Code/PyCharm: setup, compute/GPU availability, privacy, internet reliance, dependency control, and version compatibility.

Q12. Explain comments, quotations, and line continuation.

Cover #, the triple-quoted-string caveat, matching quote marks, explicit \ continuation, implicit continuation inside delimiters, and blank lines.

  • Script: saved .py program executed by interpreter.
  • Identifier: letter/underscore first; then letters/digits/underscores; case-sensitive; no keywords/punctuation.
  • Block structure: colon + consistent indentation; four spaces by convention.
  • Comment: #; triple quotes are strings, not a dedicated comment syntax.
  • Continuation: backslash explicitly; implicit inside (), [], {}.
  • Dynamic typing: objects have types; names are rebound.
  • input(): returns str; convert explicitly.
  • Function: def name(parameters): ... return value.
  • List: ordered + mutable; use for changing sequences.
  • Tuple: ordered + immutable; use for fixed structures.
  • Dictionary: key–value + mutable; average key lookup \(O(1)\).
  • Sequence value search: generally \(O(n)\).
  • Normalization: convert external identifiers to one canonical form before using them as keys.
  • Final design rule: select a structure from requirements—mutability, access pattern, scale, memory, readability—not habit.
