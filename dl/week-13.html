1. Week at a glance

Week 13 connects two representation-learning problems:

  1. Principal Component Analysis (PCA): transform high-dimensional numerical data into fewer, orthogonal, variance-preserving dimensions.
  2. Bag-of-Words (BoW): transform text into numerical feature vectors that machine-learning algorithms can process.

The advanced text section then improves BoW with TF-IDF, n-grams, subword features, feature selection, dimensionality reduction, topic modelling, and modern embeddings.

Part I — Principal Component Analysis (PCA)

2. Definition and purpose

Principal Component Analysis (PCA) is a statistical, linear-algebra-based technique for dimensionality reduction and representation learning. It transforms possibly correlated original features into a smaller set of uncorrelated (orthogonal) principal components, ranked by how much variance they explain.

PCA projects data from its original feature space to a component space. The aim is to preserve the most important patterns with fewer dimensions.

Key terms

Term Meaning
Dimensionality Number of features/axes used to represent an observation
Dimensionality reduction Replacing many dimensions with fewer informative ones
Principal component (PC) A new axis/direction formed as a linear combination of original features
Orthogonal Perpendicular; components are mutually uncorrelated
Variance Spread of data along a direction; PCA treats larger variance as more information-bearing
Explained variance Variance captured by a component
Covariance Extent to which two features vary together

Instructor emphasis: the first principal component captures the maximum possible variance; the second captures the maximum remaining variance subject to being orthogonal to the first; later PCs follow the same rule.

3. Why dimensionality reduction matters

PCA can:

  • improve computational efficiency and reduce training time;
  • reduce storage requirements and compress data;
  • remove redundant/correlated information;
  • mitigate overfitting by reducing unnecessary features;
  • suppress low-variance noise;
  • permit 2-D or 3-D visualization of high-dimensional data;
  • reveal clusters, patterns, and relationships more clearly;
  • sometimes improve downstream classification performance.

Important qualification

The lecture informally calls PCA “feature selection.” More precisely, PCA is usually feature extraction: it creates new features from linear combinations of the originals. It does not normally select a literal subset of original columns.

4. Mathematical foundation

Assume a data matrix $X\in\mathbb{R}^{n\times d}$, where $n$ is the number of samples and $d$ the number of features.

4.1 Standardization

PCA is scale-sensitive. For each feature $j$, compute

\[ z_{ij}=\frac{x_{ij}-\mu_j}{\sigma_j} \]

where μ_j is its mean and σ_j its standard deviation. Standardized features have approximately mean 0 and variance 1, preventing a large-unit feature from dominating merely because of its scale.

If features already share meaningful, comparable units, centering may sometimes suffice; for the taught workflow, use standardization.

4.2 Covariance matrix

For standardized matrix $Z$, the sample covariance matrix is

\[ C=\frac{1}{n-1}Z^T Z \]

$C\in\mathbb{R}^{d\times d}$. Its diagonal contains feature variances; off-diagonal entries describe pairwise covariance.

4.3 Eigenvalues and eigenvectors

Solve

\[ Cv_i=\lambda_i v_i \]

  • $v_i$: eigenvector, giving a principal direction;
  • $\lambda_i$: eigenvalue, giving variance captured along that direction.

Sort eigenpairs so that

\[ \lambda_1\ge\lambda_2\ge\cdots\ge\lambda_d. \]

The eigenvectors of the symmetric covariance matrix are orthogonal.

4.4 Explained-variance ratio

For PC $i$,

\[ \text{EVR}_i=\frac{\lambda_i}{\sum_{j=1}^{d}\lambda_j}. \]

Cumulative explained variance for the first $k$ PCs is

\[ \text{CEV}(k)=\sum_{i=1}^{k}\text{EVR}_i. \]

Choose the smallest $k$ that reaches a desired information threshold, such as 90%, 95%, or another value justified by validation.

4.5 Projection

Let $W_k=[v_1,v_2,\ldots,v_k]$. The reduced representation is

\[ Y=ZW_k, \]

where $Y\in\mathbb{R}^{n\times k}$.

An approximate reconstruction is

\[ \hat Z=YW_k^T, \]

and, after undoing standardization, it can be returned to the original units. Reconstruction is approximate when $k

5. Complete PCA workflow

  1. Collect the $n\times d$ dataset.
  2. Split training and test data when building a predictive model.
  3. Fit scaling parameters on the training set only; transform both train and test with those parameters.
  4. Compute the training covariance matrix.
  5. Calculate eigenvalues and eigenvectors.
  6. Sort eigenvectors by descending eigenvalue.
  7. Select the top $k$ directions using cumulative explained variance and/or validation.
  8. Project training and test observations into the $k$-dimensional subspace.
  9. Train/evaluate the downstream model or visualize the projected data.

Data-leakage trap

Do not standardize or fit PCA on the full dataset before splitting. Test-set means, variances, and directions would leak into training. In a pipeline:

\[ \text{train data}\rightarrow\text{fit scaler}\rightarrow\text{fit PCA}\rightarrow\text{fit model}. \]

Apply the already fitted transformations to validation/test data.

6. Visualization intuition

Before PCA, high-dimensional points may appear scattered or overlapping. Projection onto PC1 and PC2 reorients the coordinate system toward the directions of greatest variation. A 2-D/3-D plot may then expose clusters or class structure.

Taught 3-D example

For a 3-feature dataset:

  1. form a $3\times3$ covariance matrix;
  2. obtain $\lambda_1,\lambda_2,\lambda_3$ and $v_1,v_2,v_3$;
  3. if $\lambda_1$ and $\lambda_2$ together explain 95% of variance, keep $v_1,v_2$;
  4. project the data onto their 2-D subspace.

Practical example

If a dataset has 100 features but its first 10 PCs retain nearly all useful variability, work with those 10 components. This simplifies storage and modelling, although each PC is a combination rather than one of the original 100 variables.

7. MNIST case study

MNIST consists of grayscale images of handwritten digits. Each $28\times28$ image becomes 784 pixel features, so the raw data are high-dimensional.

PCA can transform the 784 correlated pixel dimensions into fewer components that capture dominant handwriting variations. Benefits include:

  • lower computational load and faster model training;
  • smaller storage footprint;
  • 2-D visualization using the first two PCs;
  • removal of less informative/noisy pixel directions;
  • possible improvement in classification through denoising.

It is not guaranteed to improve accuracy: PCA preserves variance, not class-separating information.

8. Applications

Application PCA contribution
Data compression Stores fewer component scores while retaining much variability
Image compression Keeps dominant visual structure with fewer dimensions
Noise reduction Discards low-variance directions often associated with noise
Visualization Projects high-dimensional data into 2-D/3-D
Preprocessing Reduces collinearity and model input size
Pattern discovery Can expose dominant structure, relationships, or clusters
Text matrices Can reduce a numeric document-term/TF-IDF matrix, although truncated SVD is often more natural for sparse text

9. Advantages and limitations

Advantages Limitations
Reduces dimensions and redundancy PCs are harder to interpret than original features
Improves speed and storage efficiency Assumes useful structure is linear
May reduce overfitting Sensitive to feature scale
Can remove low-variance noise High variance is not always task-relevant information
Enables visualization Outliers can distort covariance and PCs
Produces uncorrelated components Information is lost when components are discarded

Linear vs nonlinear structure

Ordinary PCA finds linear directions. If data lie on a nonlinear manifold, linear PCs may not represent it well. Kernel PCA extends the idea by implicitly mapping data to a nonlinear feature space, but it is more complex and harder to interpret.

10. PCA exam traps

  • Principal, not “principle,” component analysis.
  • PCA does not merely delete columns; it rotates the feature space and forms linear combinations.
  • Orthogonal/uncorrelated PCs do not automatically imply statistically independent PCs.
  • PC signs are arbitrary: $v$ and $-v$ define the same axis.
  • PCA is unsupervised and ignores class labels.
  • Maximum variance is not identical to maximum predictive power.
  • Standardization and PCA serve different purposes: scaling equalizes feature influence; PCA rotates/reduces dimensions.
  • Reduced representation $Y$ is not the same as reconstruction $\hat Z$.
  • Low variance is often noise, not always; a low-variance feature can be discriminative.
  • Fit preprocessing only on training data.

Part II — Bag-of-Words (BoW)

11. Definition

Bag-of-Words (BoW) is a simple text-representation method that converts documents into numerical vectors. Every unique vocabulary term becomes a feature, and a document’s value for that feature records the term’s count or presence.

It disregards grammar and word order while retaining word occurrence/frequency. It is called a “bag” because the model knows which words are present, but not their sequence.

Core objects

Object Meaning
Corpus A structured collection of text documents
Document One text unit, e.g., review, article, tweet, or email
Token A unit produced by tokenization, commonly a word
Vocabulary Set of unique retained tokens/features across the corpus
Document-term matrix Rows are documents; columns are vocabulary features
Sparse matrix Matrix storing mainly the nonzero entries

A corpus may include metadata such as source, genre, author, or domain. Corpora can be general or domain-specific (medical, legal, scientific). They support model training, language-pattern analysis, frequency studies, sentiment analysis, topic modelling, and classification.

12. BoW construction pipeline

12.1 Collect a corpus

Example:

  • $D_1$: “I love machine learning”
  • $D_2$: “Machine learning is amazing”
  • $D_3$: “I love deep learning”

12.2 Preprocess

Typical steps:

  1. Text cleaning: remove unwanted punctuation, special characters, and—when appropriate—numbers.
  2. Lower-casing: map “Product” and “product” to one feature unless capitalization carries meaning.
  3. Tokenization: split documents into tokens.
  4. Stop-word treatment: optionally remove frequent function words such as “the,” “is,” and “and.”
  5. Stemming or lemmatization: optionally reduce related forms to a shared base.

12.3 Build the vocabulary

After suitable preprocessing, a possible vocabulary is:

\[ [\text{amazing},\text{deep},\text{is},\text{learning},\text{love},\text{machine}]. \]

Vocabulary order fixes column order.

12.4 Vectorize each document

Using the order above:

Document amazing deep is learning love machine
$D_1$ 0 0 0 1 1 1
$D_2$ 1 0 1 1 0 1
$D_3$ 0 1 0 1 1 0

This document-term matrix is the numerical input to a model.

13. Binary vs frequency BoW

Representation Value Best interpretation
Binary 1 if term occurs, otherwise 0 Presence/absence matters
Frequency/count Number of occurrences Repetition/intensity matters

If “good” appears three times, binary BoW records 1; count BoW records 3.

Exam trap: both vectors have one dimension per vocabulary term. Binary encoding does not reduce dimensionality; it only changes values.

14. Why sparse representation matters

Real vocabularies can contain thousands or millions of features, while any single document uses only a small subset. Most matrix entries are zero, so the document-term matrix is high-dimensional and sparse.

Sparse storage:

  • stores nonzero values and their positions rather than every zero;
  • reduces memory and often speeds computation;
  • is the default output style of tools such as CountVectorizer.

Converting a large sparse matrix to a dense array can exhaust memory.

15. Preprocessing decisions and caveats

Stop words

Removing stop words reduces vocabulary and noise, but it is task-dependent. Words such as “not,” “no,” and “never” may be crucial to sentiment:

  • “good” vs “not good”
  • “recommend” vs “do not recommend”

Do not apply a generic stop-word list blindly.

Stemming

Stemming crudely strips affixes: e.g., “connected,” “connecting,” and “connection” may be mapped toward a common stem. It lowers sparsity/vocabulary size but can create unnatural stems or merge distinct meanings.

Lemmatization

Lemmatization maps inflected words to linguistic lemmas, e.g., “better” → “good” when context supports it. It is usually more interpretable but costs more computation and language knowledge.

Vocabulary-size trade-off

  • Smaller vocabulary: faster, less sparse, lower overfitting risk, but can discard meaningful distinctions.
  • Larger vocabulary: preserves detail and nuance, but raises memory, computation, and sparsity.

Choose using validation performance, not stakeholder preference alone.

16. Strengths, weaknesses, and use cases

Strengths

  • simple and intuitive;
  • easy to implement;
  • efficiently produces numeric features;
  • works with many conventional ML algorithms;
  • strong, interpretable baseline;
  • useful with limited data or computational resources.

Weaknesses

  • ignores word order, grammar, context, and much semantics;
  • treats vocabulary entries as unrelated dimensions;
  • creates large, sparse, high-dimensional matrices;
  • raw counts overemphasize common or long-document terms;
  • struggles with synonyms and polysemy;
  • vocabulary may fail on unseen/out-of-vocabulary words.

Applications

  • text/document classification;
  • spam detection;
  • topic categorization;
  • basic sentiment analysis;
  • information retrieval/basic search by matching query and document terms;
  • feature extraction for traditional machine-learning models.

BoW remains valuable when word presence/frequency matters more than deep context, or as a fast baseline on small datasets.

Part III — Improvements and advanced text representations

17. TF-IDF

Raw BoW gives common terms large counts even when they are not informative. Term Frequency–Inverse Document Frequency (TF-IDF) increases the importance of terms frequent in one document but rare across the corpus.

Term frequency

A common normalized definition is

\[ TF(t,d)=\frac{f_{t,d}}{\sum_{u\in d}f_{u,d}}, \]

where $f_{t,d}$ is the count of term $t$ in document $d$. Implementations may use raw or log-scaled TF.

Document frequency and inverse document frequency

Let $N$ be the number of documents and $df(t)$ the number containing $t$:

\[ IDF(t)=\log\left(\frac{N}{df(t)}\right). \]

Smoothed implementations often use

\[ IDF(t)=\log\left(\frac{N+1}{df(t)+1}\right)+1. \]

Combined weight

\[ TFIDF(t,d)=TF(t,d)\times IDF(t). \]

Thus corpus-wide common words are downweighted; rare but locally important words are highlighted. Uses include keyword extraction, document classification, retrieval, and sentiment analysis.

BoW vs TF-IDF

BoW count TF-IDF
Raw occurrence frequency Frequency adjusted by corpus rarity
Common words may dominate Common words receive low weight
Simple and interpretable Often more discriminative
No corpus-level importance Explicitly uses document frequency

TF-IDF still does not inherently capture word order or semantic equivalence.

18. N-grams

An n-gram is a sequence of $n$ consecutive tokens:

  • unigram: one token, e.g., “machine”;
  • bigram: two tokens, e.g., “machine learning”;
  • trigram: three tokens, e.g., “deep learning model.”

For “I love natural language processing,” bigrams are:

\[ (I, love), (love, natural), (natural, language), (language, processing). \]

Benefits

  • partially restores local word order;
  • treats meaningful phrases (“machine learning”) as features;
  • preserves negation patterns such as “not good”;
  • helps sentiment analysis, classification, and contextual feature extraction.

Costs

  • vocabulary grows rapidly;
  • sparsity, memory, and computation rise;
  • rare n-grams can overfit;
  • longer n-grams still do not provide general contextual understanding.

Use validation and controls such as minimum document frequency, maximum vocabulary size, or regularization.

19. Subword and character features

Instead of whole words, features may be characters or subwords. This helps:

  • morphologically rich languages such as German and Finnish;
  • misspellings and word variants;
  • unseen words;
  • related forms such as “run,” “running,” and “runner.”

“Unhappiness” might be represented using units resembling “un,” “happy,” and “ness.” Techniques mentioned include Byte-Pair Encoding (BPE) and SentencePiece.

20. Reducing or structuring a BoW matrix

Method Purpose
PCA Dense linear components maximizing variance
Truncated SVD / LSA Low-rank latent structure; suitable for sparse text matrices
NMF Nonnegative factors that can form interpretable topics
χ² test Selects features associated with class labels
Mutual information Selects features informative about labels
LDA topic model Represents documents as mixtures of topics and topics as mixtures of words

PCA on text

PCA can reduce a high-dimensional numeric BoW/TF-IDF matrix, but centering may destroy sparsity. Truncated SVD, often called latent semantic analysis in this setting, is commonly preferred because it operates efficiently on sparse matrices.

PCA vs LDA

  • PCA/SVD: algebraic dimensionality reduction; components capture variance/low-rank structure.
  • Latent Dirichlet Allocation: probabilistic topic model; documents are topic mixtures and topics are word distributions.

Do not confuse LDA topic modelling with Linear Discriminant Analysis, which shares the abbreviation.

21. Topic modelling

Topic models discover hidden themes without requiring document labels.

  • LDA: documents are mixtures of topics; topics are mixtures/distributions of words.
  • NMF: decomposes the nonnegative document-term matrix into document-topic and topic-term factors.

A news corpus, for example, may yield topics corresponding to sports, politics, and entertainment.

22. Word embeddings and modern NLP

Word2Vec and GloVe map words to dense continuous vectors where semantic relationships can be represented geometrically. Unlike BoW/TF-IDF, embeddings can associate related words.

BERT (Bidirectional Encoder Representations from Transformers) creates context-sensitive representations by considering text in both directions. This improves tasks such as sentiment analysis and question answering and helps resolve words whose meanings depend on context.

Property BoW TF-IDF Static embedding Contextual model (e.g., BERT)
Counts/occurrences Yes Weighted No No
Word order/context No No Limited/static Strong
Semantic similarity No No Yes Yes, context-dependent
Dimensionality High, sparse High, sparse Low, dense Dense, computationally costly
Simplicity/speed Highest High Moderate Lowest/highest resource cost

Instructor emphasis: modern representations address BoW’s shortcomings, but BoW remains an important baseline because it is simple, fast, and effective in suitable tasks.

Part IV — Sentiment-analysis case study

23. Problem

A company wants to classify customer reviews as positive, negative, or neutral so that negative feedback can be addressed and customer experience improved.

Examples:

  • Positive: “The product is excellent. I loved it.”
  • Negative: “This is the worst product I have ever used.”

For binary classification, positive may be labelled 1 and negative 0.

24. End-to-end pipeline

  1. Collect and label reviews.
  2. Split train/validation/test data before fitting text transformations.
  3. Clean text; lower-case where appropriate.
  4. Tokenize.
  5. Apply a sentiment-aware stop-word policy.
  6. Stem or lemmatize only if validation supports it.
  7. Fit a vocabulary on training text.
  8. Build count/binary BoW or TF-IDF features; consider word and phrase n-grams.
  9. Train a classifier such as logistic regression or Naive Bayes.
  10. Evaluate with a confusion matrix and appropriate metrics.
  11. Inspect errors, vocabulary coverage, and effects of negation.

The sample positive review may become “product excellent love” after preprocessing, though removing “it” and other tokens is a modelling choice rather than a universal rule.

25. Customer-feedback representation dispute

In the embedded case, Jane must reconcile two stakeholder preferences:

  • Omar — information-rich model: moderate stop-word removal, frequency counts, and less aggressive preprocessing. Counts distinguish “good” from “good good good” and may help granular sentiment analysis, though repetition is not a perfect measure of sentiment intensity.
  • Sofia — lean model: aggressive stemming and binary presence features, prioritizing processing speed, memory, and operational simplicity.

Jane is therefore balancing feature richness against model simplicity. Frequency and binary vectors have the same dimensionality when they use the same vocabulary; the distinction is the information stored in each cell. Vocabulary size—not whether values are binary or counts—controls the number of dimensions.

The case’s third document, “Programming is fun and I love learning new programming skills,” records programming = 2 under frequency BoW. The count captures repetition but not relationships such as “programming is fun” or “I love learning.”

Correct resolution

Treat preprocessing, vocabulary size, and vector values as separate decisions. Compare candidate pipelines empirically under the same split and metric:

  • Model A (Omar-aligned): moderate preprocessing + frequency BoW.
  • Model B (Sofia-aligned): aggressive preprocessing + binary BoW.

Record predictive metrics (accuracy, precision, recall, F1) and operational metrics (training/inference time, memory, vocabulary size, and feature dimensionality). A further sentiment-aware variant can retain negators, use unigrams+bigrams, and/or TF-IDF.

Select based on validation evidence, inference/storage constraints, and error analysis. If strengths are complementary, an ensemble could be explored later—but first establish whether either individual pipeline is adequate.

Why the extremes are unsafe

  • Simplest is not always best: removing “not” can reverse sentiment.
  • Richest is not always best: indiscriminate features raise sparsity and overfitting.
  • Stakeholder compromise is not a substitute for controlled experimentation.

26. Evaluation

For classification, construct a confusion matrix and compute metrics suited to the class distribution:

\[ \text{Accuracy}=\frac{TP+TN}{TP+TN+FP+FN} \]

\[ \text{Precision}=\frac{TP}{TP+FP},\qquad \text{Recall}=\frac{TP}{TP+FN} \]

\[ F_1=2\frac{\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}}. \]

For imbalanced sentiment classes, macro-F1 or per-class recall may reveal weaknesses hidden by accuracy.

27. Visualization

  • Word cloud: word size reflects corpus frequency; useful for an overview but not rigorous comparison.
  • Bar chart: displays top-term frequencies more precisely.
  • These reveal dominant terms/themes and can guide feature inspection.

Frequency does not equal importance or sentiment; a common word can be visually large yet uninformative.

Part V — Python implementation using CountVectorizer

28. Conceptual code

from sklearn.feature_extraction.text import CountVectorizer

corpus = [
    "I love machine learning",
    "Machine learning is amazing",
    "I love deep learning",
]

vectorizer = CountVectorizer()
X = vectorizer.fit_transform(corpus)

print(vectorizer.get_feature_names_out())
print(X.toarray())  # suitable only for this tiny demonstration

Meaning of each step

  • CountVectorizer() defines tokenization/vocabulary/count rules.
  • fit_transform(corpus) learns the vocabulary and creates the document-term matrix.
  • get_feature_names_out() returns column names in matrix order.
  • X is sparse: rows represent documents; columns represent vocabulary terms; entries are counts.
  • toarray() exposes the dense matrix for a small classroom example, but should be avoided for large corpora.

Typical frequency plot

import matplotlib.pyplot as plt

terms = vectorizer.get_feature_names_out()
frequencies = X.sum(axis=0).A1

plt.bar(terms, frequencies)
plt.title("Word Frequencies in Corpus")
plt.xlabel("Words")
plt.ylabel("Frequency")
plt.xticks(rotation=45)
plt.tight_layout()
plt.show()

The lecture’s core implementation sequence is: create corpus → create vectorizer → fit and transform → inspect vocabulary/matrix → aggregate frequencies → plot.

Safe predictive pipeline

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

model = Pipeline([
    ("tfidf", TfidfVectorizer(ngram_range=(1, 2))),
    ("clf", LogisticRegression(max_iter=1000)),
])

model.fit(train_texts, train_labels)
predictions = model.predict(test_texts)

The pipeline ensures the vocabulary/IDF is learned only from training data when evaluation is correctly arranged.

Part VI — High-yield comparisons

PCA BoW
General method for high-dimensional numerical data Text-specific conversion to numerical features

Part VII — Likely exam questions with answer points

32. Short-answer questions

Q1. Define PCA.

PCA is an unsupervised linear transformation that converts correlated features into orthogonal principal components ordered by explained variance, enabling dimensionality reduction while retaining dominant patterns.

Q2. State the steps of PCA.

Standardize/center data; compute covariance matrix; find eigenvalues/eigenvectors; sort by eigenvalue; choose top $k$; project data onto those eigenvectors.

Q3. What do eigenvectors and eigenvalues mean in PCA?

Eigenvectors define component directions; corresponding eigenvalues quantify variance captured by them.

Q4. Why standardize before PCA?

Because PCA is scale-sensitive. Standardization prevents large-scale features from dominating covariance and the resulting PCs.

Q5. Define BoW and state its main limitation.

BoW maps documents to vocabulary-based count/presence vectors. Its main limitation is loss of word order and context; it also creates sparse, high-dimensional data.

Q6. What is a corpus?

A structured collection of text documents used for language analysis or model training, often with metadata and sometimes tailored to a domain.

Q7. Compare BoW and TF-IDF.

BoW uses raw counts/presence. TF-IDF multiplies within-document frequency by inverse corpus frequency to downweight ubiquitous words and highlight document-specific terms.

Q8. Why use n-grams?

They capture local word sequence and phrases, including negation such as “not good,” but expand vocabulary and sparsity.

Q9. Why is BoW sparse?

The corpus vocabulary is large while each document contains only a small subset, so most document-term cells are zero.

Q10. How can BoW be improved?

Use TF-IDF, n-grams, subword features, better preprocessing, feature selection, LSA/truncated SVD, NMF/topic modelling, or semantic/contextual embeddings.

34. One-line memory aids

  • PCA: standardize → covariance → eigenpairs → rank → select $k$ → project.
  • PC1: direction of maximum variance.
  • Eigenvector: direction; eigenvalue: variance captured.
  • BoW: tokenize → vocabulary → count/presence vector.
  • TF-IDF: important here, uncommon everywhere.
  • N-gram: consecutive token sequence that restores limited order.
  • Sparse matrix: many dimensions, mostly zeros.
  • Embedding: dense semantic vector; contextual embeddings vary with context.

36. Final conceptual map

\[ \text{Raw text} \xrightarrow{\text{clean/tokenize}} \text{tokens} \xrightarrow{\text{vocabulary + weighting}} \text{sparse BoW/TF-IDF matrix} \xrightarrow{\text{optional selection/SVD/PCA}} \text{compact features} \xrightarrow{\text{classifier}} \text{prediction} \]

For general numerical data:

\[ \text{high-dimensional data} \xrightarrow{\text{standardize}} \text{covariance/eigenanalysis} \xrightarrow{\text{top PCs}} \text{lower-dimensional representation}. \]

Bottom line: BoW makes text computable; TF-IDF and n-grams make frequency features more useful; PCA/SVD make high-dimensional representations more compact; embeddings and transformers add semantic and contextual understanding.
