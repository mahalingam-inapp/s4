Part I — Matplotlib Stacked Plots / Area Charts

1. Meaning and purpose

A stacked plot or stacked area chart displays numerical information for multiple collections or categories, with each category stacked on top of the preceding one.

It is especially useful for:

  • showing cumulative data over time;
  • displaying how several components contribute to a total;
  • comparing both the overall total and the changing contribution of categories.

The Matplotlib function is:

plt.stackplot(x, y1, y2, ..., labels=..., colors=..., alpha=...,
              edgecolor=..., linewidth=...)

2. Important stackplot() arguments

Argument Meaning Exam point
x X-axis values, such as time points or categories All Y-series correspond to these positions.
y1, y2, ... Numerical datasets for the categories to be stacked Their order determines bottom-to-top stacking.
labels Names for the stacked areas Used by the legend.
colors Custom colors for the stacked areas Must remain aligned with the Y-series order.
alpha Opacity/transparency 0 is fully transparent; 1 is fully opaque.
edgecolor Color of area boundaries Helps visually separate adjacent areas.
linewidth Width of area boundaries Controls boundary prominence.

Accuracy note: The instructor correctly interprets alpha=0.7 as 70% opaque and 30% transparent, but later says “100” is fully opaque. In Matplotlib the practical range is 0 to 1, so alpha=1, not 100, is fully opaque.

3. Worked example: weekly temperatures in three cities

Task

Create a stacked area plot showing average daily temperatures from Monday to Sunday for Chennai, Kochi, and Bengaluru.

The transcript uses these data:

import matplotlib.pyplot as plt

days = ["Monday", "Tuesday", "Wednesday", "Thursday",
        "Friday", "Saturday", "Sunday"]

chennai = [36, 35, 32, 30, 35, 32, 29]
kochi = [28, 29, 30, 31, 29, 28, 25]
bengaluru = [25, 23, 26, 27, 27, 28, 26]

plt.stackplot(days, chennai, kochi, bengaluru)
plt.show()

Improved aesthetics and readability

labels = ["Chennai", "Kochi", "Bengaluru"]
colors = ["lightblue", "lightgreen", "lightcoral"]

plt.stackplot(
    days,
    chennai,
    kochi,
    bengaluru,
    labels=labels,
    colors=colors,
    alpha=0.7
)
plt.legend(loc="upper center")
plt.title("Days of Week versus Temperature")
plt.show()

The plotted order is:

  • Chennai at the bottom in light blue;
  • Kochi in the middle in light green;
  • Bengaluru at the top in light coral.

Changing stack order

To place Bengaluru at the bottom, Kochi in the middle, and Chennai at the top, change the sequence of Y-series:

plt.stackplot(
    days,
    bengaluru,
    kochi,
    chennai,
    labels=["Bengaluru", "Kochi", "Chennai"],
    colors=["lightcoral", "lightgreen", "lightblue"],
    alpha=0.7
)

Core rule: The first Y-series becomes the bottommost layer; each later series is placed above it.

When order changes, also reorder:

  • labels, so the legend remains correct;
  • colors, if each city/category is meant to retain its original color.

Interpretation caveat

A stacked temperature plot demonstrates the function, but summing temperatures across cities is not normally a meaningful “total.” In applied work, stacked areas are strongest when components genuinely form a cumulative whole, such as sales by product over time, expenses by category, or energy supplied by source.

Part II — Multiple Plots with subplot()

5. Why subplots are needed

Earlier work included:

  • one plot on one axes;
  • multiple data series drawn on the same axes.

subplot() instead creates multiple standalone plots inside one figure. This is useful when overlaying all series would hide individual patterns or create clutter.

6. Syntax and matrix logic

plt.subplot(rows, columns, index)
  • First argument: number of rows.
  • Second argument: number of columns.
  • Third argument: the selected cell/position.

Compact notation is also valid:

plt.subplot(231)

This means 2 rows, 3 columns, position 1.

Numbering rule

Positions are numbered left to right across the first row, then left to right across each following row.

For a 2 × 3 layout:

+-----------+-----------+-----------+
|     1     |     2     |     3     |
+-----------+-----------+-----------+
|     4     |     5     |     6     |
+-----------+-----------+-----------+

Examples:

  • subplot(2, 3, 1) → top-left.
  • subplot(2, 3, 3) → top-right.
  • subplot(2, 3, 4) → bottom-left.
  • subplot(3, 3, 2) → first row, second column.
  • subplot(3, 3, ...) creates nine total cells.

7. Figure size and rcParams

Two ideas must be distinguished:

Setting an individual figure size

plt.figure(figsize=(12, 8))

This sizes the figure explicitly.

Setting the default size for future figures

plt.rcParams["figure.figsize"] = (12, 8)

rcParams is Matplotlib’s configuration dictionary. This assignment sets the default size of figures created afterward in the session.

Important behavior:

  • it controls the overall figure canvas, not each subplot independently;
  • individual subplots scale to fit within that canvas;
  • it affects new figures, not figures that already exist;
  • it changes presentation dimensions, not underlying data or mathematical curve shape.

With a 12 × 8 figure, a 2 × 3 grid is relatively wide. With an 8 × 12 figure, a 3 × 2 grid is relatively tall.

8. Data generation and list comprehension

The lesson generates X-values using NumPy and transformations using Python/NumPy:

import matplotlib.pyplot as plt
import numpy as np
import math

plt.rcParams["figure.figsize"] = (12, 8)

x_values = np.linspace(0, 20, 20)
y1_values = [math.sqrt(i) for i in x_values]
y2_values = [i**3 for i in x_values]

np.linspace(0, 20, 20) produces 20 evenly spaced values from 0 through 20. It does not mean a step size of 20; the transcript’s wording on that point is imprecise.

[math.sqrt(i) for i in x_values]

is a list comprehension. It applies math.sqrt() to every X-value and creates a new list. The instructor notes that a for loop could do the same work, but list comprehension expresses it efficiently in one line.

9. Worked example: 2 × 3 matrix

The first row contains square-root plots; the second contains cubic plots. Each cell can receive its own data and color.

plt.subplot(2, 3, 1)
plt.plot(x_values, y1_values, color="blue")

plt.subplot(2, 3, 2)
plt.plot(x_values, y1_values, color="red")

plt.subplot(2, 3, 3)
plt.plot(x_values, y1_values, color="green")

plt.subplot(2, 3, 4)
plt.plot(x_values, y2_values, color="green")

plt.subplot(2, 3, 5)
plt.plot(x_values, y2_values, color="blue")

plt.subplot(2, 3, 6)
plt.plot(x_values, y2_values, color="red")

plt.show()

The exact color sequence is less important than the principle: after selecting a cell with subplot(), subsequent plot settings apply to that cell.

10. Worked example: 3 × 2 matrix

The second demonstration uses:

  • row 1: square root of X;
  • row 2: square of X;
  • row 3: cube of X.
plt.rcParams["figure.figsize"] = (8, 12)

x_values = np.linspace(0, 20, 20)
y1_values = [math.sqrt(i) for i in x_values]
y2_values = [i**2 for i in x_values]
y3_values = [i**3 for i in x_values]

series = [y1_values, y1_values, y2_values,
          y2_values, y3_values, y3_values]
colors = ["blue", "red", "green", "green", "blue", "red"]

for position, (values, color) in enumerate(zip(series, colors), start=1):
    plt.subplot(3, 2, position)
    plt.plot(x_values, values, color=color)

plt.show()

Each cell may also receive its own:

  • title;
  • X- and Y-values;
  • color;
  • marker and line style;
  • axis labels or limits.

11. Comparing square-root and cubic growth

For nonnegative X:

  • sqrt(x) rises relatively quickly near zero and then its growth slows; the curve flattens.
  • x**3 grows increasingly rapidly.
  • Therefore, as X increases, the gap between x**3 and sqrt(x) increases.

Examples:

x √x x³
1 1 1
2 1.414 8
3 1.732 27

Part III — Matplotlib Object-Oriented Approach

13. State-based versus object-oriented plotting

State-based pyplot style

plt.plot(x, y)
plt.title("Sine Wave")

This style operates through Matplotlib’s current/global plotting state.

Object-oriented style

fig, ax = plt.subplots()
ax.plot(x, y)
ax.set_title("Sine Wave")

This explicitly creates and manipulates objects:

  • fig: the whole Figure or canvas;
  • ax: an Axes object, the individual plotting area.

An object encapsulates an entity together with its data and methods. Here, the figure and axes objects expose methods for configuring the plot.

14. Advantages of the OO approach

  1. Better structure and scalability — figures and their related axes are separate objects, which makes complex figures and multiple subplots easier to manage.
  2. Precise control — ticks, labels, grids, titles, limits, and other properties can be changed for one axes without unintentionally changing the whole figure.
  3. Avoidance of global-state issues — pyplot settings may cause unintended changes when several plots exist; explicit objects reduce ambiguity.
  4. Readability and maintainability — explicit references make code easier to understand, debug, and maintain.

15. Worked example: sine wave

import matplotlib.pyplot as plt
import numpy as np

x = np.linspace(0, 10, 1000)
y = np.sin(x)

fig, ax = plt.subplots()

ax.set_title("Sine Wave")
ax.set_xlabel("Time")
ax.set_ylabel("Amplitude")
ax.grid(True)

ax.plot(x, y, label="Sine Curve", color="green")
ax.legend()

plt.show()

Here all axes-specific settings are called through ax:

  • ax.set_title();
  • ax.set_xlabel();
  • ax.set_ylabel();
  • ax.grid(True);
  • ax.plot();
  • ax.legend().

16. Independent axes customization

fig, axes = plt.subplots(1, 3)

axes[0].plot(x, y, color="red", marker="o")
axes[0].set_ylim(0, 5)

axes[1].plot(x, y, color="blue", marker="x")
axes[1].set_ylim(0, 10)

Individual axes can have different colors, markers, titles, grid settings, and limits. These changes affect presentation, not the X- or Y-data.

17. Saving a figure

Use the Figure object’s savefig() method:

fig.savefig("waves.jpg")

or a full path:

fig.savefig("D:/Data Visualization/waves.jpg")

The instructor demonstrates saving the sine-wave plot as waves.jpg in a local folder and then verifies that the file exists and opens correctly. The same method can save PNG and other supported image formats; the extension usually determines the format.

On Windows, forward slashes are convenient. Alternatives include a raw string such as r"D:\Data Visualization\waves.jpg" or escaped backslashes. The entire path must be quoted because it is a Python string.

Likely exam distinction:

  • axes methods configure an individual plotting area;
  • fig.savefig() saves the entire figure.

Part IV — Introduction to Seaborn

18. Definition and relationship to Matplotlib

Seaborn is a powerful Python visualization library built on top of Matplotlib. It is designed to make statistical graphics informative, attractive, and relatively easy to create.

It is widely used for:

  • data exploration;
  • statistical visualization;
  • trends, relationships, and distributions;
  • concise, high-level plotting with attractive defaults.

Seaborn does not replace Matplotlib. A Seaborn plot still creates Matplotlib Figure/Axes objects, so Matplotlib can be used afterward for detailed titles, annotations, ticks, axis control, and layout adjustments.

19. Key features

  1. Attractive default styles — aesthetically pleasing output without extensive customization.
  2. Built-in statistical plots — distribution, regression, and categorical plot types are readily available.
  3. Pandas integration — column names from DataFrames can be mapped directly to plot roles.
  4. Automatic data mapping — variables are mapped to visual elements such as X, Y, color/hue, row, and column.
  5. Themes and palettes — multiple themes and palettes support different presentation styles.
  6. High-level interface — complex statistical graphics can often be produced with short function calls.

Common functions mentioned:

  • histplot() — histogram/distribution;
  • scatterplot() — relationship between two variables;
  • boxplot() — quartiles, median, spread, and outliers;
  • heatmap();
  • violinplot();
  • barplot();
  • catplot().

20. Installation and imports

In a Jupyter cell:

!pip install seaborn

The exclamation mark sends the command to the system shell from the notebook. If already installed, the output may say “Requirement already satisfied.” Installing Seaborn normally installs or checks required dependencies, including Matplotlib and pandas.

Standard imports:

import matplotlib.pyplot as plt
import seaborn as sns

Preferred Matplotlib import:

import matplotlib.pyplot as plt

Avoid wildcard imports such as:

from matplotlib.pyplot import *

because they clutter the global namespace, create possible naming conflicts, reduce readability, and complicate debugging.

21. Seaborn barplot()

barplot() is used to plot a categorical variable against a numerical variable. Principal arguments discussed are:

  • x: categorical variable;
  • y: numerical variable;
  • data: DataFrame;
  • hue: additional category used to split/group each X-category;
  • palette: color palette;
  • width: bar width;
  • error-bar configuration;
  • hue_order: explicit order of hue categories.

By default, a Seaborn bar plot represents an aggregate estimate (commonly the mean) for each category and may show uncertainty/error bars depending on the Seaborn version and settings.

22. Worked example: Titanic passenger class and age

Load and inspect the dataset

import matplotlib.pyplot as plt
import seaborn as sns

titanic_data = sns.load_dataset("titanic")
titanic_data.head()

Inspecting head() reveals the first five rows and column names such as:

  • survived, pclass, sex, age, sibsp, parch, fare, embarked, who, adult_male, deck, and others.

The columns of primary interest are:

  • pclass: passenger class;
  • age: passenger age;
  • later, sex: subgrouping variable.

Basic plot

sns.barplot(x="pclass", y="age", data=titanic_data)
plt.show()

Interpretation described in the lesson:

  • first-class mean age is roughly between 35 and 40;
  • second-class mean age is around 30;
  • third-class mean age is around 25;
  • the average passenger age therefore declines from first to third class.

Different colors by class

To assign separate colors, map pclass to hue and choose a palette:

sns.barplot(
    x="pclass",
    y="age",
    data=titanic_data,
    hue="pclass",
    palette="pastel"
)

Built-in palette examples mentioned:

  • pastel;
  • bright;
  • muted;
  • dark.

Custom colors are also possible. Documentation can be consulted for the available palette choices.

Grouped/clustered bar plot by sex

sns.barplot(
    x="pclass",
    y="age",
    data=titanic_data,
    hue="sex",
    palette="pastel",
    hue_order=["male", "female"]
)

This divides each passenger-class category into male and female bars. hue_order forces male to appear first and female second.

The lesson’s conclusion is that the broad pattern remains similar across sex: first-class passengers are older on average and third-class passengers younger.

Interpretation caution: Bar height here represents average age, not the number of passengers. The transcript occasionally says “number of males,” but the Y-variable is age; therefore, it is the mean age for each sex/class group.

23. Role of hue

hue maps another variable to color and creates subgroups within the main X-category. It is the key argument for grouped or clustered bar plots in this example.

Uses:

  • compare male and female average age within each passenger class;
  • compare regions within product categories;
  • compare customer segments within months.

Changing palette, marker, or color changes appearance, not the data.

Part V — Seaborn catplot() and Categorical Data

24. Definition

catplot() is a figure-level Seaborn function for visualizing categorical data. It offers a flexible interface for producing different categorical plot types, including:

  • bar plots;
  • box plots;
  • violin plots;
  • other categorical plot variants selected through kind.

25. Figure-level versus axes-level functions

Feature Figure-level function (catplot) Axes-level function (barplot)
Scope Creates and manages its own complete figure Draws directly on a Matplotlib Axes
Multiple panels Supports them automatically through faceting Requires axes/subplot management for multiple panels
Common parameters row, col, hue, kind x, y, hue, data, etc.
Typical use Multi-panel categorical comparisons One categorical plot on a chosen axes

The transcript calls axes-level functions “access-level” due to transcription error.

26. Key catplot() capabilities

  1. Works directly with categorical variables.
  2. Supports faceting—creating multiple subplots—using row and col.
  3. Supports grouping through hue.
  4. Supports multiple plot types through kind.
  5. Automatically handles the full figure and multiple panels.

27. Worked example: Tips dataset

Load and inspect

import matplotlib.pyplot as plt
import seaborn as sns

tips = sns.load_dataset("tips")
tips.head()

Relevant columns include:

  • total_bill — numerical bill value;
  • tip;
  • sex — Male/Female;
  • day — Thursday, Friday, Saturday, Sunday;
  • time — Lunch/Dinner.

Faceted grouped bar plot

sns.catplot(
    data=tips,
    x="day",
    y="total_bill",
    hue="sex",
    col="time",
    kind="bar"
)

Role of each argument:

  • x="day": days on the horizontal axis;
  • y="total_bill": numerical response;
  • data=tips: source DataFrame;
  • hue="sex": separate male and female groups by color;
  • col="time": create separate panels for Lunch and Dinner;
  • kind="bar": use bar plots.

The result contains two panels automatically:

  • left panel: Lunch;
  • right panel: Dinner;
  • within each day/panel, colors split the values by sex.

Interpretation caution: As with barplot(), the bars generally display an aggregate estimate such as the mean total_bill, not the literal sum of all bills, unless an explicit estimator or pre-aggregation changes that behavior. “Total bill” is the column name.

Part VI — Distribution Charts and Visualization Choices

29. Box plots

A box plot is appropriate when an analyst must compare distributions—such as fares across passenger classes—while avoiding display of every individual observation.

It summarizes:

  • median: middle value;
  • quartiles: boundaries of the middle portion of the data;
  • box / IQR: middle 50% of values;
  • whiskers: the typical non-outlier range under the plot’s convention;
  • outliers: unusually distant values plotted separately.

Why side-by-side box plots fit the passenger-fare problem:

  • compare several classes;
  • show typical value and spread;
  • reveal unusual values;
  • do not require exposing or labeling each fare.

A dot plot is less appropriate under those requirements because it shows individual observations and can become cluttered with large datasets.

30. Violin plots

A violin plot combines:

  • box-plot-like summary information;
  • a density estimate showing distribution shape.

It helps compare:

  • spread;
  • concentration/density;
  • shape and possible multimodality;
  • typical/median tendencies;
  • subgroups, such as passenger age by class and gender.

Color can encode gender or another subgroup. A violin plot does not necessarily show the exact value of every observation unless points are added separately.

31. Scatter-plot markers

sns.scatterplot(data=df, x="age", y="fare", marker="x")

marker changes point shape only. Common examples:

Code Shape
o circle
x cross
s square
^ triangle
* star

It does not move points, change values, delete observations, or alter the underlying dataset.

32. Chart choice by analytical goal

Goal Suitable chart
Compare distributions Box plot or violin plot
Show relationship between two numerical variables Scatter plot
Compare multiple independent views Subplots/facets
Show individual observations Dot/strip/scatter plot
Show cumulative components over time Stacked area plot
Compare category-level estimates Bar plot

Part VII — Case Study: Stellar Analytics

33. Scenario

Priya, an analyst at Stellar Analytics, must compare growth curves created by transforming time data. She generates linearly spaced X-values from 0 to 20 and computes square roots. The objective is to understand how growth changes and identify nonlinear trends.

She chooses a 12 × 8 figure and initially arranges plots in a 2 × 3 grid. The first three cells use indices 1, 2, and 3, leaving cells 4–6 for other transformations.

Visual styles include:

Style Meaning
bo- blue, circle markers, solid line
rx- red, cross markers, solid line
g*- green, star markers, solid line

The case mentions a red-cross dashed line in one sentence, but the literal format string rx- uses a solid line. A dashed version would require rx--.

Stakeholders:

Person Role Priority
Priya Analyst complete and correct comparison of patterns
Leo UX designer consistent labels, spacing, palette, print/screen readability
Zara Product manager high-level summary without overwhelming stakeholders

34. Why multiple visual encodings matter

Do not rely only on color because:

  • grayscale printing may remove distinctions;
  • screens and projectors differ;
  • viewers may have color-vision deficiencies.

Combine color, marker, and line style. This improves robustness and accessibility without changing the underlying values.

35. Evaluating the options

Option A — Complete the 2 × 3 grid

Add three transformations to panels 4–6.

Advantages:

  • maximum completeness;
  • every transformation visible;
  • valuable for technical exploration.

Disadvantages:

  • six panels may be dense;
  • each panel is smaller;
  • executive audiences may be overwhelmed.

Best use: internal analysis or appendix.

Option B — Switch to a focused 2 × 2 grid

Show only the four most important curves.

Advantages:

  • larger, clearer panels;
  • more readable labels;
  • easier presentation and storytelling;
  • lower cognitive load.

Disadvantage: some transformations are omitted from the main view.

Best use: executive presentation.

Option C — Overlay all curves on one axes

Advantages:

  • compact;
  • direct comparison on common axes.

Disadvantages:

  • overlap can hide individual shapes;
  • colors and legends become difficult to track;
  • clutter increases with each series.

Best use: only when there are few clearly distinguishable curves and direct comparison is paramount.

36. Recommended answer

Use a dual-artifact strategy:

  1. During exploration, use the complete 2 × 3 grid to inspect all transformations.
  2. Select the most decision-relevant curves.
  3. For Zara’s presentation, use a 2 × 2 grid with consistent labels, spacing, colors, markers, and line styles.
  4. Retain the full 2 × 3 view in an appendix or supporting analysis.

This balances analytical depth, UX readability, and executive clarity.

Core design lesson: the best visualization is not necessarily the one containing the most information; it is the one that communicates the right information effectively to its intended audience.

Part VIII — Live Session: Table Design Review

37. Tables as visualization

Visualization is not limited to graphs and pictures. Tables are also visual/graphic mechanisms for communicating data.

Use a table when the audience needs to examine individual data points, row by row or column by column. Charts are often better for patterns; tables are especially strong for precise lookup.

38. Guiding reading direction with spacing

The instructor strongly emphasizes that visualization designers must control audience attention: viewers should notice and interpret what the designer intends.

This applies the Gestalt principle of proximity: items placed near one another are perceived as a group.

To force row-wise reading

  • make horizontal gaps between columns relatively small, so items within a row feel grouped;
  • make vertical gaps between rows relatively large, so each row is separated from the next group.

To force column-wise reading

  • make vertical gaps between rows relatively small, so values down a column feel grouped;
  • make horizontal gaps between columns relatively large, so each column appears as a separate group.

This is not merely decoration: spacing determines grouping, reading direction, attention, and interpretation.

39. Best practices for tables

39.1 Offset the header from the body

The header explains how to interpret each column and must stand out using suitable pre-attentive attributes. It should be noticed before the body.

Use informative labels. Prefer “Student Name” over merely “Name” where ambiguity exists; similarly specify student roll number or marks in Mathematics, Physics, Chemistry, and Biology.

39.2 Put informative titles at the top

The eye typically begins near the top-left. Put the most important interpretive information there.

Titles should say what is shown, not merely name a broad topic. Prefer:

  • “Product-wise Profitability” over “Profitability”;
  • “Sector-wise GDP” or “Comparative GDP” over “GDP.”

If explanatory information is placed only below a visual, viewers may become confused or lose interest before finding it.

39.3 Use gridlines judiciously

Every line, color, and pixel demands some cognitive processing. More visual elements increase cognitive load; excessive load tires the audience, reduces interest, and can cause disengagement.

Ask whether each gridline is necessary. In a table, full crisscross borders around every cell can be irritating and heavy. White space often separates groups adequately.

The same logic applies to charts: if values are printed directly above bars, a vertical scale and gridlines may become redundant. Retain only what genuinely helps interpretation.

39.4 Align numbers and text properly

  • right-align numerical values;
  • left-align text;
  • align headers consistently with the data beneath them.

Right alignment makes place values and magnitudes easier to compare. The instructor explains that number magnitude is recognized from units, tens, hundreds, thousands, and so on, making a shared right edge useful.

39.5 Highlight outliers carefully

Use a different color or other restrained emphasis for values that do not follow the general pattern. The goal is to signal “this is unusual; note it,” not to make the outlier overwhelm all other information.

39.6 Avoid unit repetition

If every value in a column is in rupees, put the unit/symbol in the header instead of repeating it in every cell. This reduces clutter.

39.7 Use meaningful precision

Do not display unnecessary decimals. Round to the nearest meaningful digit or decimal place. Several decimal places may matter for very small values, but are often meaningless beside a large whole-number magnitude.

39.8 Group similar items and remove repetition

Keep related rows together—for example, all Mechanical Department records, then all Operations records—with white space between groups. A merged/group label can prevent writing “Mechanical” or “Operations” repeatedly in every row.

39.9 Add small visualizations when useful

Small in-cell visualizations such as sparklines can be added when they genuinely help readers perceive a trend. Their use must still be appropriate and uncluttered.

40. Instructor emphasis on visual economy

The instructor criticizes overly decorative AI-generated visuals that add lines, colors, pictures, and other noise. The principle is:

Every line and pixel should be justifiable.

Visual attractiveness is not the same as professional clarity. Remove elements that consume attention without adding meaning.

Part X — Python and Jupyter Notebook Setup

44. Why Jupyter Notebook is used

Jupyter Notebook combines in one file:

  • explanatory text/notes;
  • executable code;
  • visible output and charts.

Therefore, a teacher or analyst need not distribute separate notes and a separate coding platform. Recipients can read the explanation, execute the code, and inspect results in one place.

Download Anaconda and follow its installer. It can install Jupyter Notebook and necessary dependencies together. The instructor describes this as the easiest and most straightforward option.

Route B — Python and pip

  1. Download a recent stable Python version from python.org.
  2. During installation, select Add Python to PATH.
  3. Verify installation in Command Prompt:

  1. Verify pip:

  1. Use pip to install Jupyter Notebook if needed.

Why PATH matters

Adding Python to the environment PATH tells the operating system where the Python executable is located. Users can type python without specifying its full installation path.

The instructor accepts other tools such as VS Code, PyCharm, IPython, or JupyterLab, but recommends having classic Jupyter Notebook because class demonstrations and shared notebooks use it.

46. Launching Jupyter Notebook

In Command Prompt:

jupyter notebook

Expected behavior:

  1. A terminal/command window opens and displays server log messages.
  2. The default browser opens the Jupyter interface.
  3. Jupyter looks like a website, but the notebook server is normally running on the user’s own computer rather than on a remote website.
  4. The log indicates the local directory from which notebooks are served and a local port, commonly 8888.

47. Kernel/server and browser relationship

The instructor uses “kernel” broadly for the background engine. The key conceptual model is:

  • the browser is the visible front end;
  • the local notebook server serves the web interface and files;
  • the kernel executes code and returns results;
  • the browser displays those results.

Do not close the background terminal/server while using the notebook. It can be minimized, but closing it stops the local service and makes the browser notebook cease functioning.

Users normally interact with the browser notebook, not by typing code into the server log window.

Part XI — Jupyter Notebook Interface and Cells

48. Notebook interface

Students are encouraged to create/open a notebook and explore menus such as:

  • File;
  • Edit;
  • View;
  • Run;
  • Kernel;
  • Settings;
  • Help.

The central unit of interaction is a cell.

49. Three cell types

Code cell

  • contains executable Python code;
  • sends code to the kernel;
  • shows output beneath the cell;
  • has an execution indicator such as [1] on the left.

Example:

x = "Santhosh"
y = "Raju"
print(x, y)

Strings must be placed in quotes. The output is Santhosh Raju.

Execution counts reveal order. [1] means the cell was the first execution in that kernel session. Running cells out of logical order may create errors—for example, using a variable before the defining cell has run.

An asterisk [*] means the cell is still executing.

Markdown cell

  • contains formatted explanatory text rather than executable Python;
  • can create headings and narrative notes;
  • does not show the code-cell execution bracket.

Examples:

# Introduction to Jupyter Notebook
## Basics of the User Interface

One # creates a level-one heading; two create a level-two heading. Executing the Markdown cell renders the formatting.

Raw cell

  • preserves entered material without Markdown rendering;
  • does not execute it through the kernel;
  • is useful when content must remain unformatted/unprocessed.

Part XII — Integrated Comparisons and Exam Traps

53. Matplotlib versus Seaborn

Aspect Matplotlib Seaborn
Level foundational/general plotting library high-level statistical visualization library built on Matplotlib
Strength precise control, annotation, axes/layout customization attractive defaults, statistical plots, DataFrame mapping
DataFrame support possible but more manual direct and convenient
Best combined use customize figures/axes create statistical plot quickly

Strong workflow:

  1. Use Seaborn for efficient statistical visualization and attractive defaults.
  2. Use Matplotlib for precise refinement, annotations, ticks, titles, and layout.

It is a mistake to stop using Matplotlib after adopting Seaborn, because doing so gives up fine-grained control that remains fully compatible with Seaborn plots.

54. subplot() versus subplots()

  • plt.subplot(r, c, i) selects one cell in a grid using pyplot’s stateful interface.
  • plt.subplots(...) creates a Figure and one or more Axes objects and is central to the OO interface.

Example:

fig, axes = plt.subplots(2, 3, figsize=(12, 8))
axes[0, 0].plot(x, y)

55. Appearance versus data

Changing any of the following changes visual encoding but not observations:

  • color;
  • marker;
  • line style;
  • palette;
  • axis limits;
  • figure size.

However, axis limits can hide part of the displayed range, so they may alter perception even though the stored data remains unchanged.

56. Frequent mistakes to avoid

  1. Treating np.linspace(0, 20, 20) as a step of 20; it means 20 evenly spaced samples.
  2. Saying alpha=100 is the valid opaque setting; use alpha=1.
  3. Reordering stacked data but not labels/colors.
  4. Confusing an average-age bar with passenger count.
  5. Assuming total_bill bars necessarily show the sum; default barplot behavior is an estimate such as the mean.
  6. Calling barplot() figure-level; it is axes-level.
  7. Calling catplot() axes-level; it is figure-level.
  8. Believing Seaborn prevents Matplotlib customization.
  9. Assuming marker/color changes data.
  10. Using rx- while describing a dashed line; - is solid and -- is dashed.
  11. Using excessive gridlines, borders, colors, or decoration.
  12. Showing every plot to an executive audience when a focused selection would communicate better.

Rapid Revision and Exam Checklist

Definitions to memorize

  • Stacked area plot: multiple numerical series filled and stacked to show cumulative composition, often over time.
  • Subplot: an individual plotting area placed within a matrix/grid in one figure.
  • Figure: the complete Matplotlib canvas.
  • Axes: an individual plot area inside a figure.
  • Seaborn: a statistical visualization library built on Matplotlib.
  • Axes-level function: draws on a particular Matplotlib Axes; example: sns.barplot().
  • Figure-level function: creates/manages its full figure and can facet automatically; example: sns.catplot().
  • Hue: mapping of an additional grouping variable to color.
  • Faceting: splitting data into multiple panels by row or column categories.
  • Box plot: summary of median, quartiles, spread, whiskers, and outliers.
  • Violin plot: distribution plot combining density shape with box-plot-like summary information.
  • Kernel: computational process that executes notebook code.
  • Markdown cell: rendered text/documentation cell.
  • Raw cell: unexecuted, unrendered content cell.
  • Gestalt proximity: nearby items are perceived as belonging to one group.

Review-Week Augmentation

Implementing perceptually consistent multi-panel figures

The review adds no new Matplotlib syntax, but it sharpens implementation choices:

  • Preserve the same semantic colour, marker meaning, units, and scale logic for a metric across subplots. Independent axes customization must not silently change meaning.
  • Use proximity to place related panels together, alignment to create order, and continuity to guide a left-to-right/top-to-bottom analytical sequence.
  • Keep typography, spacing, title style, label precision, and legend strategy consistent across panels.
  • Split an overloaded overlay into subplots or small multiples when doing so reduces occlusion and cognitive load; do not fragment a coherent comparison unnecessarily.
  • Use restrained gridlines/backgrounds so the data form the figure and interface decoration remains ground.

Practical validation

After code runs, inspect the rendered output: Are labels overlapping? Does one panel dominate accidentally? Are comparable axes truly comparable? Is a category’s colour stable? Can the intended reading sequence be understood without explanation? Tool correctness is not visualization correctness.
