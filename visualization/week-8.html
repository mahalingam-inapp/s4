1. Major Python Data-Visualization Libraries

Week 8 introduces five major libraries: Matplotlib, Seaborn, Cartopy, Pandas, and Plotly.

1.1 Matplotlib

Matplotlib is the de facto standard for static visualization in Python. It is one of Python’s oldest, most widely used, and most popular visualization libraries. It was developed to resemble MATLAB, a language widely used in academia.

Key capabilities:

  • Creates static, interactive, and animated visualizations.
  • Supports line graphs, scatter plots, histograms, bar charts, pie charts, and many other plots.
  • Is highly customizable: color, fonts, axes, labels, titles, markers, line styles, legends, and other elements can be adjusted.
  • Can produce publication-quality figures.
  • Is simple and versatile.
  • Integrates well with NumPy and Pandas, making data from different sources easy to visualize.
  • Supports multiple backends, so figures can be displayed on different platforms and saved in different formats.

1.2 Seaborn

Seaborn is a powerful visualization library built on top of Matplotlib. It specializes in attractive, informative statistical graphics with relatively little code.

Key capabilities:

  • Provides high-level abstractions for complex plots.
  • Supports heat maps, violin plots, and clustered pair plots/pair plots.
  • Handles Pandas DataFrames seamlessly.
  • Makes relationships among variables straightforward to plot.
  • Offers themes, color palettes, and easy customization of chart elements.
  • Is especially useful in exploratory data analysis (EDA) for finding patterns, trends, and correlations.

1.3 Cartopy

Cartopy is designed for geospatial visualization and map-based plotting. It is widely used in scientific and academic work.

Key capabilities:

  • Builds on Matplotlib and extends it for geospatial data.
  • Supports map projections such as Mercator, Robinson, and Albers Equal Area.
  • Draws geographic boundaries, coastlines, borders, and gridlines.
  • Supports customizable overlays, including data points, heat maps, and vector data on base maps.
  • Works with libraries such as Shapely and Fiona for efficient geospatial-data manipulation.
  • Is regarded as a more modern and versatile alternative to the older Basemap package, which has been deprecated.
  • Produces professional-quality geographic visualizations.

1.4 Pandas

Pandas is primarily a library for data manipulation and analysis, but it is also a powerful visualization tool, especially when paired with Matplotlib or Seaborn.

Key capabilities:

  • Plots directly from a DataFrame or Series using the .plot() method.
  • Supports line plots, bar plots, histograms, scatter plots, and pie charts.
  • Removes much of the manual preparation normally needed to configure data for a chart.
  • Automatically uses a DataFrame’s index on the x-axis, simplifying axis handling.
  • Combines strong grouping and aggregation operations with immediate plotting of summaries.
  • Supports customization of colors, styles, titles, axis labels, and other elements through .plot() arguments.
  • Works with Matplotlib for more complex visualization and with Seaborn for enhanced statistical graphics.

1.5 Plotly

Plotly is a robust library for interactive, web-based visualization. Its charts are dynamic, visually polished, shareable online, and embeddable in applications.

Key capabilities:

  • Supports line, scatter, bar, box, heat-map, and 3D plots.
  • Allows users to hover, zoom, pan, and export from the chart interface.
  • Supports advanced charts such as geographic maps, choropleth maps, and financial charts.
  • Works with Python, Pandas, and Jupyter Notebook.
  • Allows extensive customization of colors, themes, styles, titles, and labels.
  • Exports plots as static images or HTML files for web presentations and platforms.
  • Is popular among analysts, data scientists, and developers when polished interactivity is required.

1.6 Library Comparison

Library Primary strength Best suited to
Matplotlib Foundational, highly customizable plotting General-purpose/static and publication-quality figures
Seaborn High-level statistical graphics EDA, correlations, distributions, attractive defaults
Cartopy Geospatial plotting and projections Maps, geographic boundaries, overlays
Pandas Direct plotting from tabular data Quick plots during manipulation, grouping, and aggregation
Plotly Interactive web graphics Dashboards, online sharing, hover/zoom/pan, advanced interactive charts

Likely exam comparison: Seaborn and Cartopy both extend Matplotlib, but Seaborn focuses on statistical graphics while Cartopy focuses on geospatial graphics. Pandas prioritizes convenient DataFrame/Series plotting; Plotly prioritizes interactivity.

2. Matplotlib and Jupyter Notebook Setup

Matplotlib is not part of the core Python library and must be installed separately.

2.1 Install Matplotlib in Jupyter

!pip install matplotlib

The leading ! tells Jupyter to run the line as a terminal/shell command. Installation may take time and print many messages; successful completion is indicated by an installation-success message.

2.2 Import Pyplot

import matplotlib.pyplot as plt

pyplot is conventionally given the shorter alias plt.

For the notebook-oriented workflow shown in the lecture:

%matplotlib inline

This IPython magic directs plots to appear inside the Jupyter Notebook. Modern notebook environments often display plots inline automatically, but this was an explicit lecture step.

2.3 Notebook Execution Caveat

If a cell depends on imports or variables defined in earlier cells, those earlier cells must have been executed. Otherwise, repeat the import in the current cell or run the notebook from the start. plt.show() explicitly renders the prepared chart.

3. Line Charts with Matplotlib

3.1 Purpose and Basic Procedure

A line chart is useful for showing ordered change, especially change over time.

The lecture example plots years on the x-axis and nominal GDP on the y-axis:

years = [1950, 1960, 1970, 1980, 1990, 2000, 2010, 2020]
gdp = [300.2, 543.5, 1035.5, 2890.3, 5240.9, 10700.3, 14560.1, 20670.3]

plt.plot(years, gdp)
plt.show()

The essential call is plt.plot(x_values, y_values). The x- and y-lists must contain matching numbers of observations.

3.2 Improving Aesthetics and Readability

plt.plot(
    years,
    gdp,
    color="green",
    marker="o",
    linestyle="solid"
)
plt.title("Nominal GDP from 1950 to 2020")
plt.xlabel("Years")
plt.ylabel("GDP")
plt.show()

Important components:

  • color changes the line color.
  • marker="o" marks observations with circles.
  • linestyle="solid" controls the line pattern.
  • title, xlabel, and ylabel provide context and improve readability.

Syntax warning: Python’s keyword is color, not British colour. Opening and closing quotes must match, values must be valid Python values, and brackets must be closed.

3.3 Multiple Lines on One Plot

To compare two countries, call plt.plot() once for each series:

gdp_b = [310, 354, 510, 1030, 2000, 4150, 7500, 10350, 14340]

plt.title("GDP Comparison")
plt.ylabel("GDP")

plt.plot(years, gdp, color="blue", marker="o",
         linestyle="solid", label="A")
plt.plot(years, gdp_b, color="red", marker="s",
         linestyle="solid", label="B")

plt.legend(loc="upper left")
plt.show()

The transcript’s second list appears to contain a data-count inconsistency; in actual code, both y-series must match the length of years.

Marker examples:

  • "o": circle
  • "s": square
  • "+": plus
  • "x": cross

label names the plotted series; plt.legend() displays those names. Place a legend where it does not cover important data, such as loc="upper left" when that area is open.

3.4 Annotation

Annotations direct attention and strengthen the intended message. Conceptually, an annotation needs:

  1. The annotation text.
  2. xy: the coordinate of the data point being referenced.
  3. xytext: the coordinate where the text should appear.
plt.annotate(
    "Country B in 2020",
    xy=(2020, 14340),
    xytext=(1970, 17500)
)

Positioning often requires trial and error. Lowering the y-value in xytext moves the annotation text downward.

To add an arrow:

plt.annotate(
    "Country B in 2020",
    xy=(2020, 14340),
    xytext=(1970, 17500),
    arrowprops={"color": "black", "width": 0.5, "headwidth": 5}
)

arrowprops receives a dictionary and can control arrow color, line width, and head width. The arrow points to xy, not to xytext.

4. Bar Charts

4.1 Definition and Data Mapping

A bar chart compares magnitudes across categories. For a vertical bar chart:

  • x-axis: categorical values/bar positions
  • y-axis: corresponding aggregated numerical values/bar heights

Use plt.bar() for vertical bars and plt.barh() for horizontal bars.

4.2 Important plt.bar() Arguments

Argument Meaning
x x-coordinates/categories of bars
height heights of vertical bars
width width of bars; lecture gives default as 0.8
color fill color
edgecolor outline color
linewidth thickness of bar outlines
align alignment to x position: "center" (default) or "edge"
label series name used by the legend
alpha transparency: 0 fully transparent, 1 fully opaque
hatch interior pattern, such as /, \\, o, or x
bottom starting position of bars on the y-axis
log when True, uses a logarithmic scale

4.3 Simple Vertical Bar Chart

Lecture data:

  • Annie Hall: 5 Oscars
  • Ben-Hur: 11
  • Casablanca: 3
  • Gandhi: 8
  • West Side Story: 10
movies = ["Annie Hall", "Ben-Hur", "Casablanca", "Gandhi", "West Side Story"]
num_oscars = [5, 11, 3, 8, 10]

plt.bar(movies, num_oscars, color="blue", edgecolor="black", width=0.5)
plt.title("My Favorite Movies")
plt.ylabel("Number of Academy Awards")
plt.show()

The height of each bar encodes the number of awards.

4.4 Grouped/Clustered Bar Chart

A clustered bar chart compares two or more series within each category. Bars need numeric offsets so that they appear side by side rather than overlap.

Procedure:

  1. Import NumPy.
  2. Use np.arange(len(categories)) to create numeric base positions.
  3. Choose a common bar width.
  4. Offset each series around each category’s base position.
  5. Reset x-ticks to the category labels.
import numpy as np
import matplotlib.pyplot as plt

years = [2023, 2024, 2025]
sales_a = [5, 6, 8]
sales_b = [7, 9, 10]
sales_c = [8, 7, 6]

x = np.arange(len(years))
width = 0.3

plt.bar(x - width, sales_a, width=width, color="green",
        edgecolor="black", alpha=0.8, label="Product A")
plt.bar(x, sales_b, width=width, color="blue",
        edgecolor="black", alpha=0.8, label="Product B")
plt.bar(x + width, sales_c, width=width, color="red",
        edgecolor="black", alpha=0.8, label="Product C")

plt.xticks(x, years)
plt.title("Sales Performance")
plt.xlabel("Years")
plt.ylabel("Sales")
plt.legend()
plt.show()

The exact offsets can vary; the core rule is that each series receives a consistent adjacent position and bars must not overlap. The instructor stressed practicing the positioning logic.

4.5 Horizontal Bar Chart

Use plt.barh(). Categories move to the y-axis and values to the x-axis.

plt.barh(movies, num_oscars, color="green", edgecolor="red")
plt.title("My Favorite Movies")
plt.show()

4.6 Avoiding Misleading Bar Charts

Because bar length represents magnitude, a bar-chart value axis should normally start at zero.

Example: Store A sales = 100; Store B sales = 105. The true difference is only 5. If the y-axis begins at 95, the visible lengths exaggerate that small difference and can falsely imply that B greatly outperforms A.

Best practice: begin the quantitative axis at zero, preserve proportional length, and avoid visual exaggeration.

4.7 What a Bar Chart Does—and Does Not—Show

If a horizontal bar for females is longer than the bar for males in a chart of average age difference, the valid conclusion is only that the female average age difference is larger. Bar length does not by itself reveal sample size, variability, or consistency.

5. Histograms

5.1 Definition and Purpose

A histogram shows the distribution of numerical data by grouping continuous values into contiguous intervals called bins. Each bar’s height represents frequency (or another specified statistic) in that interval.

Histograms reveal:

  • frequency and concentration
  • center or typical region
  • spread/range
  • shape
  • dense and empty regions
  • possible outliers or subgroups

Unlike a categorical bar chart, histogram bars normally touch because bins represent adjacent numerical ranges.

5.2 Important plt.hist() Arguments

Argument Meaning
x input dataset, such as an array or list
bins number of bins or explicit bin edges; default is 10
range lower and upper limits included in the histogram
density if True, normalizes the histogram rather than showing raw counts
cumulative if True, creates a cumulative histogram
color bar fill color
edgecolor bar-outline color
linewidth width of bin edges
alpha transparency from 0 to 1
histtype style such as bar, barstacked, step, or stepfilled
label dataset label for a legend

5.3 Lecture Example: Normally Distributed Random Data

import numpy as np
import matplotlib.pyplot as plt

data = np.random.randn(1000)  # 1,000 random values from a normal distribution

plt.hist(
    data,
    bins=20,
    range=(-3, 3),
    density=True,
    cumulative=False,
    color="skyblue",
    edgecolor="black",
    linewidth=1.2,
    alpha=0.7,
    histtype="bar",
    label="Data Distribution"
)
plt.xlabel("Value")
plt.ylabel("Density")
plt.title("Histogram Example")
plt.legend()
plt.show()

The transcript called the y-axis “frequency,” but because density=True, density is the technically precise label. Set density=False or omit it when raw frequency/count is intended.

5.4 Common Distribution Shapes

  • Approximately uniform: bars are roughly equal in height; values occur at similar frequencies and there is no strong peak.
  • Normal/bell-shaped: one central peak, approximate symmetry, and fewer values at both extremes.
  • Bimodal: two peaks, suggesting two common groups or processes.
  • Right-skewed: many smaller values and a long tail toward larger values.

5.5 Histogram vs Dot Plot

Dot plot Histogram
Shows each observation/exact value Groups observations into bins
Best for smaller datasets Scales better to larger datasets
Individual values remain identifiable Individual observations are concealed
Good when exact observations matter Good for overall distribution shape

If the requirement is to show distribution while hiding individual observations, choose a histogram.

5.6 Transforming Index-Based Data for Distribution Analysis

A plot with dataset row index on x and flight duration on y answers “How does duration vary by row?” It does not directly answer questions about typical duration, spread, or extremes.

To study the distribution:

  1. Divide durations into bins.
  2. Count flights in each bin.
  3. display those counts as a histogram.

This exposes the center, spread, and unusually short or long flights.

6. WellFit University Histogram Case Study

6.1 Scenario and Objective

WellFit University’s Health and Wellness team studies weekly step totals from 120 staff members, collected during March.

  • Maria, data analyst: focuses on statistical exploration and visualization.
  • Jamal, fitness coach: focuses on interpretable results for wellness programs.
  • Elena, program manager: focuses on decision usefulness.

Their objective is to understand walking patterns and design targeted wellness interventions.

6.2 Initial Histogram

Maria begins with 1,000-step bins:

  • 2,000–2,999
  • 3,000–3,999
  • 4,000–4,999
  • 5,000–5,999
  • 6,000–6,999
  • 7,000–7,999
  • 8,000–8,999

The highest frequency occurs in 6,000–6,999, and frequencies decline toward both ends. This resembles a bell-shaped/normal distribution with roughly symmetric tails: most staff cluster around the center and relatively few occupy the extremes.

6.3 What the Histogram Answers

  • Where do most staff fall? The modal bin/peak, here 6,000–6,999.
  • How varied are walking habits? A wider distribution indicates more variation; a narrow one indicates more consistency.
  • Are there unusual groups? A secondary peak may suggest a subgroup, but it must be validated.
  • How many observations exist? Add the heights/frequencies of all bins; the total should be 120.

6.4 Bin Width Controls Interpretation

Bin width Benefit Cost/risk Best use
500 steps Fine detail; may expose a secondary peak near 7,500 More noise, irregular fluctuations, cognitive load, false subgroups Exploration
1,000 steps Balance of detail and smoothness May still simplify subtle structure Primary communication and decisions
2,000 steps Smooth, simple overview Can merge meaningful groups and conceal structure Broad overview only

Smaller bins provide more detail but increase noise. Larger bins reduce noise but lose detail. The best histogram is not the most detailed; it is the one that best supports the analytical question and audience.

6.5 Stakeholder Positions

  • Maria favors examining 500-step bins because a secondary peak around 7,500 might reveal highly active staff or different behavioral patterns.
  • Jamal worries that too many bins will make interpretation difficult and encourage over-reading random variation.
  • Elena favors 1,000-step bins as a practical balance for intervention planning.

6.6 Recommended Analytical Strategy

  1. Establish the baseline: use the 1,000-step histogram for the main report.
  2. Explore: use a 500-step histogram to investigate the possible 7,500-step subgroup.
  3. Validate: check whether the secondary peak is stable, statistically meaningful, and connected to a genuine subgroup or program participation.
  4. Design interventions: use the validated pattern, not the visual peak alone.

Do not use 2,000-step bins as the only analysis because they may hide important wellness segments.

6.7 Caution About “Normal Distribution”

A bell-shaped histogram resembles a normal distribution, but appearance alone does not prove normality. Histogram shape changes with bin width, sample size, random variation, and outliers. Confirm normality with summary statistics, alternative bin widths, Q–Q plots, or formal statistical tests when the conclusion matters.

Likewise, a small secondary peak may be a real subgroup or random fluctuation. Do not make causal or segment claims without additional evidence.

6.8 Practical Wellness Uses

  • Staff in the central 6,000–6,999 range: maintain programs and encourage incremental improvement.
  • Low-step tail, such as 2,000–2,999: offer targeted support, reminders, or walking challenges.
  • High-step group, such as 8,000–8,999: study successful behaviors and potentially use them as examples.

6.9 Common Histogram Mistakes

  1. Too many bins: noisy, unstable, hard to interpret.
  2. Too few bins: oversimplifies and hides subgroups.
  3. Treating every peak as meaningful: visual fluctuations require validation.
  4. Ignoring the audience: analysts may need detail; decision-makers often need clarity.
  5. Declaring a distribution normal solely from its visual appearance.

7. Scatter Plots

7.1 Definition and Use

A scatter plot displays the relationship between two numerical variables as points. The lecture describes it as especially appropriate when a given x-value may have multiple y-values.

Scatter plots help reveal:

  • relationships and trends
  • correlations
  • clusters
  • outliers

They do not by themselves prove causation.

7.2 Basic Scatter Plot

Lecture scenario: number of friends versus minutes spent on a website.

import matplotlib.pyplot as plt

plt.scatter(friends, minutes)
plt.title("Minutes vs Number of Friends")
plt.xlabel("Number of Friends")
plt.ylabel("Minutes Spent on the Site")
plt.show()

The first two arguments provide x and y. Color and marker shape can distinguish observations or series.

7.3 Labeling Every Point

The lecture assigns labels A–I to nine points and uses zip() plus a for loop:

labels = ["A", "B", "C", "D", "E", "F", "G", "H", "I"]

plt.scatter(friends, minutes)

for label, friend_count, minute_count in zip(labels, friends, minutes):
    plt.annotate(
        label,
        xy=(friend_count, minute_count),
        xytext=(-15, -3),
        textcoords="offset points"
    )

plt.show()

xytext=(-15, -3) offsets each label slightly from its point; different offsets can be tried until labels remain readable and do not obscure the marks.

7.4 Multi-Series Scatter Plots

When several measurements—such as sepal width, petal length, and petal width—must each be compared with sepal length, use separate scatter series on the same axes. Distinguish them with color and marker shape, and include a legend that does not cover data.

Do not rely on color alone. A robust design could use blue circles, red squares, and green triangles. This remains interpretable in grayscale and helps people with color-vision deficiencies.

7.5 Scatter Plots for Location Decisions

If home locations form one large cluster, two smaller clusters, and a few isolated points, a single meetup location should generally be near the center of the densest/largest cluster, because that region represents the greatest concentration of users.

Caveats:

  • Isolated outliers should not dominate the decision.
  • A simple arithmetic mean can lie in an empty region between clusters and may not represent most users.
  • A spatial pattern does not explain its cause; the plot cannot prove that housing cost or another factor caused the clustering.

7.6 Curse of Dimensionality

Nearest-neighbor methods predict or classify on the assumption that nearby observations behave similarly. In low-dimensional space, distance differences can be meaningful. As features/dimensions increase:

  • distances tend to become more similar;
  • nearest and farthest points become harder to distinguish;
  • neighborhoods become unstable;
  • the identity of the “nearest” point may increasingly depend on chance.

This is the curse of dimensionality. A clear or random-looking two-dimensional scatter plot cannot prove that nearest-neighbor behavior will remain reliable in a higher-dimensional feature space.

8. Pie Charts

8.1 Construction with Matplotlib

Use plt.pie() to show parts of a whole.

sizes = [30, 20, 50]
labels = ["Category A", "Category B", "Category C"]

plt.pie(sizes, labels=labels)
plt.show()

8.2 Important plt.pie() Arguments

Argument Meaning
x values determining wedge sizes
labels text labels for wedges
autopct formatting for values/percentages inside wedges
colors custom wedge colors
explode offsets selected wedges to emphasize them
shadow adds a shadow when True
startangle angle at which the first wedge begins
wedgeprops dictionary of wedge properties
textprops dictionary of text-appearance properties
radius overall pie radius/size
counterclock direction; default is counterclockwise, False makes it clockwise

8.3 Enhanced Pie Chart

colors = ["lightblue", "lightgreen", "lightcoral"]
explode = [0, 0.1, 0]  # emphasize Category B

plt.pie(
    sizes,
    labels=labels,
    colors=colors,
    explode=explode,
    autopct="%1.1f%%",
    shadow=True,
    startangle=180
)
plt.show()

%1.1f%% displays one digit after the decimal and a literal percent sign. Thus 33.33 becomes 33.3%. explode must contain one offset per wedge; zero means no displacement. Without counterclock=False, wedges are drawn counterclockwise.

8.4 Instructor’s Critical Evaluation of Pie and Donut Charts

Although pie charts are popular and instantly familiar, the live-session instructor advised avoiding them as far as possible in analytical visualization:

  • Humans are poor at accurately comparing slice sizes.
  • It is unclear whether people judge central angle, arc length, or area.
  • Similar slices make the smallest, second largest, and fine differences difficult to identify.
  • They provide a general picture but lose nuance and precision.
  • A bar/column chart makes rankings and small differences easier to see through aligned lengths.

A pie chart can still be suitable for a broad, nontechnical audience—such as a shareholders’ AGM—when the aim is merely to show an obvious largest or smallest component and more complex charts would confuse the audience. The trade-off is loss of detail.

Exam nuance: Know both positions. Matplotlib supports pie charts and the lecture teaches their arguments, but visualization best practice often favors bar charts for accurate comparison.

9. Visualization Selection and General Design Principles

9.1 Match the Chart to the Question

Analytical question Suitable visual
Compare categories/magnitudes Bar chart
Show change over ordered time Line chart
Show relationship between numerical variables Scatter plot
Show distribution shape Histogram
Show every observation in a small dataset Dot plot
Compare multiple numerical series Multi-series line/scatter chart
Show geographic clusters Map or spatial scatter plot
Show exact value of every item Table
Show an overview/general magnitude Graph/chart

9.2 Do Not Distort Magnitude

Avoid truncated quantitative axes on bar charts and any scale manipulation that makes a small difference appear strategically large.

9.3 Use Appropriate Visual Encoding

Visualization encodes information through position, length, color, shape, line style, and markers. Position and aligned length are generally easier to compare accurately than angles or areas.

9.4 Design for Accessibility

Do not depend on a single visual channel. Multiple overlapping lines should combine color, marker, and line style—for example, solid-circle, dashed-square, and dotted-triangle. This helps when colors look similar, for color-vision deficiencies, and in grayscale printing.

9.5 Understand the Limits of a Chart

A chart may show patterns, relationships, clusters, or distributions. It cannot automatically establish causes or explain why the pattern occurred. It also cannot show measures that were not encoded: a mean bar does not reveal sample size or variability.

9.6 Reduce Cognitive Load

Effective charts make comparison immediate. Avoid designs that force the viewer to search, mentally calculate, repeatedly consult a distant legend, or decode unnecessary decoration.

10. Legends in Matplotlib

A legend maps visual elements to datasets.

plt.plot(months, revenue, label="Revenue")
plt.legend()
  • label names an individual plotted series.
  • plt.legend() displays the legend.
  • title sets the chart title, not the series name.
  • name is not the standard Matplotlib plot argument for legend entries.

Place the legend where it does not obstruct data.

11. Tables as Data Visualization

11.1 When to Use a Table

Tables are not an inferior substitute for graphs. Use a table when every individual value matters and must be available for exact lookup. Use a graph when the audience needs the overall picture, magnitude, pattern, or “feel” of the data.

The instructor stressed that tables are often neglected: people beautify graphs but assume a table is merely rows and columns. Table design deserves equal attention.

11.2 Ten Guidelines for Better Tables

1. Offset the header from the body

Make headers visibly distinct, for example through restrained shading or bold treatment. This establishes hierarchy and separates labels from data. Avoid harsh styling that overwhelms the values.

2. Use gridlines judiciously

Remove gridlines where spacing and alignment already provide structure. If lines are needed, make them subtle. Heavy internal borders draw attention away from the figures; data should remain dominant.

3. Left-align text

In left-to-right reading systems, readers naturally begin text at the left margin. Consistent left alignment gives every text item the same starting point. (The instructor noted that right-to-left languages may follow the opposite reading convention.)

4. Right-align numbers

Never center numerical columns. Right alignment aligns units, tens, hundreds, and higher place values, making numbers such as 10 and 10,000 easy to compare. The natural comparison of numerical place value proceeds from the right.

5. Align headers with their data

  • A header over a text column should be left-aligned.
  • A header over a numeric column should be right-aligned.

Centering all headers breaks the visual alignment that helps readers scan columns.

6. Use an appropriate level of precision

Do not reproduce every decimal merely because a calculator provides it. Precision must fit the purpose and measurement context.

  • A heat-exchanger area stated as approximately 10,323.2435 m² implies meaningless precision at that magnitude.
  • A book price stated as 350.235 has an irrelevant fractional part in the practical pricing context.
  • Very small quantities such as 0.025 may require several decimals because those digits carry meaning.
  • Spacecraft orientation may demand fine precision because tiny differences matter.
  • When the integer part is very large, use no decimals or at most one or two unless the context genuinely requires more.

Core principle: distinguish calculator precision from meaningful decision precision.

7. Guide reading with spacing

Whitespace implicitly directs the eye:

  • More space between columns groups entries vertically and encourages column-wise reading.
  • Less space between columns plus more space between rows groups entries horizontally and encourages row-wise reading.

Use spacing deliberately rather than explaining the reading path in words.

8. Avoid repeated units

Do not repeat %, ₹, “rupees,” or another unit in every cell. Put the unit in the column header when it applies to the entire column. This reduces clutter without removing meaning.

9. Highlight outliers and missing data

If most values lie between 1 and 10 but one value is 100, visually flag it so the reader does not miss it. Missing values should also be visibly identified.

Use preattentive attributes such as a restrained font-color change. Heavy background blocks can be too harsh and may make readers see only the outlier while ignoring the rest of the table.

10. Group similar items and add small visuals where appropriate

Place related items together—for example, countries grouped by continent—and use whitespace between groups. Avoid unnecessarily repeating group labels in every row when clear grouping conveys membership.

Small visuals such as sparklines can be placed inside cells. A sparkline is a compact line graphic that fits within a cell and summarizes the pattern or trend without requiring a full-size chart.

11.3 Table Checklist from the Instructor

  • Header clearly offset from body
  • Gridlines removed or subtle
  • Text left-aligned
  • Numbers right-aligned
  • Headers aligned with the type of data below
  • Precision appropriate to purpose
  • Spacing guides the intended reading direction
  • Units stated once in headers
  • Outliers/missing values highlighted without overpowering the table
  • Similar items grouped with whitespace
  • Small visuals added only when useful

13. High-Probability Exam Questions and Model Points

Q1. Compare Matplotlib, Seaborn, Cartopy, Pandas, and Plotly.

State each library’s focus, relationship to other libraries, plot strengths, and whether it emphasizes statistical, geospatial, DataFrame-based, foundational, or interactive visualization.

Q2. Explain how to create and customize a line plot in Matplotlib.

Mention installation/import, plt.plot(x, y), matching data lengths, color, marker, linestyle, title, axis labels, legend labels, plt.legend(), annotation, and plt.show().

Q3. Explain annotation parameters.

text is the message; xy is the referenced data point; xytext is the text position; arrowprops optionally formats an arrow. Placement may require iteration.

Q4. Distinguish bar charts and histograms.

Bar charts compare discrete categories with separated bars; histograms group continuous numerical values into contiguous bins to show a distribution. Bar height represents category magnitude; histogram height represents bin frequency/density.

Q5. Explain grouped bar-chart positioning.

Create base locations with np.arange, choose a common width, add/subtract width-based offsets for each series, and set tick labels back to the original categories. Correct positioning prevents overlap.

Q6. Discuss histogram bin-width selection using WellFit.

500-step bins provide detail but noise; 2,000-step bins provide smoothness but hide subgroups; 1,000-step bins balance clarity and detail. Use 1,000 for primary communication, 500 for exploration, and validate any apparent secondary peak.

Q7. Why should a bar chart normally start at zero?

Bar length is the magnitude encoding. A truncated axis changes the apparent ratio of lengths and exaggerates differences.

Q8. Why are pie charts often discouraged?

People compare aligned lengths better than slice angles/areas; similar slices are hard to rank precisely, nuance is lost, and a bar chart usually supports more accurate comparisons. Pie charts remain usable for a very broad audience and an obvious part-to-whole message.

Q9. Explain the curse of dimensionality.

As dimensions grow, pairwise distances become less distinguishable and nearest-neighbor neighborhoods become unstable. A 2D plot does not guarantee high-dimensional nearest-neighbor reliability.

Q10. State and explain the table-design guidelines.

Cover header/body separation, subtle gridlines, left-aligned text, right-aligned numbers, matched header alignment, meaningful precision, spacing-directed reading, units in headers, restrained outlier/missing-data highlighting, grouping/whitespace, and sparklines.

  • [ ] Scatter = relation between two numeric variables; patterns do not prove causes.
  • [ ] Pie = part-to-whole, but weak for precise slice comparison.

  • [ ] alpha: 0 transparent, 1 opaque.

  • [ ] Pie explode: offset/highlight wedges.
  • [ ] Pie default direction: counterclockwise; counterclock=False reverses it.
  • [ ] Annotation xy: target; xytext: label location; arrowprops: arrow formatting.

Bar versus histogram — exam distinction

A bar chart uses separated marks to compare categories and may be sorted by the reader’s task. A histogram uses touching, ordered numeric bins to reveal distribution shape. Numeric-looking data are not automatically continuous: a year often behaves as ordered time.

Answer framework

  1. State the question and audience.
  2. Identify variable types and order.
  3. Select the most perceptually accurate suitable encoding.
  4. Verify baseline, limits, labels, units, and completeness.
  5. Check accessibility; never rely only on colour.
  6. Remove clutter and state the remaining limitation.

Correct chart choice itself reduces cognitive load because users do not have to mentally reconstruct the intended comparison.
