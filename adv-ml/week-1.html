Learning objectives

By the end of this week, you should be able to:

  • define machine learning from multiple viewpoints;
  • distinguish conventional rule-based programming from machine learning;
  • describe offline, online/feedback-loop, and large-data iterative ML workflows;
  • identify supervised, unsupervised, and reinforcement-learning problems;
  • distinguish regression, classification, clustering, and association-rule mining;
  • formulate simple linear regression, interpret its parameters and error term, and derive the least-squares estimates;
  • solve the age–glucose numerical example manually and explain its Python implementation;
  • select an appropriate ML approach for a practical business case, including the NovaMart case used in the week material.

1. What is machine learning?

Core viewpoints

Learning is a process by which a system improves its performance through experience. A machine-learning system acquires knowledge autonomously through a computer program rather than requiring every operational rule to be written explicitly.

A common general definition is:

Machine learning is a field of study that gives computers the capability to learn without being explicitly programmed.

The live session described this as a model learning from data or supplied information and becoming better at performing the required activity. “Without explicit programming” does not mean that no code or algorithm exists; it means the final decision rules or mapping are learned from examples rather than exhaustively hand-coded by a programmer.

Tom Mitchell’s definition: experience, task, and performance

A computer program is said to learn from experience \(E\), with respect to some task \(T\) and performance measure \(P\), if its performance on \(T\), as measured by \(P\), improves with \(E\).

Element Meaning Spam-filter example
\(E\): experience The data/exposure from which the program learns Previously labeled spam and legitimate emails
\(T\): task The activity the program must perform Classify a new email
\(P\): performance The measure used to judge improvement Accuracy, precision, recall, or error rate

The essential test is not simply whether a program runs repeatedly; its measured performance on the specified task must improve because of experience.

Pattern-and-uncertainty viewpoint

ML can also be defined as a set of methods that:

  1. automatically detects or discovers patterns in data;
  2. uses those patterns to predict future/unseen data or make other decisions;
  3. operates under uncertainty.

Data may be numeric, text, an image/photo, a fingerprint, speech/voice, video, or other multimedia. If a problem is completely certain and can be captured reliably by fixed rules, ML/AI may be unnecessary; ML is especially valuable where patterns are complex, changing, or uncertain.

2. Conventional programming versus machine learning

Information flow

Approach Inputs to the computer Output
Conventional programming Human-written program/rules + data Answers/results
Supervised machine learning (training) Example data + corresponding known outputs/labels A learned model/program
Trained ML model (inference) Learned model + new input data Predicted output

In conventional C, C++, Java, or Python programming, a developer studies the problem and encodes the algorithm using the language’s syntax and semantics. For a prime-number checker, the prime-test algorithm is already in the computer; the user supplies a number, and the program returns “prime” or “not prime.” Similarly, adding two numbers follows rules explicitly written by the programmer.

In supervised ML, the system receives examples of inputs and correct outputs and learns the mapping that produced those outputs. Examples include spam detection and facial recognition. The programmer still chooses an algorithm and builds a pipeline, but the model learns the detailed pattern/rules from data.

Development cycles

Conventional cycle

  1. Study the problem.
  2. Write rules/program.
  3. Evaluate.
  4. Analyze errors; if necessary, restudy the problem and rewrite rules.
  5. Launch once evaluation succeeds.

Classical/offline ML cycle

  1. Define and study the problem.
  2. Collect and clean data.
  3. Select/construct a suitable algorithm and train it on the data; do not manually enumerate all decision rules.
  4. Evaluate the solution on data not used for fitting.
  5. Analyze errors, iterate, and refine the data/model/approach.
  6. Deploy the model.

Online-learning or feedback-loop variant

  1. Train, evaluate, and deploy.
  2. Capture feedback or fresh data after deployment.
  3. Feed it back to training.
  4. Retrain/optimize, reevaluate, and continue the refinement cycle.

Deployment is therefore not necessarily the end of learning. The live-session instructor stated that feedback loops can apply to both supervised and unsupervised learning, though their unsupervised use is more advanced. Once a model is already deployed, the repeated loop concerns feedback, training, evaluation, and refinement rather than repeatedly performing the initial deployment step.

Big-data/knowledge-discovery variant: with a very large dataset, train an ML algorithm, examine potentially multiple solutions, improve the solution, use what is learned to understand the problem more clearly, and iterate.

Instructor emphasis: data quality and generalization

  • ML needs data; useful training starts with clean data.
  • The test data should be different from the training data. Reusing training examples does not demonstrate that the model learned a general rule.
  • The aim is performance on unseen, real-world cases—generalization—not memorization.
  • After evaluation, errors are analyzed and minimized through iteration/refinement before deployment.

Practical analogy from the live session: knowing only the sequence “ABCDEFG” does not by itself establish an ability to speak; competence must be tested using different letters, words, and sentences. Likewise, a model must be tested beyond the examples used for training.

3. Why advanced ML is needed: scale and applications

Big-data motivation

Online systems such as YouTube, Amazon, Google, Facebook, and Netflix generate enormous volumes of users, interactions, networks, pages, and multimedia. The lecture used older YouTube statistics illustratively: roughly 600 hours of video uploaded per minute and about 3.25 billion hours watched per month, along with extremely large daily views, monthly unique visits, and operating costs. The exact figures were presented as older and likely much larger now; the examinable point is the scale, not memorization of transient statistics.

At this volume, ordinary fixed-rule programs alone are insufficient to extract and analyze patterns for system and human benefit. Advanced ML and AI methods are required to process the volume and complexity.

Recommendation engines analyze large quantities of data. Amazon can use what a user searched, browsed, or purchased and what similar users viewed or purchased. Facebook analyzes profiles and friendship networks. Netflix may use both user–item relationships and user–user similarity, together with viewing/search/genre behavior, to queue a likely next movie.

Computer vision is a branch of AI that uses ML—especially neural networks and convolutional neural networks—to understand images and videos. Deep learning is a domain within ML; the live session specifically associated CNNs with self-driving camera processing and deep neural networks with speech recognition.

4. Types of machine learning

4.1 Supervised learning

Supervised learning trains a machine using well-labeled data. Each training observation contains:

  • \(X\): input variable(s), predictor(s), or features;
  • \(Y\): the correct output, target, tag, class, or value.

The goal is to infer a mapping \(f\) such that:

\[ f:X\rightarrow Y \]

At prediction time, only the new \(X\) is supplied; the trained model predicts its \(Y\). The “supervisor” or “teacher” is the known target information. Labels may be names or categories (triangle, spam, politics), binary values (0/1), or quantities (price, glucose level).

Shape example: training data include geometric features and labels. Number of sides is one feature: three sides helps indicate “triangle”; four sides may indicate “square” or “rectangle,” so other features such as angles or side lengths may also be required. A new shape is supplied only through its features, and the model predicts its label.

Examples of supervised model families mentioned in the lecture include neural networks, support-vector machines, decision trees, and Bayesian classifiers. Supervised tasks divide primarily into regression and classification.

4.2 Unsupervised learning

Unsupervised learning receives unlabeled/raw input: only \(X\), with no corresponding \(Y\) and no prior knowledge of the correct class/value. It is self-guided and seeks structure, patterns, groupings, or relationships in the data.

Animal example: a raw collection contains cat and dog images without the words “cat” or “dog.” The algorithm interprets their features and discovers two different groups. It has found structure; it was not taught the semantic names of those groups.

Mentioned examples include K-means, clustering approaches, and (in the lecture’s broad categorization) genetic algorithms. Association-rule mining is another unsupervised pattern-discovery task.

4.3 Reinforcement learning

The course did not examine reinforcement learning in depth because it is a large domain. Its basic elements are:

  • an agent;
  • an environment;
  • actions performed by the agent;
  • positive rewards for desirable/correct actions and negative rewards/penalties for undesirable actions.

Through feedback, the agent learns behavior intended to maximize cumulative reward and avoid actions that led to penalties. Practical examples include game playing, robotics, and sequential control.

4.4 Do not confuse these two distinctions

Supervised vs. unsupervised concerns whether target labels \(Y\) are available. Structured vs. unstructured data concerns the form/schema of data. They are different dimensions: supervised or unsupervised tasks may involve tabular structured data, text, images, or other unstructured data.

Comparison

Aspect Supervised Unsupervised Reinforcement
Training signal Known \(Y\) for each \(X\) No \(Y\) Rewards/penalties from interaction
Main aim Predict class or value Discover patterns/groups/relations Learn a policy of actions
Typical tasks Regression, classification Clustering, association rules Sequential decision-making
Example Predict house price Segment customers Robot navigation

Caveat: neither supervised nor unsupervised learning is universally “more efficient” or “more modern.” The live discussion informally favored unsupervised learning for broad, unlabeled clusters, but the correct method depends on the problem statement, desired output, labels, features, data quality, and constraints.

5. Supervised tasks: regression and classification

Regression

Regression is a statistical predictive technique used when the target is a continuous quantity. It estimates the relationship between independent/predictor variables and a dependent/response variable.

Examples:

  • predict the exact age of a viewer from behavior;
  • predict an exact indoor temperature from weather, time, or door sensors;
  • predict house price from house size;
  • forecast sales;
  • predict glucose level from age.

House example: training pairs contain house size \(X\) and known price \(Y\). After fitting the regression model, a new house size alone is supplied and the model predicts a price, such as \($160{,}000\).

Classification

Classification predicts a discrete category/class/label. It approximates a mapping from input features \(X\) to discrete \(Y\).

News example: extract text features from labeled news articles. Training labels include food, sports, and politics. For a new article, feed only its features/text and predict its category.

Other examples: spam/not spam, fraud/genuine, churn/no churn, diseased/healthy, or positive/neutral/negative sentiment.

Same domain, different question

Question Output type Task
“What will tomorrow’s exact average temperature be?” Continuous number Regression
“Will tomorrow be cold, warm, or hot?” Discrete category Classification

Classification requires explicit class definitions. The lecture illustrated possible thresholds: above about \(40^\circ\text{C}\) could be called hot and below it cold, or three intervals could define cold, warm, and hot. The precise boundary is a design/domain decision; changing it changes the labels.

6. Unsupervised tasks: clustering and association rules

Clustering

Clustering groups observations so that points in the same group have similar features/properties and points in different groups are comparatively dissimilar. It operates on \(X\) without a known \(Y\).

Fruit example: a raw dataset contains apples, cherries, oranges, mangoes, pineapples, etc. Based on features, a clustering algorithm such as K-means separates similar fruits into clusters. The algorithm discovers group structure; attaching semantic names afterward may require human interpretation.

Practical use case: group customers using visit duration, pages viewed, category preferences, and purchase frequency, then tailor marketing to high spenders, price-sensitive shoppers, or window shoppers.

Association-rule mining

Association-rule mining discovers rules, co-occurrence patterns, or relationships among items in transactional data. It asks which items tend to occur together; it does not primarily form customer clusters or predict a continuous number.

Example transactions:

  • Customer 1: milk, bread, butter
  • Customer 2: milk, cereal, bread, butter
  • Customer 3: milk, bread, butter

These imply a stronger observed association among milk, bread, and butter than among milk, bread, and sugar. A common rule form is:

\[ \{\text{milk, bread}\}\Rightarrow\{\text{butter}\} \]

Uses include supermarket shelf proximity, online recommendations, cross-selling, product bundles, and market-basket analysis. Association indicates co-occurrence, not necessarily causation.

Review/case-study augmentation introduces three common rule measures:

  • Support: how frequently an itemset occurs in all transactions.
  • Confidence: how often the consequent occurs when the antecedent occurs.
  • Lift: strength relative to what would be expected if antecedent and consequent were independent; lift greater than 1 suggests a positive association.

Sparse transaction matrices—many products purchased rarely and many empty item entries—can yield few frequent itemsets and make rule discovery difficult. Support, confidence, and lift thresholds must be selected carefully.

7. Simple linear regression

Purpose and model

Simple linear regression fits the best straight-line relationship between one independent variable \(X\) and a dependent variable \(Y\).

The deterministic line is:

\[ Y=\beta_0+\beta_1X \]

The probabilistic model adds a random error term:

\[ Y=\beta_0+\beta_1X+\varepsilon \]

This corresponds to the familiar line \(y=mx+c\): \(\beta_1\) is the slope \(m\), and \(\beta_0\) is the vertical intercept \(c\).

Symbol Interpretation
\(X\) Independent, predictor, or explanatory variable
\(Y\) Dependent, response, or target variable
\(\beta_0\) True intercept: average/expected \(Y\) when \(X=0\)
\(\beta_1\) True slope: expected change in \(Y\) for a one-unit increase in \(X\)
\(\varepsilon\) Random deviation/error representing noise and omitted influences

For fixed \(X\), \(Y\) is random because \(\varepsilon\) is random. With \(n\) independent observations \((X_i,Y_i)\), the points scatter around the true regression line. Some may lie exactly on it, but generally each has its own error \(\varepsilon_i\).

Error, residual, and variance

The model error is the vertical difference between an observed point and the line. For a fitted model:

\[ \hat Y_i=\hat\beta_0+\hat\beta_1X_i, \qquad e_i=Y_i-\hat Y_i \]

The lecture sometimes described this as a perpendicular distance, but ordinary least squares minimizes vertical residuals in the \(Y\)-direction.

The variance parameter \(\sigma^2\) controls the spread of the conditional normal curves around the regression line:

  • small \(\sigma^2\): observed points usually lie close to the true line;
  • large \(\sigma^2\): observations may deviate considerably from expected values.

Least-squares objective

The best-fit line minimizes the sum of squared vertical residuals:

\[ F(B_0,B_1)=\sum_{i=1}^{n}\left[Y_i-(B_0+B_1X_i)\right]^2 \]

This is the sum of squared errors/residuals (SSE). Squaring prevents positive and negative residuals from canceling and gives larger deviations greater influence.

To minimize \(F\), take partial derivatives with respect to both unknowns and set them to zero:

\[ \frac{\partial F}{\partial B_0} =-2\sum_{i=1}^{n}\left[Y_i-B_0-B_1X_i\right]=0 \]

\[ \frac{\partial F}{\partial B_1} =-2\sum_{i=1}^{n}X_i\left[Y_i-B_0-B_1X_i\right]=0 \]

Solving these normal equations gives the least-squares estimates. Hats indicate estimates from sample data rather than unknown population parameters:

\[ \hat\beta_1= \frac{\sum_{i=1}^{n}(X_i-\bar X)(Y_i-\bar Y)} {\sum_{i=1}^{n}(X_i-\bar X)^2} =\frac{S_{XY}}{S_{XX}} \]

where

\[ S_{XY}=\sum X_iY_i-\frac{(\sum X_i)(\sum Y_i)}{n} \]

\[ S_{XX}=\sum X_i^2-\frac{(\sum X_i)^2}{n} \]

and

\[ \hat\beta_0=\bar Y-\hat\beta_1\bar X =\frac{\sum Y_i-\hat\beta_1\sum X_i}{n} \]

The fitted/estimated regression line is:

\[ \hat Y=\hat\beta_0+\hat\beta_1X \]

Accuracy note: a brief live-session utterance reversed “slope” and “intercept.” The recorded lecture and formulas establish the correct interpretation: \(\beta_1\) is slope; \(\beta_0\) is intercept.

8. Worked example: predict glucose level from age

Problem and data

The input/predictor \(X\) is age; the output/response \(Y\) is glucose level. Six labeled observations are used, including \((43,99)\) and \((21,65)\). The full ages referred to in the live session are 43, 21, 25, 42, 57, and 59. The model must predict the glucose level for a person whose age is not one of the training observations.

For manual calculation, construct columns \(X\), \(Y\), \(XY\), \(X^2\), and optionally \(Y^2\). For example, the first row contributes \(43\times99\), \(43^2\), and \(99^2\).

The lecture gives:

\[ n=6,\quad \sum X=247,\quad \sum Y=486, \]

\[ \sum XY=20{,}485,\quad \sum X^2=11{,}409 \]

From these:

\[ S_{XY}=478,\qquad S_{XX}=1240 \]

Therefore:

\[ \hat\beta_1=\frac{478}{1240}\approx0.385 \]

\[ \hat\beta_0=\bar Y-\hat\beta_1\bar X\approx65.14\text{ or }65.15 \]

The fitted model is:

\[ \hat Y=65.14+0.385X \]

For age \(55\):

\[ \hat Y=65.14+(0.385)(55)\approx86.3 \]

Thus the model predicts a glucose level of approximately 86.3. The software result shown was about 86.32329, with the tiny difference due to use of unrounded coefficients.

What the model means

  • Slope \(\approx0.385\): within this fitted example, a one-year increase in age corresponds to an expected increase of about 0.385 glucose units.
  • Intercept \(\approx65.14\): mathematical fitted value at age zero. It need not have a useful real-world interpretation when \(X=0\) is outside the meaningful data range.
  • Each residual is the observed glucose value minus the value on the fitted line at that age.

Important caveat from the live session

The instructor explicitly warned that this six-row dataset is only a small teaching example, not a realistic or logically validated medical dataset. Real applications can contain lakhs of observations, and one should not infer a medical law or causal relationship from these six values. The small sample was chosen for ease of manual computation.

9. Python implementation described in the lecture

The recorded demonstration followed this logic:

  1. Enter paired age/glucose values as a NumPy array (np.array).
  2. Plot the six points and label the axes “Age” and “Glucose Level.”
  3. Separate the paired array into \(X\) and \(Y\) (the lecture used np.split in its demonstration).
  4. Import LinearRegression from scikit-learn.
  5. Fit the model with the training inputs and targets.
  6. Inspect the learned coefficient and intercept: approximately 0.385225 and 65.14.
  7. Put 55 into a test NumPy array and call the model’s predict method.
  8. Obtain approximately 86.32329.
  9. Plot the fitted line and observe that residuals are vertical point-to-line distances; the line was selected to minimize their squared sum.

A clear modern equivalent is:

import numpy as np
from sklearn.linear_model import LinearRegression

# Six training observations; y values should match the lecture table.
X = np.array([43, 21, 25, 42, 57, 59]).reshape(-1, 1)
y = np.array([...])

model = LinearRegression().fit(X, y)
print(model.coef_[0])     # slope, approximately 0.385225
print(model.intercept_)  # intercept, approximately 65.14
print(model.predict(np.array([[55]])))  # approximately 86.32329

The mathematical and Python approaches should give the same result. The only reason the demonstration used just six observations was to keep manual arithmetic manageable.

10. Training, testing, evaluation, and improvement

End-to-end workflow

  1. State the business/problem objective.
  2. Collect relevant, clean data.
  3. For supervised learning, ensure each training \(X\) has a target \(Y\).
  4. Select and train an appropriate algorithm/model.
  5. Reserve different data for testing/evaluation.
  6. Compare predictions with actual targets using an appropriate measure.
  7. Analyze errors.
  8. Iterate on data, features, model choice, and settings.
  9. Deploy when acceptable.
  10. Where appropriate, use post-deployment feedback and retraining.

Without \(Y\), ordinary supervised linear regression cannot estimate its slope/intercept or compute training residuals. On unseen cases, \(Y\) may initially be hidden from the model but must be available later if a quantitative test error is to be calculated.

Common regression evaluation measures introduced in the accompanying week notes include:

  • MSE: mean of squared errors;
  • RMSE: square root of MSE, expressed in target units;
  • MAE: mean absolute error;
  • \(R^2\): proportion of target variation explained relative to a mean baseline.

A model should achieve useful performance on both training and testing data. Very low training error with poor test performance indicates poor generalization/overfitting.

Ways to improve include collecting more representative labeled data, cleaning data, engineering/selecting meaningful features, choosing a more suitable algorithm, and tuning its hyperparameters. ML improvement generally comes through better data and retraining rather than manually rewriting every decision rule.

11. NovaMart case study: selecting an ML roadmap

NovaMart is an e-commerce startup balancing three stakeholder priorities:

Stakeholder Priority
Ana, lead data scientist Prediction accuracy and generalization to unseen data
Raj, marketing manager Customer understanding and campaign personalization
Priya, IT Limited compute, low training overhead, memory/operational feasibility

Mapping each business question to an ML task

Business question Useful inputs Output Technique Learning type Main caveat
Forecast daily/quarterly sales Ad spend, visits, promotions, season/holiday, previous sales Numeric sales Linear regression Supervised Needs sufficient labeled sales history
Classify review sentiment Review text features Positive/neutral/negative Classification Supervised Needs labeled reviews
Segment customers Pages, time, clicks, purchase frequency, category interests Customer groups Clustering Unsupervised Feature choice and number/interpretation of clusters
Discover product bundles Transaction baskets Co-purchase rules Association rules Unsupervised Sparse data and threshold selection

Three strategic options

Option A — linear regression: simple, fast, interpretable, and computationally efficient; supports sales, financial, and inventory planning. It needs historical labeled outcomes and offers less direct customer insight.

Option B — clustering: directly supports targeted marketing without predefined labels. It may reveal frequent buyers, price-sensitive shoppers, occasional buyers, or window shoppers. Quality depends strongly on meaningful behavioral features; irrelevant variables such as random customer IDs distort similarity. One must also choose the number of clusters and interpret them.

Option C — association rules: generates product affinity, cross-selling, recommendation, shelf-layout, and bundle insights. It can struggle when transactions are sparse and may reveal product-level rather than customer-level behavior.

Infrastructure affects algorithm selection and feasibility, but it does not by itself determine whether the method should be supervised or unsupervised. Linear regression is an especially inexpensive baseline. Clustering can also be manageable, depending on data size and algorithm.

Review/quiz augmentation: balanced phased roadmap

The case review favored clustering as the most balanced initial choice because it:

  • gives Raj immediate actionable personalization;
  • does not require pre-existing labels;
  • can fit reasonable infrastructure limits;
  • produces customer-segment features that can later strengthen prediction.

A phased roadmap is therefore:

  1. Customer segmentation: understand behavior and target promotions.
  2. Sales forecasting: combine historical sales, traffic, marketing variables, and learned customer segments.
  3. Association rules: improve recommendations, bundles, and basket size.

This is contextual, not a universal claim that clustering is always best. If forecasting is the primary objective and good labeled history exists, regression may be the correct first choice; if cross-selling is urgent and transactions are sufficiently dense, association rules may be first.

12. High-value comparisons for the exam

If the requested output is… Labels? Choose… Example
Exact continuous number Yes Regression Sales, price, glucose, temperature
Discrete class Yes Classification Spam, sentiment, article topic
Natural groups No Clustering Customer segments
Item co-occurrences/rules No target labels Association-rule mining Market baskets
Sequence of actions maximizing reward Rewards instead of fixed labels Reinforcement learning Robot/game agent

Common traps

  • Regression vs classification: predicting exact temperature is regression; predicting cold/warm/hot is classification.
  • Clustering vs classification: classification uses named target classes during training; clustering discovers groups without those labels.
  • Clustering vs association rules: clustering answers “what similar groups exist?”; association rules answer “what items occur together?”
  • Label status vs data format: supervised/un-supervised is not the same as structured/unstructured.
  • Prediction vs causation: a fitted association or regression relationship does not by itself prove that \(X\) causes \(Y\).
  • Training vs test data: fitting and evaluating on the same examples cannot establish generalization.
  • \(\beta_0\) vs \(\beta_1\): \(\beta_0\) is intercept; \(\beta_1\) is slope.
  • True vs estimated line: \(\beta_0,\beta_1\) are population/true parameters; hats denote estimates from observed data.
  • Residual direction: ordinary least squares minimizes squared vertical residuals, not shortest geometric distances.
  • Small teaching dataset: do not treat the age–glucose data as medical evidence.

13. Exam-focused recall and self-test

Must-memorize equations

\[ Y=\beta_0+\beta_1X+\varepsilon \]

\[ e_i=Y_i-\hat Y_i,qquad SSE=\sum_{i=1}^{n}e_i^2 \]

\[ \hat\beta_1= \frac{\sum(X_i-\bar X)(Y_i-\bar Y)}{\sum(X_i-\bar X)^2} =\frac{S_{XY}}{S_{XX}} \]

\[ S_{XY}=\sum X_iY_i-\frac{(\sum X_i)(\sum Y_i)}{n},qquad S_{XX}=\sum X_i^2-\frac{(\sum X_i)^2}{n} \]

\[ \hat\beta_0=\bar Y-\hat\beta_1\bar X,qquad \hat Y=\hat\beta_0+\hat\beta_1X \]

Short-answer prompts

  1. State Mitchell’s definition. Include \(E\), \(T\), \(P\), and improvement of performance with experience.
  2. Why square residuals? To stop sign cancellation, penalize large deviations, and obtain a minimizable objective.
  3. Why hold out test data? To measure generalization on unseen cases rather than memorization of training examples.
  4. What does \(\sigma^2\) mean? The error spread around the regression line; small values imply tighter observations.
  5. Why is labeled data necessary for regression? It supplies observed \(Y\) values needed to estimate parameters and calculate errors.
  6. Why can a recommendation system be ML? It learns patterns in browsing, purchases, profiles, and similar-user behavior to predict relevant items.
  7. Why is customer segmentation unsupervised? Natural groups are sought without predefined target categories.
  8. Why is market-basket analysis not clustering? Its objective is item co-occurrence rules, not groups of similar observations.
  9. What is an online-learning loop? Post-deployment feedback becomes new experience for retraining, reevaluation, and refinement.
  10. Why is clean data emphasized? Learned patterns reflect the training data; poor, noisy, or irrelevant data produce poor rules and predictions.

Numerical recall

For the teaching example:

  • \(n=6\), \(\sum X=247\), \(\sum Y=486\)
  • \(\sum XY=20{,}485\), \(\sum X^2=11{,}409\)
  • \(S_{XY}=478\), \(S_{XX}=1240\)
  • \(\hat\beta_1\approx0.385\), \(\hat\beta_0\approx65.14\)
  • \(\hat Y=65.14+0.385X\)
  • at \(X=55\), \(\hat Y\approx86.3\)

Final one-minute revision

  • ML learns patterns from experience/data and is most useful under uncertainty.
  • Traditional programming: rules + data → output; supervised training: inputs + known outputs → learned model.
  • Supervised = \(X,Y\); unsupervised = \(X\) only; reinforcement = agent, environment, rewards.
  • Regression predicts continuous values; classification predicts categories.
  • Clustering finds similar groups; association rules find co-occurring items.
  • Linear regression fits \(\hat Y=\hat\beta_0+\hat\beta_1X\) by minimizing squared vertical residuals.
  • Use different training and test data; good performance means generalization to unseen cases.
  • Real ML is iterative: define, collect/clean, train, evaluate, analyze errors, refine, deploy, and potentially learn from feedback.
  • Choose techniques from the business question, available labels, features, data quality, compute resources, and required output—not from a belief that one learning type is universally superior.

Application areas explicitly reviewed

  • Computer vision learns from images/video (cars, trucks, handbags, etc.) and extensively uses neural networks.
  • Cybersecurity applications include malware/endpoint protection and safer browsing.

Association-rule example

The supermarket illustration associates milk, bread, butter, and cereal more strongly than an arbitrary combination such as milk, bread, and sugar. Stores and online retailers can use co-occurrence for layout, bundling, and cross-selling. Association does not establish causation.

Linear-regression numerical anchors

  • Examples include (age, glucose) = (43,99) and (21,65).
  • The hand calculation constructs $XY$, $X^2$, and $Y^2$ columns, obtaining $\hat\beta_1\approx0.385$ and $\hat\beta_0\approx65.14$.
  • Fitted equation: $\hat y=65.14+0.385x$.
  • For age 55: $\hat y\approx86.3$.

The slope describes sample association, not proof that age causally raises glucose.

Statistical assumption behind the pictured curves

The lecture depicts outcomes around the line as normal distributions whose spread is controlled by $\sigma^2$. A textbook interpretation is $Y\mid X=x\sim N(\beta_0+\beta_1x,\sigma^2)$ with independent constant-variance errors. The fitted line estimates a conditional mean, not every individual’s exact outcome.

Labels, features, quality, generalization, compute/memory, maintenance, and actionability all matter. A phased portfolio can serve all three; one algorithm cannot answer all three questions.
