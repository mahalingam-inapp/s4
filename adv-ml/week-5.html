1. Recommender-system overview

Two major filtering approaches emphasized in the course are:

Approach Main evidence Core question
Content-based filtering Features of items and the target user’s own profile/behavior “Which items resemble what this user likes?”
Collaborative filtering Ratings/interactions of multiple users “Which users behave similarly, and what did similar users like?”

Real applications often use hybrid recommendation systems, combining multiple approaches rather than relying on only content-based or only collaborative filtering.

Utility matrix recap

A utility matrix records the degree to which each user likes/dislikes each item, commonly as a 1–5 star scale (the live session also mentioned 1–10). Rows typically represent users, columns represent items, and a cell is the user’s rating for that item.

An empty cell means not rated/unknown, not a true rating of zero. Large utility matrices are normally sparse: most user–item combinations are blank. A recommendation system aims to predict useful blank cells, especially those likely to receive high ratings, and recommend the corresponding items.

2. Content-based filtering

Inputs and mechanism

Content-based filtering combines two main forms of information:

  1. Item/product features — e.g., category, subject, size, color, genre, education, science, health care, casual.
  2. User representation and context — profile, declared likes/dislikes, ratings, and observed behavior.

Each item and user is encoded as a vector in a common feature space. A matching/similarity score between the user vector and item vector is used to rank items.

Play Store example and feature matrix

For Play Store apps, each row can represent an app and each column a feature. Features may overlap: one app can be educational and science-related; another can be health/health-care; a fourth may combine education, science, and health care.

A binary feature matrix uses:

  • 1: feature is present/relevant;
  • 0: feature is absent/not relevant.

The recorded lecture consistently explains rows as apps and columns as features. A brief live-session description reversed the orientation before correcting itself; orientation is a convention, but matrix multiplication must use it consistently.

Example:

App Education Science Health Casual
App A 1 1 0 0
App B 0 0 0 1
App C 0 0 1 0
App D 1 1 1 0

Explicit and implicit feedback

Feedback Source Example Strength/caveat
Explicit User deliberately states a preference Canva asks whether use is business, education, or personal; user selects entertainment; user rates an item Direct signal, generally clearer, though users can still be inconsistent
Implicit System infers preference from behavior Previously installed apps, watched videos, clicks, time spent, purchases Abundant but ambiguous and potentially biased/noisy

The live session called explicit feedback relatively trustworthy and implicit feedback less trustworthy because behavior may not equal preference. Bias/noise should be handled by normalization, regularization, validation, or other modeling safeguards rather than treating every interaction as certain liking.

User and item embeddings; dot-product score

  • User embedding/profile vector: what the user likes or dislikes, learned from explicit and implicit signals.
  • App/item/feature embedding: features associated with the app/item.

For equal-dimensional vectors \(x\) and \(y\), a basic score is the dot product:

\[ x\cdot y=\sum_{i=1}^{d}x_i y_i \]

It is coordinate-wise multiplication followed by addition. For binary vectors, a coordinate contributes 1 only when both vectors contain 1 there, so the dot product counts shared active features.

Strengths

  • Does not require data about other users.
  • Can scale to many users without user-to-user comparison becoming the central bottleneck.
  • Directly incorporates a particular user’s interests.
  • Supports strong personalization, including niche/specific interests.
  • Can recommend an item from its attributes even when other users have not rated it, provided its features are available.

Limitations

  • Item features are often manually/hand engineered.
  • Good feature design requires substantial domain knowledge.
  • Only items with adequate representations/features can be matched reliably.
  • Recommendations are driven by the user’s existing profile and past interests, creating over-specialization: little novelty or serendipity.
  • Personalization is therefore both an advantage and a disadvantage.

Content-based versus collaborative filtering

Dimension Content-based Collaborative
Needs other users’ data No Yes
Basis Item attributes + target user’s profile Similar users/items from collective behavior
Main feature challenge Manual/domain-specific content representation Sparse user–item interactions and cold start
Diversity risk May repeat known interests Can expose new categories via peers

3. Vector foundations

Equal dimensionality

Vectors can be compared coordinate by coordinate only if they use the same features in the same order. Unequal dimensionality or mismatched feature order makes the dot product/cosine comparison invalid.

Dot product

For \(A=[a_1,\ldots,a_d]\) and \(B=[b_1,\ldots,b_d]\):

\[ A\cdot B=\sum_{i=1}^{d}a_i b_i \]

Live worked example:

\[ A=[1,2,3],\qquad B=[4,5,6] \]

\[ A\cdot B=(1)(4)+(2)(5)+(3)(6)=32 \]

L2 norm/magnitude

\[ \|A\|_2=\sqrt{\sum_{i=1}^{d}a_i^2} \]

For the above vectors:

\[ \|A\|=\sqrt{1^2+2^2+3^2}=\sqrt{14} \]

\[ \|B\|=\sqrt{4^2+5^2+6^2}=\sqrt{77} \]

Instructor warning: calculate the two square roots separately, then multiply \(\|A\|\|B\|\). Do not accidentally place all terms inside one incorrect combined root. In an exam, show the computation and interpret the resulting degree of similarity, not just the number.

4. Cosine similarity

Definition

Cosine similarity compares the direction/orientation of two nonzero vectors:

\[ \operatorname{cosim}(A,B) =\cos\theta =\frac{A\cdot B}{\|A\|_2\|B\|_2} =\frac{\sum_i a_i b_i} {\sqrt{\sum_i a_i^2}\sqrt{\sum_i b_i^2}} \]

A vector can be viewed geometrically as an arrow from the origin. A small angle means similar direction; an angle near \(90^\circ\) means orthogonality/no directional similarity.

Range and interpretation

For nonnegative/binary/rating vectors used in the lecture, cosine similarity lies between 0 and 1:

  • 1: same direction, maximum similarity;
  • 0: orthogonal/completely dissimilar in this feature space;
  • intermediate values: relative similarity.

After mean-centering, negative coordinates and negative cosine values can occur:

  • positive: similar above/below-average preference patterns;
  • near zero: weak relationship;
  • negative: opposing preference patterns.

In general real-valued spaces, cosine ranges from \(-1\) to \(1\), not always 0 to 1.

Why normalize the dot product?

The raw dot product increases with both alignment and vector magnitude. Cosine divides by both lengths, emphasizing direction and making comparisons less sensitive to absolute activity/intensity.

Measure Focus Sensitive to magnitude?
Dot product Shared weighted components Yes
Cosine similarity Angle/direction Largely no
Euclidean distance \(\sqrt{\sum(a_i-b_i)^2}\) Straight-line closeness Yes

Cosine is useful when preference pattern matters more than total activity. A “power user” and a less active customer can appear similar if their vectors point in the same direction; this can be useful or misleading depending on campaign goals.

Recorded binary-vector examples

The first recorded example used two 0/1 vectors, described as having norms \(\sqrt5\) and \(\sqrt4\). Binary values were chosen only for convenience; vectors can contain any real values.

A second displayed example produced:

\[ \frac{5}{\sqrt6\sqrt6}=0.833 \]

which was interpreted as high similarity. The transcript does not retain every displayed coordinate cleanly, so use the displayed formula/result as the course example while applying the general formula carefully.

For the live example \([1,2,3]\) and \([4,5,6]\):

\[ \cos\theta=\frac{32}{\sqrt{14}\sqrt{77}}\approx0.975 \]

The vectors therefore point in very similar directions.

5. Cosine similarity in collaborative filtering

Movie utility matrix

The course example uses four users—Hyun/Haiyun, Eric, Chundru, and “You”—and seven movies: watched-movie columns WM1–WM4 and new/not-watched columns NM1–NM3. Ratings are generally on a 1–5 scale, and blanks mean not rated.

Examples stated in the transcript:

  • Hyun rated several movies including WM1=5, WM3=3, WM4=2, NM1=1, NM2=4, and NM3=3; WM2 is blank.
  • Eric has WM1 blank, WM2=4, WM3 blank, WM4=5, NM1 blank, NM2=2, and NM3=5.

The initial method converts blanks to zero for computation. This is convenient but conceptually dangerous because “not observed” is not “disliked.” UV decomposition later avoids this assumption.

User–user similarity

Each user row is a rating vector. The lecture’s uncentered calculations give:

\[ \operatorname{cosim}(\text{Hyun},\text{Eric})=0.493 \]

The numerator uses their common/nonzero components:

\[ (2)(5)+(4)(2)+(3)(5) \]

with the corresponding full vector norms in the denominator.

Likewise:

\[ \operatorname{cosim}(\text{Hyun},\text{Chundru})=0.597 \]

Because \(0.597>0.493\), unnormalized/raw cosine says Chundru is closer to Hyun than Eric is.

The recorded video treats missing entries as zero when forming full vectors. The live explanation instead emphasizes using only co-rated/common observed items. These are distinct implementation choices; state the convention used because results may differ.

Predict a missing rating using a weighted average

If user 1 has not rated an item and users 2 and 3 have, predict:

\[ \hat R_1= \frac{R_2S_{12}+R_3S_{13}}{S_{12}+S_{13}} \]

where \(S_{1k}\) is user 1’s similarity to user \(k\), and \(R_k\) is user \(k\)’s rating for the target item.

In general, over neighbors who actually rated item \(i\):

\[ \hat r_{ui}= \frac{\sum_{v\in N_i(u)}s(u,v)r_{vi}} {\sum_{v\in N_i(u)}s(u,v)} \]

This is a similarity-weighted average. Omit missing neighbor ratings rather than inserting them into the numerator/denominator as observations. High-similarity users influence the prediction more.

Practical safeguards: define behavior when the denominator is zero, consider using only positive/top-\(k\) similarities, and—if signed similarities are used—consider \(\sum|s|\) in the denominator or another explicitly chosen convention.

6. Mean-centering/normalization

Why raw ratings are biased

Users employ rating scales differently. A strict user may rarely give 5, while a generous user may award 5 to mediocre items. Raw cosine can mistake rating generosity for preference similarity.

For each user \(u\), compute the average over that user’s observed ratings:

\[ \bar r_u=\frac{1}{|I_u|}\sum_{i\in I_u}r_{ui} \]

Then center each observed rating:

\[ r'_{ui}=r_{ui}-\bar r_u \]

  • positive centered value: above that user’s average;
  • zero: equal to the user’s average;
  • negative: below that user’s average;
  • opposite signs for an item suggest contrasting opinions.

Example from the lecture: if Hyun’s mean is 3, a raw 5 becomes \(+2\), a raw 3 becomes 0, and a raw 2 becomes \(-1\). On WM4, Hyun has \(-1\) while Eric has \(+1\), indicating contrasting normalized preference.

Effect on the movie example

After mean-centering:

\[ \operatorname{cosim}(\text{Hyun},\text{Eric})=-0.387 \]

\[ \operatorname{cosim}(\text{Hyun},\text{Chundru})=-0.51 \]

Although both are negatively related, \(-0.387>-0.51\), so centered cosine considers Eric closer to Hyun than Chundru—the reverse of the raw result.

This reversal is the instructor’s key point: normalization can materially change neighbors and predictions by removing user-specific baseline ratings. In practice, after predicting a centered deviation, add the target user’s mean back to return to the original rating scale.

7. UV decomposition / matrix factorization

Motivation

Cosine-based computation often turns blanks into zero, losing the crucial distinction between “unrated” and “rated zero.” UV decomposition predicts missing values without requiring every blank to be treated as an observed zero.

The lecture presents UV decomposition as a special/simplified case related to singular value decomposition (SVD). SVD factorizes a matrix into three matrices; UV factorization approximates a utility matrix with two lower-dimensional matrices:

\[ M\approx UV \]

Dimensions

For a utility matrix \(M\in\mathbb R^{m\times n}\) and latent dimension \(d\):

\[ U\in\mathbb R^{m\times d},\qquad V\in\mathbb R^{d\times n} \]

so:

\[ (m\times d)(d\times n)=m\times n \]

In the movie example:

  • 4 users, 7 movies: \(M\) is \(4\times7\);
  • choose \(d=2\);
  • \(U\) is \(4\times2\);
  • \(V\) is \(2\times7\);
  • \(UV\) returns a \(4\times7\) completed prediction matrix.

Interpretation: rows of \(U\) are user latent-factor vectors; columns of \(V\) are item latent-factor vectors. Their dot product predicts a user–item rating. The latent dimensions need not have explicit labels, though they may capture patterns such as genre affinity.

Objective: fit only observed entries

Let \(\Omega\) be the set of observed/nonblank cells. Optimize the factors using only those cells:

\[ \operatorname{RMSE}_{\Omega}= \sqrt{\frac{1}{|\Omega|} \sum_{(i,j)\in\Omega}\left(M_{ij}-(UV)_{ij}\right)^2} \]

The transcript sometimes loosely describes “difference, square, sum, square root” without always stating division by the number of observed entries. The quiz/review correctly emphasizes root mean squared error, so the mean factor belongs in the formal RMSE. Minimizing SSE or MSE gives the same minimizer for a fixed observed set; RMSE changes scale, not the optimum.

Only observed entries belong in the loss. Including blanks as zeros would train the system to reproduce invented dislikes and undermine the reason for factorization.

Coordinate-descent demonstration

The lecture uses an intuitive coordinate-wise optimization:

  1. Initialize every entry of \(U\) and \(V\) to 1.
  2. Then every cell of \(UV\) initially equals 2 when \(d=2\).
  3. Select one factor entry, e.g. \(U_{11}\), replace it by variable \(x\), and hold all other factor entries fixed.
  4. The first predicted row becomes \(x+1\) because the other latent component remains 1.
  5. For each observed first-row rating, form residuals such as \(5-(x+1)\), \(3-(x+1)\), etc.; do not invent residuals for blank cells.
  6. Square and sum the residuals to obtain a quadratic function of \(x\).
  7. Differentiate, set the derivative to zero, and solve the one-variable minimum. The demonstration obtains \(x=2\) for the first update.
  8. Substitute the updated value, select another coordinate (e.g. \(V_{11}\)), and repeat.
  9. Cycle across the entries of \(U\) and \(V\), reducing RMSE until values stabilize/converge or improvement becomes negligible.
  10. Multiply the final factors. \(UV\) contains estimates for originally blank cells as well as fitted values for observed cells.

This is coordinate descent: optimize one variable/coordinate at a time while holding the others fixed. It reduces the objective iteratively but is not guaranteed to find the global optimum because factorization is jointly non-convex. Initialization, latent dimension, stopping criteria, and regularization can affect the result.

Regularization and generalization

The live session linked regularization/normalization to bias control. In matrix factorization, a standard regularized objective is:

\[ \sum_{(i,j)\in\Omega}(M_{ij}-u_i^Tv_j)^2 +\lambda(\|U\|_F^2+\|V\|_F^2) \]

The penalty discourages excessively large factors and overfitting. This formula is a practical augmentation; the core transcript demonstration minimizes observed-entry reconstruction error without explicitly deriving the penalty.

8. Python collaborative-filtering demonstration

The demonstrated code was originally in R and converted to Python. It used pandas, NumPy, and a cosine-similarity facility from scikit-learn, while also defining a manual cosine function.

Step 1: load data

  1. Import pandas and NumPy.
  2. Create a movie_ratings DataFrame.
  3. Use users Hyun, Eric, Chundru, and You as the index.
  4. Use four watched-movie and three non-watched/new-movie columns.
  5. Enter blanks as None; pandas displays these numeric missing values as NaN (“not a number”), which is not zero.

Step 2: manual cosine-similarity function

The function takes two vectors and:

  1. converts NaN to numeric values for computation;
  2. computes each norm as the square root of the sum of squared elements;
  3. creates coordinate-wise products and sums them to obtain the dot-product numerator;
  4. returns numerator divided by the product of norms.

A function definition alone produces no result until called with vectors.

Step 3: prepare vectors and compute similarities

The later code fills missing values with a very small value, 0.0001 (\(10^{-4}\)), as a near-zero computational placeholder. It extracts each user’s row as a flattened NumPy array and computes the similarities between “You” and each friend.

Reported values:

Pair Cosine similarity
You–Hyun 0.66
You–Eric 0.53
You–Chundru 0.59

The similarity DataFrame is transposed so names become accessible keys for the weighted-average function. The instructor stressed that this transpose is an indexing/layout adjustment; it does not change similarity values or underlying data.

Step 4: weighted-average function

For a target new movie:

  • initialize numerator and denominator;
  • iterate through friend names;
  • retrieve the friend’s similarity and rating;
  • if the friend’s target rating is missing, continue/skip it;
  • otherwise add similarity × rating to the numerator and similarity to the denominator;
  • return numerator/denominator.

Conceptual pseudocode:

def weighted_rating(movie, friends, ratings, similarities):
    numerator = 0.0
    denominator = 0.0
    for friend in friends:
        rating = ratings.loc[friend, movie]
        if pd.isna(rating):
            continue
        sim = similarities.loc[friend]
        numerator += sim * rating
        denominator += sim
    return numerator / denominator

Step 5: predict new movies

  1. Set friend names to Hyun, Eric, and Chundru.
  2. Set new movies to NM1, NM2, and NM3.
  3. Transpose ratings as required to align rows/columns in the code.
  4. Loop through each new movie.
  5. Call the weighted-average function.
  6. Append movie and predicted rating to a results DataFrame.

Reported predictions for “You”:

Movie Predicted rating
NM1 2.3066
NM2 2.07
NM3 3.59

NM3 has the highest predicted rating and should be recommended first. NM1 and NM2 are relatively close and lower.

Important implementation caveats

  • NaN is missing, not zero; replacing it by 0.0001 is only a computational workaround and can still influence similarity.
  • Guard against zero norms and zero weighted-average denominators.
  • Modern pandas may prefer accumulating rows and constructing a DataFrame or using concat rather than repeated deprecated DataFrame.append calls.
  • A robust production system should validate on held-out ratings, not judge quality only from internally generated scores.

9. TechWave Solutions case study: cosine similarity for customer segmentation

Business setting and stakeholders

TechWave Solutions represents each customer’s purchase behavior/preferences as a binary feature vector and wants meaningful marketing segments under a limited budget.

Stakeholder concerns reflected in the review:

  • marketing: useful groups and personalization;
  • data/analytics: mathematically valid similarity and thresholds;
  • finance/management: campaign return on investment (ROI), adequate group sizes, and efficient budget allocation.

Meaning of binary customer vectors

Each coordinate is a shared behavioral feature:

  • 1: customer has that preference/behavior;
  • 0: customer does not.

Customers must have the same dimensionality and feature ordering. For binary vectors, the dot product counts shared 1s, while the norm normalizes for total active features.

Course case examples

The supplied case notes list:

\[ F_1=[1,1,1,1,0,0,0],\quad F_2=[0,0,1,1,0,1,1] \]

and report:

\[ \cos(F_1,F_2)\approx0.447 \]

interpreted as low similarity.

They also list:

\[ G_1=[1,1,1,1,1,0],\quad G_2=[1,1,0,1,1,1] \]

and report:

\[ \cos(G_1,G_2)\approx0.833 \]

interpreted as high similarity.

Data-integrity warning: the transcribed vectors, stated norms, dot products, and reported answers are not fully arithmetically consistent. As written, \(F_1\) has four ones (norm 2), so its displayed vectors yield \(2/(2\cdot2)=0.5\), not 0.447. As written, \(G_1\) and \(G_2\) share four ones and each has five ones, yielding \(4/5=0.8\), not 0.833. Preserve 0.447 and 0.833 as the quiz/case’s intended reported values, but in a calculation question recompute from the exact vectors printed on the exam and show every step.

Threshold strategies

Similarity band Segment interpretation Marketing treatment
\(s\ge0.8\) Highly similar, narrow/high-confidence segment Premium personalization, loyalty, cross-sell, tightly targeted offers
\(0.5\le s<0.8\) Moderately similar, broader segment General promotions, awareness, seasonal offers
\(s<0.5\) Weakly similar Avoid treating them as one tightly targeted group

Single threshold 0.5: larger segments and wider reach but weaker cohesion, less precise personalization, and possible wasted spend.

Single threshold 0.8: smaller, more homogeneous, high-confidence groups but reduced coverage and possible exclusion of useful customers.

Dual-threshold strategy: use both bands and vary campaign intensity. The quiz/review recommends this as the best balance of segment precision, usable size, personalization, limited budget, and ROI.

Power-user issue

Cosine removes magnitude. A power user with many active features and a regular customer with fewer can still point in a similar direction and receive high cosine similarity. Whether they should be in the same business segment depends on objectives. Binary features also discard purchase frequency, value, recency, and intensity.

Practical solution: combine cosine-based preference direction with variables such as spend, frequency, recency, customer lifetime value, or activity tier. Segmentation can be hierarchical: preference cluster first, power-user tier second.

Validate thresholds empirically

Do not accept 0.5, 0.8, or dual thresholds only because they sound reasonable. Compare strategies using:

  • segment size and stability;
  • within-segment similarity/cohesion;
  • campaign click/conversion and uplift against a control group;
  • revenue, margin, and cost;
  • ROI and coverage;
  • A/B tests or pilots.

The best threshold is the one that achieves the business objective on real outcomes, not merely the largest cosine value.

10. Exam-focused comparisons and traps

Concept Correct exam statement
Blank rating Unknown/unobserved; not automatically zero
Dot product Coordinate-wise products summed; magnitude-sensitive
Cosine similarity Dot product divided by both L2 norms; direction-sensitive
Raw cosine Can be biased by rating scale/generosity
Mean-centering Subtract each user’s own observed-rating mean
Weighted prediction Similar neighbors’ observed ratings contribute in proportion to similarity
UV factorization Approximate \(M\) by lower-rank \(UV\) and predict missing cells
UV loss Computed over observed entries only
Coordinate descent Optimize one factor entry at a time, repeat to convergence
RMSE Square root of mean squared observed-entry residuals

Common errors

  • Comparing vectors with different feature meanings/order.
  • Forgetting one of the two norms in cosine similarity.
  • Combining the norm roots incorrectly.
  • Assuming cosine is always in \([0,1]\); centered/real vectors can produce negatives.
  • Calling a blank a negative preference or zero rating.
  • Including blank entries as zeros in matrix-factorization loss.
  • Averaging neighbor ratings without similarity weights.
  • Including a missing neighbor rating in the weighted average.
  • Reading \(-0.51\) as “closer” than \(-0.387\); numerically, \(-0.387\) is greater and less opposed.
  • Assuming a high cosine guarantees business profitability.
  • Treating quiz vectors/results as infallible when their displayed arithmetic conflicts; recompute from the actual question.

12. Recall questions with answer cues

  1. What are the two inputs to content-based filtering? Item features and a target user’s profile/context/feedback.
  2. Why can content-based filtering scale across users? It does not require all other users’ data for each target user’s recommendation.
  3. What is over-specialization? Recommending only items similar to established interests, reducing novelty.
  4. What does a binary dot product count? Features active in both vectors.
  5. Why divide the dot product by norms? To compare direction rather than raw magnitude.
  6. Why is a utility matrix sparse? Most users interact with/rate only a small fraction of all items.
  7. How is a missing rating predicted from neighbors? Similarity-weighted average over neighbors who rated the item.
  8. Why mean-center? Remove user rating-scale bias and compare relative preferences.
  9. What happened after centering the movie example? The closer neighbor changed from Chundru to Eric.
  10. Why use UV instead of simply filling blanks with zero? It learns from observed entries and estimates unknown cells without calling them observed dislikes.
  11. What are the UV dimensions for four users, seven movies, and two factors? \(U:4\times2\), \(V:2\times7\), product \(4\times7\).
  12. What is coordinate descent here? Optimize one entry of \(U\) or \(V\) at a time while holding all others fixed.
  13. Which demo movie is recommended? NM3, predicted at about 3.59.
  14. What does threshold 0.5 do in TechWave? Broad reach and larger but less cohesive segments.
  15. What does threshold 0.8 do? Narrow, highly similar, more personalized segments.
  16. Why prefer the dual threshold in the case? It assigns different campaigns to high- and moderate-similarity bands, balancing reach, precision, and ROI.

Final one-minute revision

  • Content-based = item features + the same user’s profile; collaborative = behavior of multiple users.
  • Explicit feedback is declared; implicit feedback is inferred and more ambiguous.
  • A blank utility entry is unknown, not zero.
  • Cosine = dot product divided by both norms; greater cosine means closer direction.
  • Mean-centering subtracts each user’s average and can reverse neighbor rankings.
  • Similarity-weighted averages predict missing ratings using only neighbors with observed target-item ratings.
  • UV learns low-dimensional user/item factors by minimizing observed-entry reconstruction error, then multiplies them to predict blanks.
  • Demo: similarities You–Hyun 0.66, You–Eric 0.53, You–Chundru 0.59; NM3 is highest at 3.59.
  • TechWave review: 0.5 broad, 0.8 precise, dual threshold balances marketing ROI—but validate with actual campaign outcomes.
  • Practice basic cosine calculations by hand, show all norms separately, and interpret the result as the instructor emphasized.

13. QA supplement — transcript and quiz details

Similarity measures answer different questions

  • Dot product combines alignment and magnitude.
  • Cosine measures angle/direction after normalization.
  • Euclidean distance measures absolute separation.

For binary behavior vectors, cosine emphasizes overlap relative to activity volume. It can group similarly patterned customers despite very different activity, creating the TechWave power-user caveat.

Range and centering caveats

General cosine lies in $[-1,1]$; nonnegative/binary vectors give $[0,1]$. Negative similarity becomes possible after mean-centering. After centering, $UV^T$ models deviations from user baseline; add the baseline back for a raw-rating prediction.

Coordinate-descent mechanics

Alternate updates of $U$ and $V$ while holding the other fixed, using observed set $\Omega$:

$$\min_{U,V}\sum_{(i,j)\in\Omega}(R_{ij}-u_i^Tv_j)^2+\lambda(\|U\|_F^2+\|V\|_F^2).$$

Stop on negligible objective/RMSE improvement or a maximum iteration. The lecture’s unregularized demo is educational; production needs regularization, validation, and controlled initialization.

Demo safety checks

  • Align vectors to identical item order and dimension.
  • Do not treat unknown ratings as true zero unless zero has that meaning.
  • Guard against zero norms and zero total neighbor similarity.
  • Exclude the target itself from neighbors where applicable.
  • Fit thresholds/hyperparameters only on development data.

TechWave threshold decision

The case compares broad 0.5 and strict 0.8 thresholds. A dual strategy can form high-confidence ($\ge0.8$), experimental (0.5–0.8), and low-similarity segments. Validate segment size, conversion lift, cost, ROI, stability, and fairness rather than choosing the highest cutoff automatically.

17. Review-week augmentation: factorization and implementation

The review week adds a production-oriented bias-aware prediction formula to the basic $UV^T$ treatment:

$$\hat r_{ui}=\mu+b_u+b_i+p_u^Tq_i,$$

where $\mu$ is the global mean, $b_u$ captures a user’s generous/strict rating tendency, $b_i$ captures an item’s general popularity or quality effect, and $p_u^Tq_i$ captures latent user–item compatibility. The regularized observed-entry objective is

$$\min \sum_{(u,i)\in\Omega}(r_{ui}-\hat r_{ui})^2+\lambda\left(b_u^2+b_i^2+\|p_u\|_2^2+\|q_i\|_2^2\right).$$

This separates baseline effects from interaction structure and helps prevent large latent vectors from fitting noise. Select factor count and $\lambda$ on validation data, not on the test set.

Implementation roles emphasized in review:

  • pandas: ingest, clean, aggregate, pivot, and map external IDs.
  • csr_matrix: store sparse user–item data without allocating the full dense matrix.
  • scikit-learn NearestNeighbors: retrieve neighbours; remember it returns distances and row indices, and convert cosine distance $d$ to similarity $1-d$ when appropriate.

Serving safeguards include minimum-overlap/significance weighting, excluding already-consumed items, zero-norm and zero-denominator checks, clipping rating predictions to the legal scale, availability filters, and fallbacks when neighbourhood evidence is weak.
