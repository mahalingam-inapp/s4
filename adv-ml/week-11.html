Week overview

Week 11 studies why ordinary clustering becomes unreliable in high dimensions and develops two subspace/projected solutions:

  • CLIQUE: bottom-up, grid-based, density-based subspace clustering;
  • PROCLUS: top-down, medoid-based projected clustering with cluster-specific dimensions.

The practical demonstration also uses a global projection pipeline: preprocessing → PCA → K-means. Quiz and case-study material adds parameter selection, convergence, business interpretation, and deployment trade-offs.

1. High-dimensional data

A dataset’s dimensions are its features/columns. Rows are observations/records.

Example student dataset columns: name, roll number, age, height, weight, and income. With six fields and 20,000 students, it has six dimensions and 20,000 records.

  • Width: number of features/columns.
  • Height: number of observations/rows.
  • A dataset is high-dimensional when it has many features; the especially difficult $p\gg n$ case has more features than observations.
  • High-dimensional data can also be “big data” if both width and height are large, but the concepts are not identical.

Examples:

  • genomics: thousands of gene measurements;
  • healthcare: many biomarkers, tests, diagnoses, and signals;
  • finance: trading, price, risk, and market features;
  • face images/eigenfaces: each pixel may be a feature;
  • marketing/clickstream data: many behavioral variables.

1.1 Challenges

  • high computation and memory requirements;
  • visualization beyond 3D is difficult/impossible directly;
  • relationships are hard to interpret;
  • noise and irrelevant features can dominate;
  • conventional models may fail to generalize;
  • distance-based algorithms become unreliable;
  • too few observations relative to dimensions increase overfitting risk.

2. Curse of dimensionality and distance concentration

As dimensionality rises, the volume of feature space grows rapidly and observations become sparse. More data are required to achieve the same coverage.

For distance-based clustering, an important effect is distance concentration: nearest and farthest distances become increasingly similar relative to their magnitude. Euclidean distance can stop providing strong evidence that one observation is meaningfully nearer than another.

Consequences for K-means:

  • irrelevant dimensions add noise to every distance;
  • true clusters may exist only on different feature subsets;
  • global full-space centroids blur useful structure;
  • clusters can be masked by unrelated features;
  • assignments become unstable or arbitrary.

This motivates searching for clusters in lower-dimensional subspaces rather than assuming every feature defines every cluster.

3. General responses to high dimensionality

3.1 Remove/select features

  • Drop columns with excessive missing data.
  • Remove nearly constant/low-variance columns.
  • Remove irrelevant or redundant variables.
  • In supervised tasks, use association/correlation with the response carefully.

Low variance does not automatically mean useless, and low marginal correlation can miss nonlinear/interacting predictive effects; selection must be validated.

3.2 Feature extraction

PCA creates lower-dimensional orthogonal combinations retaining maximum global variance. Principal-component regression uses these scores in regression.

3.3 Regularization

Ridge and lasso constrain coefficients and can improve high-dimensional supervised models. PCA is primarily dimensionality reduction rather than coefficient regularization, although both can control effective complexity.

3.4 Cluster in relevant subspaces

Discover groups using only locally relevant dimensions. This is necessary when different groups are visible in different feature subsets.

4. Clustering recap

Clustering discovers groups of objects with similar properties without known labels. Similarity is commonly measured through distance.

Applications mentioned:

  • biology: grouping species/genes;
  • psychology/medicine: grouping patients, conditions, or medicines;
  • business: customer segmentation;
  • networks: patterns/communities;
  • software/data analysis: grouping programs or records.

Families include centroid, density, spectral, and hierarchical clustering. Full-space clustering assumes all dimensions matter equally to all clusters—often false in high-dimensional data.

5. Subspace and projected clustering

5.1 Subspace clustering

Search for clusters that exist in subsets of the original dimensions. A point/group may participate in multiple clusters in different subspaces, depending on the method.

5.2 Projected clustering

Partitions observations into clusters and assigns each cluster its own relevant feature subset. Each observation generally belongs to one cluster, but clusters may use different dimensions.

Example:

  • price-sensitive customers cluster on discount and basket value;
  • engagement-driven customers cluster on sessions and clicks;
  • service-sensitive customers cluster on complaints and response time.

Using every marketing feature globally could conceal all three patterns.

5.3 Bottom-up versus top-down

Approach Starts with Operation Example
Bottom-up Dense low-dimensional units Combine/grow into higher-dimensional subspaces CLIQUE
Top-down Candidate full-space clusters/representatives Select/weight relevant dimensions per cluster PROCLUS

6. CLIQUE algorithm

CLIQUE (CLustering In QUEst) is a grid-based, density-based, bottom-up subspace clustering algorithm.

6.1 Core concepts

  • Divide each feature range into intervals.
  • Their Cartesian products form rectangular grid units/cells.
  • Count observations in each unit.
  • A unit is dense if its point fraction/count exceeds a density threshold.
  • A cluster is a maximal connected set of dense units in a subspace.

Typical inputs:

  • data matrix;
  • grid resolution/number of intervals;
  • density threshold.

6.2 Apriori/downward-closure principle

If a $k$-dimensional unit is dense, all of its lower-dimensional projections must also be dense. Therefore, only combinations of dense $(k-1)$-dimensional candidates need to be tested at dimension $k$.

Correct direction matters: dense high-dimensional unit ⇒ dense projections. A dense low-dimensional unit does not guarantee every higher-dimensional extension is dense.

6.3 Workflow

  1. Normalize/scale features if grid intervals require comparability.
  2. Partition every dimension into equal-width intervals.
  3. Find dense one-dimensional units.
  4. Generate candidate two-dimensional units from dense lower-dimensional units.
  5. Count points and prune non-dense candidates.
  6. Repeat for higher dimensions.
  7. Join adjacent dense units into maximal clusters.
  8. Produce compact descriptions, often axis-parallel region rules.

6.4 Strengths

  • Finds clusters in subspaces without enumerating all cells naively.
  • Scales reasonably to many observations/dimensions through Apriori pruning.
  • Grid counting makes order of input less important.
  • Produces interpretable axis-parallel cluster descriptions.
  • Can discover clusters of varying shapes as connected dense cells.

6.5 Limitations

  • Sensitive to grid resolution and density threshold.
  • Boundary effects: a natural cluster may be split across cells.
  • Axis-aligned grids struggle with rotated/diagonal patterns.
  • Too coarse a grid merges structure; too fine a grid makes cells sparse.
  • Candidate subspaces can still grow rapidly.
  • Density varies across subspaces, making one threshold imperfect.

6.6 Practical example

For customer features age, income, spend, visits, and complaints, CLIQUE may find dense connected units in (income, spend) and a different cluster in (visits, complaints) without demanding a single common feature set.

7. PROCLUS algorithm

PROCLUS (PROjected CLUStering) is a top-down, partitioning, medoid-based projected clustering algorithm. It is related to k-medoid reasoning but chooses cluster-specific relevant dimensions.

7.1 Inputs and output

Main inputs:

  • $K$: desired number of clusters;
  • $L$: average number of relevant dimensions per cluster.

Output:

  • $K$ medoid-centered clusters;
  • dimension set $D_i$ for each cluster $C_i$;
  • assignment of observations (and sometimes outliers).

7.2 Why medoids?

A medoid is an actual observation chosen as a representative. Unlike a mean centroid, it is less distorted by extreme values and remains interpretable as a real case/customer.

7.3 Cluster-specific distance

If cluster $i$ uses dimensions $D_i$, a segmental Manhattan distance can be written:

$$d_{D_i}(x,m_i)=\frac{1}{|D_i|}\sum_{j\in D_i}|x_j-m_{ij}|.$$

The averaging prevents clusters with more selected dimensions from automatically having larger distances.

7.4 High-level workflow

PROCLUS is commonly described in three phases.

Phase 1 — Initialization

  1. Draw a candidate medoid sample.
  2. Greedily choose well-separated representatives to cover the data.
  3. Select $K$ initial medoids.

Good separation avoids initializing multiple medoids in the same region.

Phase 2 — Iteration

  1. For each medoid, identify a locality/neighborhood, often relative to nearby medoids.
  2. Calculate per-dimension spread around the medoid, such as average absolute deviation.
  3. Standardize/rank dimensions by compactness.
  4. Select low-spread dimensions for that cluster, subject to the average $L$ budget and minimum-dimension requirement.
  5. Assign each point to the nearest medoid using that medoid’s selected dimensions.
  6. Evaluate objective quality; identify weak clusters/bad medoids.
  7. Replace poor medoids and repeat.

Phase 3 — Refinement

  1. Recompute relevant dimensions using final cluster memberships.
  2. Reassign observations with refined dimension sets.
  3. Remove/flag outliers and return final clusters.

7.5 Selecting relevant dimensions

A dimension with small within-locality deviation is useful because the cluster is compact there. Dimensions are scored relative to the medoid and often standardized across dimensions to make their deviations comparable.

PROCLUS distributes roughly $K\times L$ dimension assignments across clusters. This is an average budget, not necessarily exactly $L$ dimensions for each cluster. Some clusters may receive more and others fewer, subject to a minimum (commonly at least two in the discussed material).

7.6 Convergence

Stop when one or more conditions are met:

  • medoids no longer change materially;
  • point assignments stabilize;
  • dimension sets stabilize;
  • objective improvement falls below a tolerance;
  • maximum iterations reached.

A maximum-iteration cap is a safety/computation constraint, not the ideal definition of convergence.

7.7 Strengths

  • Finds different dimensions for different clusters.
  • Uses robust, interpretable medoids.
  • Avoids irrelevant-feature dilution in full-space distance.
  • Well suited to high-dimensional segmentation.
  • Can expose which variables define each discovered group.

7.8 Limitations

  • Requires $K$ and $L$ in advance.
  • Sensitive to medoid initialization/sampling.
  • Local optimum and stochastic variation are possible.
  • Axis-aligned relevant dimensions; rotated structure can be difficult.
  • Parameter search and repeated runs can be expensive.
  • Cluster-specific dimension sets complicate global visualization/comparison.

8. Effects of PROCLUS parameters $K$ and $L$

8.1 Increasing $K$

  • more, smaller clusters;
  • potentially finer market segmentation;
  • risk of fragmentation, unstable tiny groups, and reduced business actionability;
  • higher computation and larger total dimension-assignment budget $K\times L$.

8.2 Increasing $L$

  • more dimensions characterize each cluster;
  • potentially richer profiles and better coverage of relevant signals;
  • may reintroduce noisy/irrelevant features and weaken distance contrast;
  • reduces sparsity/interpretability of cluster explanations.

8.3 Joint trade-off

The pair $(K,L)$ should be tuned jointly. Increasing one changes the effective model capacity and $K\times L$ allocation. Use stability, internal quality, external/business utility, minimum cluster size, interpretability, and held-out/repeated-run evidence.

8.4 Choosing between nearby $K$ values

Do not automatically select $K=5$ over $K=4$ because an apparent score is slightly higher. Ask:

  • Is the improvement reproducible across seeds/samples?
  • Are all clusters stable and sufficiently large?
  • Do the extra segments have distinct relevant dimensions?
  • Can the business act differently on them?
  • Does complexity justify the marginal gain?

10. PCA + K-means versus PROCLUS

PCA + K-means

  1. Preprocess data.
  2. Apply one global linear projection.
  3. Cluster every observation in the same principal-component space.

Advantages:

  • simple, widely available, fast;
  • good visualization;
  • useful if one common low-dimensional structure explains all groups.

Limitations:

  • PCA preserves global variance, not cluster separation;
  • all clusters share the same transformed dimensions;
  • components mix original variables and reduce direct interpretability;
  • cluster-specific low-variance signals may disappear.

PROCLUS

Uses different original dimensions for different clusters. It can therefore be strategically better when customer segments are defined by different behavioral drivers. PCA + K-means remains a strong baseline, not a universal inferior method.

11. Projected-clustering Python demonstration

The lecture demonstrates a practical global projection rather than implementing PROCLUS directly.

11.1 Pipeline

  1. Preprocess: fill missing values, standardize numeric features, encode categorical columns.
  2. PCA: project data to fewer principal components.
  3. K-means: cluster in projected space.
  4. Evaluate: inspect labels, centroids, overlap/outliers, and whether assignments are meaningful.

K-means steps revisited:

  1. choose $K$;
  2. initialize centroids;
  3. assign each point to nearest centroid using Euclidean/Manhattan-style distance;
  4. recompute centroid as the arithmetic mean of members;
  5. repeat until assignments/centroids stabilize.

Standard K-means conventionally uses squared Euclidean distance and arithmetic means. Taking a “square root of the average,” as one spoken line suggests, is not the centroid update.

PCA uses covariance eigenvectors; the eigenvector for the largest eigenvalue is PC1 and captures maximum variance. Use more PCs if one dimension is insufficient.

11.2 Libraries

  • KMeans from sklearn.cluster;
  • NumPy for data generation;
  • Matplotlib for plots;

11.3 Datasets and observations

Random data

  • NumPy random seed;
  • 1,000 samples, 20 dimensions;
  • PCA to 2 components;
  • K-means with 3 clusters, then 4;
  • because data are random, visible clusters/overlap should not be overinterpreted.

Simple ARFF data

  • already 2D with three evident groups;
  • PCA still set to 2 components;
  • $K=3$ recovers the natural groups;
  • forcing $K=2$ or $K=4$ merges/splits structure “for name’s sake,” illustrating that K-means always returns the requested $K$ even if it is not natural.

High-dimensional ARFF data

  • four original dimensions projected to two;
  • tested with 3 and 2 K-means clusters;
  • clusters contain outliers/points outside clean boundaries;
  • lecture connects this to the approximate 95% result in the PROCLUS example.

Stream ARFF data

  • four dimensions projected to two;
  • tried $K=3$, $4$, and $2$;
  • some groups overlap;
  • four groups are visually suggested in one view, while two larger groups may be sufficient depending on interpretation.

Accuracy language is delicate in unsupervised clustering: unless ground-truth labels exist and cluster IDs are optimally matched, “95% accuracy” is not an intrinsic clustering metric. Use silhouette, cohesion/separation, stability, known-label external metrics, and business validation as appropriate.

12. DataVista quiz case study

DataVista uses PROCLUS for high-dimensional customer segmentation. The case includes simple, high-dimensional marketing, and streaming clickstream experiments.

12.1 Experiment interpretation

  • Simple low-dimensional data can be perfectly/easily clustered; PROCLUS may be unnecessary overhead.
  • High-dimensional marketing data reports about 95% apparent performance: encouraging, but not proof of universal superiority or production readiness.
  • Streaming data demonstrates useful clusters but raises drift, changing distributions, and retraining concerns.

12.2 Stakeholder concerns

Tom’s concern about larger $K$: finer segments may improve fit but increase fragmentation, instability, communication burden, and campaign complexity.

CFO’s request to limit iterations: an iteration cap controls cost and latency, but stopping too early can leave poor medoids/dimensions. Combine cap with convergence tolerance and quality monitoring.

Argument for larger $L$: more dimensions may give richer/actionable profiles, but only if the added features are stable and genuinely relevant. Otherwise they reintroduce noise.

12.3 Recommended experimental strategy

  1. Clean, impute, encode, and scale data.
  2. Remove clearly unusable/constant features.
  3. Define plausible grids of $K$ and $L$.
  4. Run multiple seeds/medoid samples per setting.
  5. Track objective value, convergence, cluster size, dimension sets, internal metrics, stability, and runtime.
  6. Interpret clusters with domain experts.
  7. Compare against K-means and PCA + K-means baselines.
  8. Validate external/business outcomes (campaign lift, retention, conversion).
  9. Select the simplest stable/actionable configuration.
  10. Deploy with drift monitoring and periodic/reflexive retraining.

12.4 Convergence strategy

Use a moderate tolerance plus maximum iterations. Tight tolerance alone can waste computation for negligible changes; a hard cap alone may stop prematurely. Also monitor cluster/dimension stability and objective improvement.

13. Practical customer-segmentation example

Suppose columns are:

  • age, income, purchase frequency, average basket value;
  • discount use, app sessions, email clicks;
  • complaints, support time, returns;
  • location and channel variables.

PROCLUS might discover:

  • Cluster A on {discount use, basket value, purchase frequency}: bargain-driven repeat buyers;
  • Cluster B on {app sessions, clicks}: digitally engaged browsers;
  • Cluster C on {complaints, response time, returns}: service-risk customers;
  • Cluster D on {income, premium-category spend}: premium customers.

Campaigns can then be cluster-specific. Record selected dimensions, medoids, membership stability, and segment size so the result is auditable and actionable.

14. Common misconceptions and corrections

  • “High-dimensional” means many rows. No; dimensions are columns. Many rows concern data volume.
  • Every feature should be used in every cluster. Subspace methods exist because this is often false.
  • PCA selects original variables. It creates global linear combinations.
  • PROCLUS selects exactly $L$ features per cluster. $L$ is an average target/budget; allocations can differ.
  • Dense 1D unit guarantees dense higher-dimensional units. No; only dense high-dimensional units guarantee dense projections.
  • More clusters always improve segmentation. They can fragment patterns and reduce actionability.
  • More dimensions always improve PROCLUS. They can restore noise and distance concentration.
  • Maximum iterations is convergence. It is a safeguard; stabilization/improvement criteria define convergence.
  • 95% proves superiority. It depends on metric, labels, split, seed, baseline, and stability.
  • Removing irrelevant features and PCA are identical. One selects original columns; the other constructs new axes.

15. Formula/definition sheet

Euclidean distance

$$d(x,y)=\sqrt{\sum_{j=1}^p(x_j-y_j)^2}.$$

Cluster-specific projected distance

$$d_{D_i}(x,m_i)=\frac1{|D_i|}\sum_{j\in D_i}|x_j-m_{ij}|.$$

CLIQUE density

For unit $u$ and $n$ observations:

$$\operatorname{density}(u)=\frac{|\{x:x\in u\}|}{n}.$$

Dense when density exceeds the user threshold.

PROCLUS dimension budget

$$\sum_{i=1}^K|D_i|\approx K L,$$

subject to minimum dimension rules.

PCA projection used by demo

$$Z=X_cV_q,$$

then run K-means on $Z$.

16. Likely exam questions

Q1. Why does K-means struggle in high dimensions?

Discuss irrelevant dimensions, distance concentration, sparsity, noise, and cluster-specific subspaces.

Q2. Define subspace and projected clustering.

Subspace methods find clusters in subsets of dimensions; projected methods partition points and attach a relevant dimension set to each cluster.

Q3. Explain CLIQUE.

State bottom-up/grid/density nature, unit partition, threshold, Apriori property, candidate growth, dense connected units, advantages and limitations.

Q4. Explain PROCLUS phases.

Initialization with candidate medoids, iterative local dimension selection and assignment, bad-medoid replacement, then refinement/outlier handling.

Q5. What do $K$ and $L$ mean?

$K$ is cluster count; $L$ is average relevant dimensions per cluster. Explain joint $K\times L$ capacity and trade-offs.

Q6. Compare CLIQUE and PROCLUS.

Use search direction, representation, parameters, overlap/partition, and sensitivity.

Q7. Compare PCA + K-means and PROCLUS.

Global transformed space shared by all clusters versus cluster-specific original dimensions; give conditions favoring each.

Q8. How should convergence be decided?

Use stable medoids/assignments/dimensions or small objective improvement plus maximum-iteration safeguard.

Q9. Interpret the projected-clustering demo.

Describe preprocessing, PCA to two PCs, K-means, four datasets, effects of forcing $K$, overlap/outliers, and clustering-evaluation caveat.

Q10. Recommend a DataVista strategy.

Jointly tune $K,L$ over repeated seeds, evaluate stability/actionability/runtime against baselines, use convergence tolerance + cap, and monitor streaming drift.

17. Rapid-recall checklist

  • [ ] Dimensions are features/columns; observations are rows.
  • [ ] High-dimensional distance can concentrate and become uninformative.
  • [ ] Different clusters may exist in different feature subsets.
  • [ ] CLIQUE = bottom-up + grid + density.
  • [ ] CLIQUE cluster = maximal connected dense units.
  • [ ] Dense high-dimensional unit implies dense projections, not vice versa.
  • [ ] PROCLUS = top-down + medoid + projected dimensions.
  • [ ] Medoid is an actual observation.
  • [ ] $K$ = number of clusters; $L$ = average relevant dimensions.
  • [ ] PROCLUS dimensions are cluster-specific.
  • [ ] Initialization, iteration, refinement are the three broad phases.
  • [ ] Convergence needs stabilization/tolerance plus a max-iteration safeguard.
  • [ ] Larger $K$ can fragment; larger $L$ can add noise.
  • [ ] PCA + K-means uses one global projected feature space.
  • [ ] PROCLUS retains interpretable original dimensions per cluster.
  • [ ] K-means always returns requested $K$ even if unnatural.
  • [ ] “Clustering accuracy” requires labels/matching; otherwise use appropriate internal/stability/business measures.
  • [ ] Streaming deployment requires drift monitoring.

18. Final takeaways

  1. Full-space clustering often fails in high dimensions because irrelevant features and distance concentration hide local structure.
  2. CLIQUE discovers connected dense grid regions bottom-up across subspaces.
  3. PROCLUS builds medoid-centered clusters and selects a different relevant feature subset for each cluster.
  4. $K$ and $L$ jointly control PROCLUS complexity; neither should be maximized blindly.
  5. PCA + K-means is a useful global-projection baseline, while PROCLUS is preferable when groups depend on different original dimensions.
  6. Stable, interpretable, actionable clusters across repeated runs and business outcomes matter more than a single apparent accuracy value.
