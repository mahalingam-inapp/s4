Week overview

Week 2 connects three foundational ideas:

  1. Regression predicts a continuous numerical value.
  2. Classification predicts a categorical class (often through a probability).
  3. Clustering discovers groups in unlabelled data.

The recorded lessons cover logistic regression, two approaches to parameter estimation, Python implementations, K-means theory, and K-means in Scikit-learn. The live class also revisits linear regression because its line, loss function, parameters, and limitations motivate logistic regression. The quiz/review material adds important implementation and deployment trade-offs.

1. Machine-learning task types

Task Learning type Training data Output Examples
Linear regression Supervised Features X and known numeric target y Continuous value house price, rainfall in mm, glucose level, sales
Logistic regression/classification Supervised Features X and known class label y Class probability and class pass/fail, spam/not spam, normal/critical glucose
K-means clustering Unsupervised Features X; no known target label Cluster assignment customer segments, image regions, social groups

1.1 Regression versus classification

  • Both are predictive-modelling problems and normally use labelled historical data.
  • Regression predicts a continuous response. Given house area, predict price; given temperature and pressure, predict tomorrow’s rainfall in millimetres; given age, predict glucose level.
  • Classification predicts a categorical/nominal response. Given study hours, predict pass or fail; given email features, predict spam or not spam; given age, predict whether glucose is normal or critical.
  • Binary classification has two classes, commonly encoded as 0 and 1.
  • Multiclass/multinomial classification has more than two classes, such as grade A, B, C, or fail. Logistic regression can be extended to multiclass classification.

1.2 Labelled-data workflow

During training, a supervised algorithm receives both:

  • X: input variables, predictors, or features;
  • y: output/response/target variable or label.

Training produces a fitted classifier. At inference time, the model receives new X values and predicts y. For example, historical study hours and pass/fail labels train a model; a new value of 30 study hours is then used to predict pass or fail.

The overall workflow is commonly:

  1. Training: build the model from labelled examples.
  2. Validation: evaluate and fine-tune model choices/hyperparameters. Operationally, prediction resembles testing; validation is used during model development.
  3. Testing: estimate final performance on unseen data.

Validation is sometimes treated as part of training. The important distinction is its purpose: tuning versus final unbiased evaluation.

1.3 Common classification applications

  • Image classification
  • Spam detection
  • Medical risk/disease classification
  • Pass/fail prediction
  • Customer purchase/churn prediction
  • Binary and multiclass categorization

2. Linear-regression recap from the live class

This recap is examinable because logistic regression begins with the same linear score.

2.1 Model and parameter meanings

The school-level slope-intercept form is:

$$y=mx+c$$

The simple linear-regression model is:

$$y_i=\beta_0+\beta_1x_i+\epsilon_i$$

where:

  • $y_i$ is the observed or actual response;
  • $x_i$ is the feature value;
  • $\beta_0$ is the intercept;
  • $\beta_1$ is the slope;
  • $\epsilon_i$ is the error/residual.

The fitted value is:

$$\hat y_i=\beta_0+\beta_1x_i$$

and the residual is $y_i-\hat y_i$. The goal is a line of best fit with small overall residuals, not literally a line passing through every point.

In the live example, if age is X and glucose level is y, an actual row might contain $x_1=43$ and $y_1=99$. These are observed data, not model predictions. The model uses such pairs to learn how to predict glucose for a new age.

2.2 Least-squares loss and model quality

The sum-of-squared-error cost is:

$$J(\beta_0,\beta_1)=\sum_{i=1}^{n}\left[y_i-(\beta_0+\beta_1x_i)\right]^2$$

It may be divided by $n$ (or another constant) to form a mean loss; a positive constant scaling does not change the location of the minimizer. Smaller cost means the fitted line is closer to the observations; a large cost suggests a poorer fit on those data.

For simple linear regression, a closed-form estimate is available:

$$\beta_1=\frac{\sum_i(x_i-\bar x)(y_i-\bar y)}{\sum_i(x_i-\bar x)^2} =\frac{\operatorname{Cov}(X,Y)}{\operatorname{Var}(X)}$$

$$\beta_0=\bar y-\beta_1\bar x$$

Here $\bar x$ and $\bar y$ are the respective means. The instructor emphasized practising the numerical problem by hand to understand what the model computes internally.

2.3 Why linear regression is not the right binary classifier

If class labels are coded 0/1, a linear model can still predict values such as $-0.3$ or $1.4$. Such values are not probabilities. Applying an artificial threshold of 0.5 produces classes, but it does not repair the model’s underlying problems:

  • outputs are unbounded;
  • squared-error training does not directly optimize class likelihood/separation;
  • outliers can strongly affect squared loss;
  • probability interpretation is unreliable;
  • the resulting decision boundary may be poor.

This motivates logistic regression, which keeps its probability output in $(0,1)$.

3. Logistic regression

Despite its name, logistic regression is primarily a classification model. It predicts the probability that an observation belongs to a target class.

Example encoding:

  • $y=0$: glucose level normal;
  • $y=1$: glucose level critical.

3.1 Probability, odds, and log-odds

Probability measures the chance of an event and lies in $[0,1]$. In equally likely elementary cases it can be written as successful outcomes divided by total outcomes.

If the event probability is $p$, then:

$$\text{odds}=\frac{p}{1-p}$$

Odds compare the probability that the event occurs with the probability that it does not occur. They range from $0$ to $\infty$, not from 0 to 1.

Taking the natural logarithm gives the logit or log-odds:

$$\log\left(\frac{p}{1-p}\right)$$

Log-odds range from $-\infty$ to $+\infty$, which allows a linear predictor to be used:

$$\log\left(\frac{p}{1-p}\right)=\beta_0+\beta_1x$$

With multiple features, replace $\beta_1x$ by $\sum_j\beta_jx_j$.

3.2 Deriving the sigmoid/logistic function

Let $z=\beta_0+\beta_1x$. Starting with

$$\log\left(\frac{p}{1-p}\right)=z,$$

remove the natural logarithm:

$$\frac{p}{1-p}=e^z.$$

Rearranging:

$$p=\frac{e^z}{1+e^z}=\frac{1}{1+e^{-z}}.$$

Thus the sigmoid/logistic function is:

$$\sigma(z)=\frac{1}{1+e^{-z}}.$$

It is an S-shaped, smooth, monotonically increasing curve. A linear score may take any real value, but the sigmoid maps it strictly between 0 and 1. This is why logistic output can be interpreted as a probability.

3.3 From probability to a class

For a standard binary example:

$$\hat y=\begin{cases}1,&p\ge 0.5\\0,&p<0.5\end{cases}$$

The live class uses 0.5 because it is the equal-probability point. In practice the decision threshold may be tuned to business costs. For example, medical screening may use a lower threshold to reduce missed high-risk patients. Threshold tuning changes the class decision, not the probability model itself.

3.4 Interpretation example

Suppose $z=-4+0.08(60)=0.8$. Then

$$p=\frac{1}{1+e^{-0.8}}\approx0.69.$$

At a 0.5 threshold, the patient is classified as critical/high-risk. The value 0.69 is a probability estimate; the final 1 is the thresholded class.

4. Estimating logistic-regression parameters

The required parameters are the intercept and coefficient(s), such as $\beta_0$ and $\beta_1$. Unlike simple linear regression, logistic regression does not have the same direct closed-form solution. It is fitted iteratively.

The lectures discuss two related views:

  1. optimization of a loss with gradient descent;
  2. maximum likelihood estimation (MLE), usually implemented by minimizing negative log-likelihood.

4.1 Gradient descent: core idea

Start with initial parameter values, often zero, and repeatedly update them in the direction that reduces loss:

$$\beta_j\leftarrow\beta_j-\alpha\frac{\partial J}{\partial\beta_j}$$

where:

  • $J$ is the objective/loss function;
  • $\alpha$ is the learning rate;
  • the derivative/gradient describes the direction of steepest increase, so subtracting it moves downhill.

For two parameters:

$$\beta_0\leftarrow\beta_0-\alpha\frac{\partial J}{\partial\beta_0},\qquad \beta_1\leftarrow\beta_1-\alpha\frac{\partial J}{\partial\beta_1}.$$

The introductory lecture describes a squared-error-style loss, $\sum_i(y_i-\hat y_i)^2$, to explain the mechanics of iterative updates. The MLE lecture supplies the classification-appropriate likelihood objective; in standard logistic regression, negative log-likelihood/cross-entropy is the conventional loss.

4.2 Learning-rate trade-off

  • Too large: fast movement but can overshoot the optimum, oscillate, fail to converge, or produce inaccurate training.
  • Too small: stable and potentially precise, but convergence is slow and many iterations are required.
  • Illustrative lecture values include 0.001; the correct value depends on scaling and data.

The iteration count/epochs can also be set explicitly (the demonstration uses 300). A maximum-iteration limit avoids an endless loop. Convergence may instead be detected when assignments/parameters/loss cease changing meaningfully.

Review refinement: tiny parameter updates alone can be misleading when $\alpha$ is tiny. A small gradient norm $\|\nabla J\|$ is stronger evidence of reaching a stationary point; production implementations often combine tolerance and maximum-iteration criteria.

5. Maximum Likelihood Estimation (MLE)

5.1 Probability and conditional probability

MLE is a probabilistic parameter-estimation framework. Conditional probability

$$P(Y\mid X)$$

is read “the probability of $Y$ given $X$”: the chance of $Y$ when $X$ is known. In supervised learning, the model seeks parameters that make the observed target values highly probable given the inputs.

The transcript occasionally reverses the conditioning notation while speaking. For supervised classification, the relevant quantity is $P(y_i\mid x_i;\theta)$.

5.2 Likelihood of a dataset

For observations assumed conditionally independent given parameters $\theta$:

$$L(\theta)=\prod_{i=1}^{n}P(y_i\mid x_i;\theta).$$

This product is the likelihood: the observed data are fixed, and it is viewed as a function of the model parameters. MLE chooses:

$$\hat\theta=\arg\max_\theta L(\theta).$$

The model form and its parameters constitute the modelling hypothesis; estimation finds the hypothesis/parameters that best explain the observed data.

5.3 Why use log-likelihood?

Logarithms turn products into sums:

$$\log(a b c)=\log a+\log b+\log c.$$

Therefore:

$$\ell(\theta)=\log L(\theta)=\sum_{i=1}^{n}\log P(y_i\mid x_i;\theta).$$

This is simpler to optimize and avoids numerical underflow from multiplying many small probabilities. Since optimizers are commonly expressed as minimizers, maximize log-likelihood or equivalently minimize negative log-likelihood (NLL):

$$\operatorname{NLL}(\theta)=-\ell(\theta).$$

5.4 Bernoulli model for binary classification

For $y\in\{0,1\}$:

$$P(Y=1)=p,\qquad P(Y=0)=1-p.$$

This is a Bernoulli distribution (binomial reasoning across multiple trials). Its expectation is:

$$E[Y]=1\cdot p+0\cdot(1-p)=p.$$

For one observation, the compact Bernoulli probability is:

$$P(y\mid x)=p^y(1-p)^{1-y}.$$

The lecture verbally motivates this through a selector expression $py+(1-p)(1-y)$: when $y=1$, it returns $p$; when $y=0$, it returns $1-p$. The exponent form is the conventional likelihood form.

With prediction $p_i=\hat y_i=\sigma(\beta_0+\beta^Tx_i)$, the full likelihood is:

$$L(\beta)=\prod_i p_i^{y_i}(1-p_i)^{1-y_i}.$$

The log-likelihood is:

$$\ell(\beta)=\sum_i\left[y_i\log p_i+(1-y_i)\log(1-p_i)\right].$$

The binary cross-entropy/NLL minimized in standard logistic regression is:

$$J(\beta)=-\sum_i\left[y_i\log p_i+(1-y_i)\log(1-p_i)\right].$$

It gives high likelihood/low loss when the predicted probability is close to the actual class and low likelihood/high loss when the model is confidently wrong.

5.5 Optimization methods

There is no simple closed-form logistic solution, so iterative numerical optimization is used. The lecture mentions:

  • gradient descent;
  • Newton–Raphson;
  • bisection-type numerical methods (details outside course scope).

Whether one says “maximize likelihood/log-likelihood” or “minimize negative log-likelihood,” the optimum parameters are the same.

6. Logistic regression in Python

The demonstration uses age as the feature and glucose category (normal/critical) as the target. Inspection suggests that critical glucose becomes more common as age increases.

6.1 Libraries and data

  • NumPy: arrays and linear algebra
  • Pandas: loading/managing the CSV data frame
  • Matplotlib: plots
  • Scikit-learn: train/test splitting and built-in logistic regression
  • CSV means comma-separated values.

6.2 Custom implementation structure

The model is separated into functions for:

  1. normalization of X (the lecture describes centering as $X-\bar X$);
  2. prediction using the sigmoid $1/(1+e^{-(\beta_0+\beta_1X)})$;
  3. logistic training, which initializes coefficients, iterates, computes derivatives, and updates parameters;
  4. training/test orchestration.

Conceptual pseudocode:

b0, b1 = 0.0, 0.0
learning_rate = 0.001

for epoch in range(300):
    probability = sigmoid(b0 + b1 * x_train)
    db0 = ...  # derivative with respect to b0
    db1 = ...  # derivative with respect to b1
    b0 = b0 - learning_rate * db0
    b1 = b1 - learning_rate * db1

After splitting into X_train, X_test, y_train, and y_test, fit only on the training set. Normalize test data consistently with training statistics, compute probabilities, apply the 0.5 class threshold, plot results, and calculate accuracy:

$$\text{accuracy}=\frac{\text{number of correct predictions}}{\text{total predictions}}.$$

The small custom demonstration reports approximately 0.8 accuracy (two misclassifications).

Important practical caveat: never independently learn a different normalization from the test set. Store training mean/scale and apply them unchanged to validation, test, and future inputs.

6.3 Scikit-learn implementation

The built-in workflow is concise:

from sklearn.linear_model import LogisticRegression

lr_model = LogisticRegression(...)
lr_model.fit(X_train, y_train)
y_pred = lr_model.predict(X_test)
accuracy = lr_model.score(X_test, y_test)

The demonstration’s built-in model reports 100% on its deliberately simple, framed sample. The instructor explicitly warns not to generalize from this tiny result: a realistic evaluation needs a much larger and more varied dataset (the lecture suggests at least around 1,000 examples with representative classes). Always retain unseen test data and inspect more than accuracy when class imbalance or unequal errors matter.

6.4 Custom code versus a library

Custom training loop Mature library implementation
Full control over learning rate, epochs, updates and logging Hyperparameters supplied through constructor/API
Can inspect gradients and every training step Internal optimization mostly abstracted
Useful for education, research and optimizer experiments Useful for rapid prototyping and production
More code, debugging and maintenance Optimized, tested, numerically stable and reproducible
Greater risk of implementation error Less freedom to alter the internal update rule

The review emphasizes that sample accuracy alone is insufficient. Choose using reliability, transparency, maintainability, deployment readiness, adaptability, validation needs, and the application’s consequences.

7. Clustering fundamentals

Clustering partitions a dataset into groups so that items within a group have similar properties while dissimilar items lie in different groups. It is commonly applied to large unlabelled datasets for exploration or before another technique such as classification.

7.1 Why clustering is unsupervised

Only features are supplied; known target labels are absent. In an age/glucose dataset, for example, there may be numerical measurements but no normal or critical label. The algorithm discovers structure rather than learning a supplied input-output mapping.

Clustering can therefore create descriptive labels/cluster IDs for previously unlabelled observations. These IDs can support exploratory analysis or act as cautious pseudo-labels in semi-supervised workflows, but a cluster number is not automatically a true business class.

7.2 Clustering families mentioned

Family Example Central idea
Centroid-based K-means Assign observations to representative centers
Density-based DBSCAN Dense connected regions form clusters
Distribution/model-based Gaussian mixture model (GMM) Data arise from a mixture of distributions
Hierarchical CURE Build a hierarchy/structure of clusters

7.3 Applications

  • Market/customer segmentation: discover groups with similar behavior when no segment labels exist.
  • Social-network analysis: represent activity/relationships as a graph and discover communities.
  • Image segmentation: group pixels/regions with similar characteristics.
  • Anomaly detection: identify observations that do not belong well to normal groups.
  • Preprocessing/exploration: understand large datasets before supervised modelling.

8. K-means clustering

K-means is a centroid-based unsupervised algorithm. K is the chosen number of clusters; “means” refers to updating each center to the arithmetic mean of its assigned observations.

8.1 Two alternating operations

  1. Assignment: assign every point to its nearest centroid.
  2. Update: recompute each centroid as the mean of all points assigned to it.

Repeat until assignments no longer change or centroid movement becomes negligible.

The original observations never move. Membership can change because the centroids move after an update, making a different centroid nearest on the next assignment.

8.2 Full algorithm

  1. Choose $K$.
  2. Initialize $K$ centroids. The lecture mentions random selection and K-means++ initialization.
  3. For each point, compute its distance to every centroid and assign it to the nearest.
  4. For cluster $C_k$, update:

$$\mu_k=\frac{1}{|C_k|}\sum_{x_i\in C_k}x_i.$$

  1. Repeat steps 3–4 until convergence.

Choosing $K$ can be tricky and may use domain knowledge. Arbitrarily making an enormous number of clusters (for example, 1,000) can defeat the purpose of summarizing and interpreting the data. In practice, diagnostics such as the elbow method or silhouette score can supplement domain knowledge.

8.3 Distance measures

For points $x=(x_1,x_2)$ and $y=(y_1,y_2)$:

Euclidean distance

$$d_2(x,y)=\sqrt{(x_1-y_1)^2+(x_2-y_2)^2}.$$

Squaring prevents positive and negative coordinate differences from cancelling and measures straight-line distance.

Manhattan distance

$$d_1(x,y)=|x_1-y_1|+|x_2-y_2|.$$

The distance metric determines the closest center during assignment. It does not select $K$, recompute the centroid, or by itself determine convergence.

Strict terminology: standard K-means conventionally uses squared Euclidean distance with arithmetic means. The lecture uses Manhattan distance to simplify its manual assignment example while still recomputing means. A fully Manhattan-based analogue is more naturally called K-medians.

8.4 Convergence and iteration controls

K-means is considered converged when:

  • assignments stop changing; or
  • centroid movement/change falls below a tolerance.

The live discussion explains why updated centers are needed: each update fine-tunes the grouping, and another assignment checks whether observations now belong nearer to another center. On the eight-point example, two or three iterations may be sufficient. Real implementations automate the process.

For very large datasets, developers may specify max_iter to bound computation and prevent endless looping. Robust implementations combine a convergence tolerance with a maximum iteration count. The transcript notes that very large volumes may require deliberate computational limits; exact choices depend on resource and accuracy needs.

8.5 Practical limitations and care

  • Results can depend on initial centroids; use K-means++ and/or multiple restarts.
  • Feature scale affects distance. Standardize features when units differ materially (for example, annual income versus a 1–5 satisfaction score).
  • K-means works best for roughly compact, center-based clusters and is sensitive to outliers.
  • Cluster labels such as 0, 1, and 2 are identifiers only; their numeric order has no meaning.

9. Manual K-means example

The lecture uses eight points:

Point Coordinates
$A_1$ $(2,10)$
$A_2$ $(2,5)$
$A_3$ $(8,4)$
$A_4$ $(5,8)$
$A_5$ $(7,5)$
$A_6$ $(6,4)$
$A_7$ $(1,2)$
$A_8$ $(4,9)$

Set $K=3$ and randomly/arbitrarily initialize centers at $A_1$, $A_4$, and $A_7$. For the classroom calculation, use Manhattan distance.

9.1 Sample assignment calculations

For $A_1=(2,10)$:

  • to $A_1$: $0$;
  • to $A_4=(5,8)$: $|2-5|+|10-8|=5$;
  • to $A_7=(1,2)$: $|2-1|+|10-2|=9$.

Hence $A_1$ belongs to cluster 1.

For $A_2=(2,5)$:

  • to $A_1$: $|2-2|+|5-10|=5$;
  • to $A_4$: $|2-5|+|5-8|=6$;
  • to $A_7$: $|2-1|+|5-2|=4$.

The smallest value is 4, so $A_2$ joins cluster 3. The same procedure is performed for every point.

9.2 First update and subsequent iteration

After assigning all points to their nearest initial center, recompute each center coordinate-by-coordinate as the average of its members. Then calculate all distances again using the updated centers.

The transcript’s second illustrated assignment produces:

  • $C_1=\{A_1,A_8\}$;
  • $C_2=\{A_3,A_4,A_5,A_6\}$;
  • $C_3=\{A_2,A_7\}$.

The corresponding updated means shown are:

  • $\mu_1=(3,9.5)$;
  • $\mu_2=(6.5,5.25)$ by direct arithmetic from the listed members (the spoken transcript appears to say $(6.5,6.5)$, an apparent transcription/slide mismatch);
  • $\mu_3=(1.5,3.5)$.

Continue assignment and updating until the groupings no longer change. The exam-relevant point is the method: distance assigns; mean updates; iteration produces convergence.

10. K-means with Scikit-learn

10.1 Libraries and data preparation

The demonstration uses:

  • NumPy;
  • Pandas for a data frame with columns X and Y;
  • Matplotlib and the ggplot style for visualization;
  • KMeans from sklearn.cluster.

The same eight two-dimensional points from the manual example are placed in a data frame and scatter-plotted.

10.2 Fit, centers, and labels

Conceptual code:

from sklearn.cluster import KMeans

kmeans = KMeans(n_clusters=3, random_state=..., n_init=...)
kmeans.fit(data)

centroids = kmeans.cluster_centers_
labels = kmeans.labels_

A single fit call performs initialization, repeated assignment/update iterations, and stopping internally.

  • cluster_centers_ contains final centroid coordinates.
  • labels_ contains one cluster ID for every input row, in the same order as the original dataset.
  • cluster_centers_[labels_] recovers the assigned centroid coordinates row-by-row.

The recorded run reports centers approximately $(7,4.33)$, $(1.5,3.5)$, and $(3.6,9)$, with three members in one cluster, two in another, and three in the third. The exact numeric label attached to a center may change across runs because label numbers are arbitrary and initialization can differ.

Plot points in different colors according to labels_ and overlay centroid markers. A legend can call them Group 1, Group 2, and Group 3, but these names are descriptive rather than known ground-truth classes.

11. Integrated practical use cases

11.1 Medical glucose analysis

  • Linear regression: predict the numerical glucose level from age and other features.
  • Logistic regression: predict $P(\text{critical glucose}\mid X)$ and classify normal/critical.
  • K-means: when labels are absent, discover patient profiles based on glucose, age, BMI, and other measurements; clinicians must interpret and validate the clusters before treating them as risk categories.

11.2 Customer analytics

  • Use K-means on frequency, recency, spend, and engagement to discover customer segments.
  • Once a meaningful outcome such as “will buy next month” is labelled, train logistic regression to estimate purchase probability.
  • Use the probability, not only the class, to prioritize marketing efforts; choose a threshold based on campaign cost and expected value.

11.3 Email filtering

  • Features may include word indicators, sender reputation, link count, and message metadata.
  • Logistic regression estimates spam probability from labelled messages.
  • A threshold greater than 0.5 may reduce false spam flags; a lower threshold may catch more spam. This illustrates why threshold choice is a business/risk decision.

12. Review/case-study augmentation: MediPredict

MediPredict must classify patients as high-risk or low-risk from labelled laboratory results. Priya initially treats the binary target as a linear-regression problem, obtains unbounded predictions, and thresholds at 0.5. The custom approach needs normalization, prediction, gradient computation, parameter updates, and convergence logic. On the small sample it achieves about 80% with two errors, while a built-in classifier reports 100%.

12.1 What the case actually demonstrates

  • A purpose-built classification method is more appropriate because it outputs valid probabilities and learns through a classification likelihood.
  • The 100% value is not proof of future performance; it may reflect a tiny/artificially separable sample.
  • Engineering choice must balance accuracy, reliability, maintainability, transparency, reproducibility, stability, deployment readiness, and long-term healthcare quality—not only one test score.

12.2 Options and what each fixes

Option Benefit What it does not fix
Threshold tuning Trades false positives against false negatives Does not turn linear output into a valid probability model
Regularization Constrains coefficients, reduces overfitting, improves stability/generalization Does not bound predictions to $[0,1]$
Probability calibration Post-processes scores to improve probability interpretation Does not make an unsuitable underlying objective ideal
Adaptive learning rate May improve optimization speed/stability Does not fix unbounded linear outputs
Logistic/built-in classifier Appropriate probability model, lower code complexity, mature optimization Offers less control over internal update logic

If the custom approach must be investigated, the review suggests stabilizing it with regularization, calibrating probabilities, assessing deployment suitability, and comparing fairly with the classifier. For most real healthcare binary-classification deployments, a mature classification implementation is preferred.

13.3 Gradient descent versus MLE

These are not competing categories:

  • MLE/NLL specifies what objective logistic regression should optimize.
  • Gradient descent specifies how parameters can be moved to optimize it.

Newton–Raphson is another possible optimization procedure for the same likelihood objective.

14. High-yield formula sheet

Linear regression

$$\hat y=\beta_0+\beta_1x$$

$$J=\sum_i(y_i-\hat y_i)^2$$

$$\beta_1=\frac{\sum_i(x_i-\bar x)(y_i-\bar y)}{\sum_i(x_i-\bar x)^2},\qquad \beta_0=\bar y-\beta_1\bar x$$

Logistic regression

$$z=\beta_0+\beta^Tx$$

$$\text{odds}=\frac{p}{1-p}$$

$$\log\left(\frac{p}{1-p}\right)=z$$

$$p=\sigma(z)=\frac{1}{1+e^{-z}}$$

Bernoulli likelihood

$$P(y_i\mid x_i)=p_i^{y_i}(1-p_i)^{1-y_i}$$

$$L(\beta)=\prod_i p_i^{y_i}(1-p_i)^{1-y_i}$$

$$\ell(\beta)=\sum_i[y_i\log p_i+(1-y_i)\log(1-p_i)]$$

$$\operatorname{NLL}=-\ell(\beta)$$

Gradient descent

$$\theta\leftarrow\theta-\alpha\nabla J(\theta)$$

15. Likely exam questions and answer points

Q1. Distinguish regression and classification.

State that both are supervised predictive methods; regression predicts a continuous value, classification predicts a categorical label/probability. Give at least one example of each.

Q2. Derive the sigmoid from the logit equation.

Begin with $\ln[p/(1-p)]=z$, exponentiate to $p/(1-p)=e^z$, rearrange to $p=e^z/(1+e^z)=1/(1+e^{-z})$, and explain its $(0,1)$ output.

Q3. Why not use linear regression for binary classification?

Mention unbounded outputs, invalid probability interpretation, squared-error rather than likelihood objective, sensitivity to outliers/poor boundary, and that thresholding does not fix the fundamental model mismatch.

Q4. Explain MLE for logistic regression.

Assume Bernoulli targets, multiply probabilities of observed labels, take logs to convert product into a sum, maximize log-likelihood or minimize NLL/cross-entropy, and use an iterative optimizer because there is no simple closed-form solution.

Q5. Explain learning rate in gradient descent.

Define the update rule. Large rates can overshoot/diverge; small rates converge slowly. Mention tolerance/gradient norm and a maximum epoch limit.

Q6. Give K-means steps.

Choose $K$, initialize centers, assign to nearest center using distance, replace every center with its members’ mean, repeat until assignments/centers stabilize.

Q7. Why can K-means membership change if points do not move?

Centroids move after mean recomputation; a different centroid can then become closest. Only assignments and centers change, not original observations.

Q8. Explain cluster_centers_ and labels_.

The first stores final centroid coordinates. The second stores one cluster ID per input row in original row order. cluster_centers_[labels_] returns each row’s assigned centroid.

Q9. Compare custom and built-in logistic regression.

Custom code gives procedural control and visibility but adds complexity, bugs, maintenance, and stability risk. A built-in library is concise, optimized, tested, and production-friendly but exposes less internal control.

Q10. Explain why 100% sample accuracy may be misleading.

It can arise from a tiny, artificial, easily separable sample and says little about generalization. Use representative data, unseen testing, reproducible splits, and metrics suited to class balance and error costs.

16. Rapid-recall checklist

  • [ ] Classification predicts categories; regression predicts continuous values.
  • [ ] Logistic regression is a classifier even though it is called “regression.”
  • [ ] The linear score is unbounded; sigmoid converts it to $(0,1)$.
  • [ ] Odds are $p/(1-p)$; log-odds equal the linear predictor.
  • [ ] A 0.5 threshold is conventional, not mandatory.
  • [ ] Binary targets are modeled with a Bernoulli distribution.
  • [ ] Dataset likelihood is a product; log-likelihood is a sum.
  • [ ] Maximizing log-likelihood equals minimizing NLL/cross-entropy.
  • [ ] Gradient descent subtracts learning rate times gradient.
  • [ ] Very large learning rate can overshoot; very small is slow.
  • [ ] Validation tunes; testing provides final evaluation.
  • [ ] K-means is unsupervised and centroid-based.
  • [ ] Distance assigns points; arithmetic mean updates centroids.
  • [ ] Points stay fixed; centroids and memberships can change.
  • [ ] Stop at stable assignments/negligible movement, with max_iter as a safeguard.
  • [ ] Cluster IDs are arbitrary, not ordered categories.
  • [ ] Tiny demonstration accuracy must not be mistaken for production evidence.

17. Final takeaways

  1. Logistic regression resolves the probability-range problem of linear regression by modeling log-odds and applying the sigmoid.
  2. Its parameters are chosen probabilistically through MLE; NLL/cross-entropy is the minimization form of that objective.
  3. Numerical optimization such as gradient descent or Newton–Raphson is required because logistic regression lacks the simple ordinary-least-squares closed form.
  4. K-means discovers structure without labels by alternating nearest-center assignment and mean recomputation.
  5. Practical model selection is not merely an accuracy contest: data representativeness, error costs, convergence, stability, maintainability, and deployment requirements all matter.

MLE/loss correction

The selector expression $\hat y y+(1-\hat y)(1-y)$ returns the probability assigned to the observed class. Conventional likelihood is $p^y(1-p)^{1-y}$ and NLL is binary cross-entropy. Standard logistic regression does not normally train with the squared-error loss used for introductory gradient-descent intuition.
